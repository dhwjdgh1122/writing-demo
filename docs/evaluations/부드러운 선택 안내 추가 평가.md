# 부드러운 선택 안내 추가 평가 — 보완 C

관련 작업: [#22](https://github.com/dhwjdgh1122/writing-demo/issues/22), [초안 PR #23](https://github.com/dhwjdgh1122/writing-demo/pull/23). 기준: [교정 설명 평가 기준](../교정%20설명%20평가%20기준.md). 이전 [A·B 평가](설명%20지침%20보완%20전후%20비교.md)는 그대로 보존한다.

**금지형 안내는 이번 출력에서 나타나지 않았고, 기존 E-07의 부정 변화도 설명했다. 그러나 오탈자 인용 오류와 수정 종류를 잘못 설명하는 오류가 나와 개선 완료로 보지 않는다. PR은 초안으로 유지한다.** 아래 내용은 Codex의 AI 보조 예비 판정이며 사람의 평가나 사용자 효과 측정이 아니다.

## 변경과 실행 조건

- 사용자는 ‘적용하지 말아야 합니다’라는 안내가 후보를 제안한 이유에 대한 불신을 줄 수 있다고 의견을 제시했다. 이에 금지하는 대신 원래 뜻을 전달하려면 유지할 정보를 안내하도록 설명 지침을 보완했다. 사용자 집단의 평가 결과는 아니다.
- 실제 의미 변화는 분명하게 설명하고, 여러 변화가 겹쳐도 부정·대상 등을 빠뜨리지 않도록 명시했다. 이미 원문에 있는 사실을 다시 확인하라는 안내와 책임 전가도 피하도록 했다.
- 제품 코드 변경은 설명 지침뿐이다. 교정 생성 지침·인용 검사·UI는 변경하지 않았다. 평가 도구에는 1~6개 사례가 담긴 별도 fixture를 선택하는 `--cases` 옵션을 추가했다. API·어댑터·인용 검사 경로는 이전과 같다.
- 실행 코드: `6ce88e8f2baad73e287c2f882e10b7b3cc0fab46`. 제공자·모델: Gemini `gemini-3.5-flash-lite`. 프롬프트 원문·해시, 입력·실행 도구 해시, 시각은 각 JSON에 보존했다.

| 실행 | KST 시작 시각 | 입력·호출 | 실제 응답 |
|---|---|---|---|
| 보완 C, 기존 사례 | 2026-11-16 21:14 | 기존 6사례·7후보, 6회 | [C JSON](criteria-2026-11-16T12-14-41-293Z.json) |
| 보완 C, 추가 사례 | 2026-11-16 21:15 | 새 3사례·3후보, 3회 | [추가 JSON](criteria-2026-11-16T12-15-01-872Z.json) |

각 사례당 1회, 총 9회이며 재시도·모델 변경·새 교정 후보 생성은 하지 않았다. #22의 A·B 12회를 포함하면 21회, #20 기준선까지 포함하면 27회다. 기업 데이터는 사용하지 않았다. E-06은 제외하고 E-05는 동일 후보의 코드 고정 안내로 별도 집계했다.

추가 사례는 응답을 보기 전에 [별도 입력 파일](../../tests/fixtures/explanation-guidance-extra.json)에 작성했다. 기존과 유사한 변화 유형의 개발자 작성 사례이므로 독립적인 사용자 데이터나 일반화 성능 시험으로 표현하지 않는다. 실행 JSON의 `E-06 excluded` 공통 메모는 기준 사례 E-06을 이번 실행에도 포함하지 않았다는 뜻이며, 추가 실행의 실제 입력은 G-01~03뿐이다.

## 대표적인 실제 출력

### E-02: 금지 대신 유지할 일정 안내

원문 `목요일에 다시 안내하겠습니다.` → 후보 `이후에 다시 안내하겠습니다.`

> 목요일이라는 특정 안내 일정이 이후로 바뀌어 안내 시점이 불분명해졌습니다. 정확한 일정을 전달하려면 원문의 목요일 표현을 유지하는 것을 검토할 수 있습니다.

B의 ‘적용하지 말아야 합니다’ 대신 유지할 정보가 제시됐다. 안내 효과나 사용자 만족이 검증된 것은 아니다.

### E-07: 부정 변화와 전달 관계 모두 설명

> 신청자가 운영진에게 자료를 보내지 않는다는 원문의 내용이 운영진이 신청자에게 자료를 보낸다는 내용으로 바뀌어 행동하는 주체와 받는 대상이 서로 반대로 달라졌습니다. 원래 뜻대로 신청자가 자료를 보내지 않는다는 사실을 전달하려면 원문의 '신청자는 운영진에게 자료를 보내지 않습니다.' 표현을 유지하는 편이 좋습니다.

B에서 빠진 ‘보내지 않음 → 보냄’의 비교가 이번에는 포함됐다. 다만 문장이 길고 같은 원문을 반복한다.

### E-01: 설명에서 새로운 오탈자를 만들어 차단됨

실제 후보는 `금요일까지 자료를 보내 주세요.`지만, 차단 전 설명은 다음과 같았다.

> 오탈자였던 '주세여.'를 '주주세요.'로 수정하여 올바른 맞춤법으로 자료 제출 기한을 안내합니다.

후보에 없는 `주주세요.`를 인용했다. API는 502 `EXPLANATION_QUOTE_MISMATCH`로 차단했다. 이번 차단은 이전 E-04의 대안 단어 차단과 달리 실제 잘못된 인용을 잡은 사례다.

### E-04: API 성공과 설명 정확성은 다름

후보 p2는 `않앗습니다 → 않았습니다`와 `8명중 → 8명 중`을 고쳤지만 `결재`는 유지한다. 설명은 다음과 같았다.

> 결재하지 않앗습니다를 결재하지 않았습니다로 수정하여 띄어쓰기만 바르게 고쳤습니다. 문서를 승인한다는 뜻의 단어가 그대로 사용되어 비용 지불의 의미로는 적절하지 않으므로 표현을 검토할 필요가 있습니다.

남은 단어 문제는 안내하지만, 오탈자 수정까지 한 후보를 ‘띄어쓰기만’ 고쳤다고 설명한다. p1 역시 `않앗습니다 → 않았습니다`가 포함된 구간의 변경을 띄어쓰기 수정으로 연결한다. 실제 띄어쓰기 수정은 별도의 `8명중` 구간이다. 둘 다 수정 설명의 정확성을 보완해야 한다. 이번 API 성공을 인용 검사 문제 해결이나 설명 품질 통과로 보지 않는다.

부드러운 구체적 정보 유지 안내를 엄격히 추가 점검했으므로 이 표의 선택 정보 판정을 과거 B의 수치와 단순 비교하지 않는다. 기존 의미 변화 7개는 같은 분모로 B 6/7에서 C 7/7이지만, 한 번의 출력 차이며 안정적 개선을 입증하지 않는다. 새 오류도 함께 보고한다.

## 검증과 남은 작업

- 설명 지침·실행 도구 변경 후 타입 검사와 단위/API 테스트 **42개 통과**. 도구 구문 검사와 기본 6개·추가 3개 입력 dry run 통과. UI 변경이 없어 로컬 브라우저 검사를 반복하지 않았다.
- 변경 문서 7개의 내부 링크·앵커 134개와 `git diff --check`를 확인했다. 두 보고서의 커밋·프롬프트 일치, 기존 평가 입력 유지, 교정 생성 지침 미변경도 대조했다.
- 기존 고정 입력 6개는 A·B와 동일하다. 추가 입력은 별도 실행으로 구분한다. 이번 도구는 `--cases` 지원으로 변경됐으므로 이전과 실행 도구 해시가 같다고 주장하지 않는다.
- Codex 단독 AI 예비 판정이며 사람 간 판정 일치, 반복 실행의 안정성, 실제 화면과 사용자 판단 도움은 미확인이다.
- 금지형 표현 수정은 반영했지만 사실 일치 기준을 충족하지 못해 main에는 아직 병합하지 않는다. 다음 보완 대상은 오탈자 정확 인용과 수정 종류 구분, 구체적인 정보 유지 안내와 설명 길이다. 좋은 결과가 나올 때까지 이번 실행을 반복하지 않았다.
- 교정 후보 자체의 품질 개선, 대안 표현과 실제 인용을 구분하는 검사, 후보별 차단 범위는 별도 범위다.
