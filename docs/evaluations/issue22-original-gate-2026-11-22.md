## 반복과 판정

Gemini `gemini-3.5-flash-lite`, 엘리스 `gpt-4o-mini`를 각각 3회 평가하는 고정 범위다. 전체 계획은 **84앱 요청·90후보 결과**이며 E-05 고정 안내 6건을 모델 설명 품질에서 분리한다. 후보 생성 시험이 아닌 고정 원문·후보의 설명 시험이다. 과거 PR #23은 동일 후보를 호출 전에 처리했으며, PR #34와 현재 단일 설명 요청 경로는 응답 후 처리한다. 모델 호출 수는 실제 실행 경로에 따라 기록하고 제품 경로를 우회하여 줄이지 않는다.

모델별 모든 회에서 사실 오류·없는 의미 변화·근거 없는 단정이 없어야 하고, 각 후보의 `required` 및 E-04-p2 보완 조건을 모두 충족해야 한다. 중요한 변화·영향·선택 정보 누락, 읽기 어려운 설명은 보완 필요이며 통과로 세지 않는다. 정상/모호한 단어의 오탐과 CT-03의 허위 조건 삭제 지적도 실패다. 형식·인용 차단은 설명 미제공, 서비스 장애·사용량 제한·미실행은 판정 보류로 남긴다. 다른 모델이나 다른 항목의 성공, 평균 점수로 상쇄하지 않는다.

`expectedNotes`와 `required`의 `notes` 언급은 원본 추적을 위해 보존한다. 현재 자유문 계약에서는 해당 내용이 실제 표시 설명에 있는지 평가하며, JSON에 `notes` 필드가 없다는 사실 자체로 실패시키지 않는다. 이는 [PR #34의 원래 내용 요구 유지 규칙](https://github.com/dhwjdgh1122/writing-demo/blob/70f5d57/docs/교정%20설명%20평가%20기준.md#issue22-merge-gate)과 같다.

모델에 보낼 설명 데이터는 `sourceText`와 `candidates`이며 API에 필요한 요청 ID는 실행기가 별도로 만든다. `origin`, `required`, `expectedNotes`, 출처·gate·사람의 판정은 보내지 않는다. 사례 정답을 프롬프트 예시로 복사하지 않는다. 실제 실행 전 최종 코드·프롬프트·계약·모델·사례를 고정하고 호출 승인/잔여 한도를 확인해야 한다. 이 복원 파일은 새 호출을 승인하거나 실행하지 않는다.

원문·후보로 필수 정보를 먼저 확정한 뒤 설명과 대조한다. 모든 글자 차이의 열거를 새 기준으로 추가하지 않는다. 단순 오타·공백은 실제 예를 들어 묶어 설명할 수 있으나 중요한 의미 변화는 빠뜨릴 수 없다. [기존 변경 범위 기준](https://github.com/dhwjdgh1122/writing-demo/blob/70f5d57/docs/교정%20설명%20평가%20기준.md#explanation-coverage-boundary)을 유지한다.
