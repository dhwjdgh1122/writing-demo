2026-11-24 / [#9](https://github.com/dhwjdgh1122/writing-demo/issues/9). [사전 계획](provider-workflow-plan-2026-11-24.md)에 따라 main `6ca0f52`의 제품 코드를 사용했다. 실행기·계획 커밋은 `5652bca`이며 두 실행의 코드·빌드·입력 해시는 원자료에 보존했다. 기본 `.env`와 제품 코드·프롬프트는 변경하지 않았다.

**결론:** 두 제공자 모두 현재 웹 흐름에서 후보 생성·표현별 이유 연결·후보 하나 재교정·적용·후보 전환·적용 후 재교정을 실행할 수 있었다. 설명 표시 실패와 내용 오류는 남아 있다. 이번 결과를 근거로 기본 Gemini 설정을 바꾸거나 #22의 품질 문제를 완료 처리하지 않는다.

- 설명 8건의 분모는 최초 3개 + 후보 하나 재교정 1개 + 적용 후 재교정 3개 + 고정 후보 1개다. 이 표의 통과는 앱의 형식·ID·인용 검사 통과이지 내용 정확성 점수가 아니다. 엘리스의 실패 2건도 HTTP 200 안에 포함되므로 HTTP 성공률로 설명 성공을 대신하지 않는다.

## 관찰한 웹 동작

두 제공자에서 다음을 확인했다. 선택 앞뒤에 둔 문장은 서버 요청과 적용 범위에서 제외됐다.

1. 처음 선택한 공지로 후보 3개를 받았다. 생성만으로 편집기 내용이 바뀌지 않았다.
2. 원문 비교를 열고 교정 이유를 요청했다. 유효한 설명의 변경 표현을 클릭했을 때 원문·교정안의 대응 강조와 이유가 연결됐다.
3. 후보 3에서 `더 담백하게`로 재교정하면 후보 1·2는 유지되고 새 후보 1개만 받았다. 열린 이유는 새 후보의 설명으로 자동 요청됐다.
4. 후보를 적용하고 다른 후보로 전환해도 후보 3개를 유지하고 선택 밖의 앞뒤 문장을 보존했다.
5. 적용한 카드에서 `더 정중하게`로 재교정하면 현재 적용 문장 기준 새 후보 3개를 받았다. 비교·설명 열림을 유지하고 새 설명을 자동 요청했다. 새 후보를 적용하기 전 편집기 내용은 그대로였다.

엘리스 최초 후보 2·3의 설명은 `EXPLANATION_QUOTE_MISMATCH`로 차단됐다. 원출력에 원문의 `예정 입니다.`를 `예정입니다.`로 바꾸어 인용한 부분이 있다. 정상 후보·유효한 설명은 사용할 수 있었다. 이 실행에서는 실패한 설명을 다시 요청하지 않았으며, 반복 실패 후 복구는 #59의 주입 응답 시험과 구분한다.

## 내용 검토 — AI 보조 분석

사람의 독립 평가나 실제 사용자 실험이 아니다. 두 모델 모두 이번 공지의 회의 날짜·오후 3시·수요일 회신 마감·회의 뒤 공유를 유지했다. 다음 문제도 함께 관찰했다.

| 항목 | Gemini | 엘리스 |

| 표시된 설명 | 초기 후보 3의 변경 이유에 실제 후보에 없는 `다음 주비`를 기술. 인용 검사 통과가 이런 무따옴표 오류까지 막지는 못함 | 재교정 설명에서 하지 않은 작업인 `번역에서`를 언급하고 띄어쓰기 변화에 정중함 증가를 부여하는 과장 관찰 |

| 정중하게 요구 | `분들께서는`·`공유해 드리겠습니다` 등 높임 변화 관찰 | `알려주시면 감사하겠습니다` 등 요청 표현 변화 관찰 |

### 같은 원문·같은 후보의 설명

원문: `담당자의 확인을 받은 경우에만 화요일까지 8명에게 자료를 보낼 예정이며, 발송은 확정되지 않았습니다.`

후보: `화요일까지 10명에게 자료를 발송합니다.`

- **Gemini:** 담당자 확인 조건 삭제, 8명→10명, 예정·미확정→단정 표현의 세 변화를 각각 지적했다. 실제 발송 여부·의도 확인 안내도 제공했다.
- **엘리스:** 세 항목을 언급했지만 조건 삭제 이유에 `발송의 확정성이 없어졌습니다`라고 설명했다. 자체 요약의 `확정된 것으로 바뀌었다`와도 모순된다. 형식 검사를 통과했지만 세 변화를 정확히 설명했다고 판정하지 않는다.
- 두 설명 모두 날짜가 바뀌었다고 기술하지 않았다. 한 사례의 결과이며 의미 보존이나 모든 설명의 정확성을 보장하지 않는다.

## 발표에 사용할 수 있는 주장

> 최신 웹 기능을 Gemini와 엘리스에 각각 연결해 같은 작업 흐름을 확인했습니다. 후보·설명·재교정·적용은 동작했고, 일부 설명은 인용 검사에서 차단됐습니다. 검사를 통과한 설명에도 내용 오류가 있어, 실제 변경 표시를 함께 제공하고 사용자가 최종 판단하도록 했습니다.

이번 결과로 일반 모델 우열, 사용자 판단 개선, 만족도, KPI 달성, 서비스 전체 안정성 또는 #22 완료를 주장하지 않는다. 제출 전에는 기본 제공자를 유지하고 실제 촬영 결과를 사용한다. 배포 여부는 별도 결정이다.
