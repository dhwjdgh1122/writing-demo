# 다른 제공자의 설명 재검토 제한 진단 계획

2026-11-22 / #22·Draft PR #55. [11/21 자기 재검토](explanation-review-result-2026-11-21.md)의 실패 원출력을 재사용한다. 새로운 초안을 뽑지 않고 **같은 설명을 다른 제공자가 검토하면 기존 누락을 보완하는지** 확인한다. 제품 호출 흐름은 바꾸지 않는다.

실행 후 [4회 결과·미채택 근거](explanation-cross-review-result-2026-11-22.md)를 별도로 연결한다. 아래 계획과 기준은 실행 전 내용으로 보존한다.

## 기존 작업과 구분

PR #48은 같은 제공자가 초안과 재검토를 모두 생성했다. PR #23의 변경 설명·용례 검토 분리도 같은 제공자를 사용했다. 확인한 과거 기록에서 상대 제공자의 출력을 검토한 실험은 찾지 못했다.

E-03의 기존 Gemini 초안은 담당자 확인 조건을 포착했지만 엘리스는 놓쳤다. 다른 실수를 보완할 여지는 있다. 그러나 두 제공자 모두 R-03의 남은 단어 문제와 E-03의 선택 기준을 놓쳤으므로 **공통된 누락은 그대로 남을 수 있다.** 교차검토가 좋을 것이라는 가정을 성공으로 취급하지 않는다.

## 고정 입력과 실행

- [기존 Gemini 보고서](explanation-review-gemini-2026-11-21.json)의 E-03·R-03 **baseline 원출력**은 엘리스가 재검토한다.
- [기존 엘리스 보고서](explanation-review-elice-2026-11-21.json)의 같은 두 baseline 원출력은 Gemini가 재검토한다.
- 과거 보고서의 원문·후보·후보 ID와 초안 JSON, 프롬프트 해시를 고정한다. 파일 내용은 키를 정렬한 canonical JSON 해시로 검사하고 실제 읽은 파일의 바이트 해시도 보고서에 남긴다. 체크아웃 줄바꿈·들여쓰기는 허용하지만 내용 변경은 거부한다. baseline이 아닌 과거 revision이나 이번 사전 실험 출력으로 바꾸지 않는다.
- 재검토 지침은 두 기존 보고서의 동일한 `revisionPrompt`를 그대로 재사용한다. 당시 기준인 최대4개의 짧은 문장·400자를 유지하므로 현재 제품1~2문장 계약의 직접 채택 결과가 아니다.
- 새 제공자 호출은 **각2회·총최대4회**다. 원자료 준비는 오프라인이지만 실제 재검토에는 모델 요청이 필요하다. `gemini-3.5-flash-lite`와 `gpt-4o-mini` 설정을 유지한다.
- 원문·현재 후보·초안 설명만 보낸다. 필수 평가 항목·정답·이번 분석 의견은 보내지 않는다. 초안은 검토 대상이며 지시나 사실로 신뢰하지 않도록 기존 지침을 유지한다.
- 실제 제공자·어댑터·API·인용 검사를 거친 결과를 원출력과 따로 보존한다. 후보 생성, 제품 모델 교체, 자동 교차호출, UI 변경은 없다.

## 평가와 중단

E-03은 조건 삭제·8→10·미확정 소실·원래 정보를 유지하려는 선택 기준을 모두 다뤄야 한다. 문장 표현의 변경을 실제 업무 사실이 바뀐 것으로 단정하지 않는다. R-03은 오타 수정과 별도로 양쪽에 남은 지불 문맥의 단어 문제를 짚고, 이미 고쳤다고 하거나 새 의미 변화로 꾸미지 않아야 한다. 기존 인용 차단을 그대로 적용한다.

고친 오류·그대로 남은 누락·새로 생긴 오류·원래 맞았던 설명의 손상을 모두 기록한다. 두 사례의 필수 항목이 함께 충족되고 새 오류·차단이 없어야 추가 검토 대상으로 삼는다. 일부 문장이 좋아진 것만으로 제품에 두 번 호출하도록 바꾸지 않는다.

기존 자기 재검토는 과거 자료이고 이번은 다른 시점의 단회 요청이다. 따라서 제공자 차이·시점·확률 변동을 분리하는 통제 실험이 아니며, **교차검토의 추가 가치·전체 품질·모델 우열·사용자 효과를 입증하지 않는다.** 긍정적 신호가 있어도 같은 시점의 통제 대조와 기존 전체 기준이 별도로 필요하다.

호출 직전에 기존 후속 장부에 예약하고 429·503·시간 초과 등 서비스 실패에는 해당 제공자의 나머지 호출을 중단한다. 같은 실험을 다시 실행하거나 미실행을 성공으로 채우지 않는다. 최근 Gemini 서비스 오류는 보존하고, 새 진단의 실패 역시 품질 오답과 구분한다.
