# 출력 한도 중단과 후보 개수 제한 점검 결과

**결정: 후보1개 생성 정책은 이번에 채택하지 않는다.** 합성 장문2개에서 기존안도 정상 종료했고 출력 중단을 직접 재현하지 못했다. 1개안의 출력 토큰 감소는 관찰했지만, 일반적으로 다른 대안을 줄일 수 있는 정책 변경이 필요하다는 근거로 확대하지 않는다. 제품에는 출력 한도 종료 구분과 복구 안내만 반영한다.

## 실행과 관찰

- [사전 계획](correction-output-limit-plan-2026-11-21.md), [원자료](correction-output-limit-20261121.json), [공통 호출 장부](approved-model-calls-2026-11-21.json).
- Elice `gpt-4o-mini` 교정5회, 설명0회, 재시도0회, 미실행0회. 기업/팀원 원문은 보내지 않았다.
- 기존 모델·`max_tokens:2000`·`stream:false`·원문을 유지하고 후보 생성 개수 지침만 비교했다. 파일 바이트 해시는 수정 중 작업 트리의 실행 당시 상태를 나타내며 HEAD 커밋만으로 같은 실행 코드를 뜻하지 않는다.
- 아래 검토는 AI 보조 내부 점검이며 사용자 효과·안정적 성공률을 측정하지 않았다.

원자료에는 모델이 반환한 후보9개를 보존했다. 반복형 안내문이라는 제한이 있으며 자유로운 문장·소설·모든1,000자 입력을 대표하지 않는다. 기존안의 후보3개는 각 사례 안에서 완전히 동일했다. 따라서 이번에 서로 다른 선택지가 실제로 줄었다는 관찰은 아니며, 일반적인 후보 다양성 축소 가능성과 구분한다. 숫자 목록·줄 수 비교는 보조 확인이며 필수 조건과 부정의 실제 표현도 대조했다.

## 제품 변경과 미해결 범위

- `length`/`MAX_TOKENS`는 `MODEL_OUTPUT_TRUNCATED`로 구분한다. 파싱 가능한 JSON이어도 해당 종료 사유면 후보/설명으로 사용하지 않는다.
- 교정은 원문·선택 보존과 범위 축소를 안내한다. 설명 실패는 이미 생성한 후보의 비교·적용을 막지 않는다.
- 자동 재시도·모델 교체·출력 한도 상향·잘린 JSON 복구는 하지 않는다.
- 실제 제보의 발생 빈도·완전 예방은 미확인이다. 추가로 반복된다면 입력·모델·종료 사유를 해당 #44에 이어 기록한다. 이번 완료 범위는 안전한 실패 구분/안내와 제한된 완화안 검토다.
- 이5회는 새 승인 작업의 개발24회에 포함한다. 과거 PR #43의24회와 #22 최종평가84회는 별도다.

자동 검증·Edge 재현 결과는 [CORRECTION-RECOVERY-01](../검증%20기록.md#correction-recovery-01)에 기록한다.

## 후속 정책 변경

같은 날 이후 사용자가 새 교정·재교정 후보를 정확히 3개로 고정하도록 요청했다. 이는 위 제한 실험의 결론을 변경하거나 3개 생성의 안정성을 입증한 결과가 아닌 별도 제품 결정이다. 당시 입력·원출력·1개 안 미채택 기록은 그대로 보존하며, 이후 구현·검증은 [CANDIDATE-COUNT-THREE-01](../검증%20기록.md#candidate-count-three-01)을 따른다.

기존 `scripts/evaluate-correction-limit.mjs`는 당시 1~3개 지침의 정확한 문자열을 교체해 비교하도록 고정돼 있다. 이후 지침에서는 문자열이 일치하지 않아 `Baseline instruction changed; review this frozen experiment.` 가드가 모델 호출 전에 실행을 중단한다. 현재 지침에 맞춰 과거 실험을 재작성하지 않았으며, 새 실험은 별도 가설·입력·호출 범위를 정한 뒤 검토한다.
