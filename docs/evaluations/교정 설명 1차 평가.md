# 고정 후보 설명 1차 평가

관련 작업: [#20](https://github.com/dhwjdgh1122/writing-demo/issues/20). 기준: [교정 설명 평가 기준](../교정%20설명%20평가%20기준.md).

## 실행 범위와 증거

- 실행: 2026-11-16 20:06:00~20:06:09 KST. JSON의 시각은 UTC다.
- 실제 요청: Gemini / `gemini-3.5-flash-lite`, 6회, 후보 7개. 후보를 새로 생성하지 않고 작성된 문장 쌍의 설명만 요청했다. 재시도·모델 전환·기업 데이터 사용 없음.
- 제품 코드 기준: `1efe87da2c94abef250a95c4b68893794091f6e1`. 실행 당시 평가 도구·fixture는 작업 브랜치의 미커밋 파일이었으며, 정확한 SHA-256을 실행 JSON에 보존했다. 제품 코드·프롬프트는 변경하지 않았다.
- 경로: 일시적으로 연 로컬 loopback 서버의 `/api/explanations` → 현재 제공자 어댑터 → 실제 모델 → 앱의 형식·인용 검사. 실행 후 서버 종료. 브라우저 화면은 시험하지 않았다.
- 실행 도구: [evaluate-explanation-criteria.mjs](../../scripts/evaluate-explanation-criteria.mjs), 입력: [fixture](../../tests/fixtures/explanation-criteria-cases.json).
- 응답·원문·후보·프롬프트·해시: [실행 JSON](criteria-2026-11-16T11-06-00-424Z.json).
- `adapterExplanations`는 제공자 어댑터의 형식 검사와 동일 후보 고정 처리를 거친 결과다. 모델의 가공 전 응답이나 내부 사고 과정이 아니다. 앱 검사에서 차단된 설명도 여기에 보존했다.
- E-06은 제보 당시 전체 입력이 불확실해 실행에서 제외했다. E-05는 실제 요청은 수행했지만 코드가 고정한 동일 후보 안내이므로 모델 품질 분모에서 제외했다.

**판정 주체는 Codex이며 사람 검토 전의 AI 보조 예비 평가다.** 실사용자의 평가나 사람 1인의 수동 판정으로 기록하지 않는다. 아래 수치는 이번 고정 표본에서의 예비 집계이며 모델 전체 품질·재현 빈도·사용자 효과를 뜻하지 않는다.

### E-01: 단순 수정은 짧게 안내

실제 설명은 `보내 주세여.` → `보내 주세요.`를 짚고 날짜·조건의 의미 변화가 없다고 알렸다. 이 입력에서는 없는 날짜 변경을 만들지 않았다. 표현이 다소 일반적이지만 단순 수정 사례의 기준은 충족한다고 예비 판정했다.

### E-02·E-03: 의미 변화는 포착했지만 선택 기준은 빠짐

- E-02는 특정 요일이 불분명한 시점으로 바뀌었고 의미가 유지되지 않았다고 설명했다. 다만 목요일 일정을 전달하려면 원래 표현을 유지하라는 조건부 선택 기준이나 추가 확인 사항은 제시하지 않았다.
- E-03은 확인 조건 삭제, 8명→10명, 미확정→확정적 표현을 모두 짚었다. 원래 조건·인원을 유지하려는 경우 후보를 그대로 적용하지 않는 편이 적절하다는 선택 기준은 없었다.
- 두 설명은 영향 파악에는 참고가 되지만, #5에서 합의한 ‘중요한 의미 변화는 영향과 선택 기준까지’라는 수준에는 보완이 필요하다. 실제로 도움이 되는지 여부는 사용자 평가가 필요하다.

### E-04: 잘못된 인용과 대안 단어 설명을 구분하지 못한 차단

후보 p1에서는 `결재`를 `결제`로 바꿨고 p2에서는 `결재`가 그대로다. 모델은 각 후보의 차이를 구분했다. p2 설명에는 다음 문구가 포함됐다.

> 돈을 주고받는 일에 쓰는 올바른 단어인 '결제' 대신 서류를 승인한다는 뜻의 '결재'를 사용하여 의미 전달에 오류가 있습니다.

`결제`는 p2의 실제 인용이라고 주장한 표현이 아니라, 남아 있는 단어 문제를 설명하기 위한 대안이다. 하지만 현재 검사는 따옴표 안의 모든 문자열이 원문 또는 해당 후보에 있는지 검사한다. `결제`는 원문·p2 어디에도 없어 불일치가 되고, p1의 설명까지 함께 차단됐다. 인용 추출을 저장된 결과에 다시 적용해 **p2의 `결제` 한 곳이 차단 조건에 해당함을 확인**했다. 추가 모델 호출 없이 검사 조건과 보존 응답을 대조한 결과다.

현재 검사 규칙대로 동작했지만, 의미상 유용한 대안 설명도 차단하는 제한이 구체적으로 드러났다. 단순히 모든 인용 검사를 없애면 허위 인용 차단을 잃으므로, 인용과 대안 표현을 어떻게 구분할지 별도 개선 범위를 정해야 한다. 이번에는 수정하지 않았다.

### E-05: 동일 후보는 고정 안내 확인

`원문과 동일하여 변경된 표현이나 의미가 없습니다.`가 반환됐다. 현재 어댑터가 동일 후보에 고정하는 문구이므로 모델이 좋은 설명을 생성했다는 증거로 집계하지 않는다.

### E-07: 의미 변화는 포착했지만 문법 용어가 부정확

실제 설명은 부정이 긍정으로 바뀌고 보내는 사람·받는 사람이 뒤바뀌었다는 점을 짚었다. 그러나 `운영진에게`를 주어와 짝을 이루는 ‘목적어’로 지칭했다. 이 문장에서 목적어는 `자료를`이며 `운영진에게`는 받는 대상을 나타내므로 해당 문법 명명은 부정확하다고 예비 판정했다. 이 판단도 사람 검토 전이다.

사용자 판단에 필요한 것은 보내는 사람과 받는 사람의 변화다. 불필요한 문법 용어를 사용해 사실 오류를 추가할 필요가 없다. 이 설명에도 원문의 전달 관계·부정 내용을 유지하려는 경우의 선택 기준은 없었다.

E-04는 단어 오용 수정 여부·후보 혼동·정보 왜곡을 사실 일치와 선택 정보 항목으로 평가했다. 그 변화의 의미를 부정하는 것이 아니라, 위 7/7의 분모는 **E-02·03·07에 사전 정의한 정보 손실·변형 요소**로 한정했다는 뜻이다. 요청 성공이나 변화 포착만으로 좋은 설명이라고 결론 내리지 않는다. 실패 1개·보완 2개·내용 통과 3개라는 설명 판정과, 통과 내용 2개가 실제로는 차단됐다는 점을 함께 본다.

## 후속 개선 후보와 한계

1. 프롬프트: 중요한 의미 변화에 조건부 선택 기준을 포함하고, ‘주어·목적어’ 같은 불필요한 문법 명명 대신 사용자에게 필요한 전달 관계로 설명하도록 보완할 필요가 있다. 이번 출력에서 드러난 후보이며 변경·효과 확인은 아직 하지 않았다.
2. 검사·설명 형식: 원문·후보의 실제 인용과 대안 표현을 구분하는 방법, 한 후보 오류로 전체 설명이 차단되는 범위를 검토할 필요가 있다. 잘못된 인용을 통과시키지 않는 회귀 사례가 필요하다.
3. 추가 평가: 각 사례 1회라 반복 발생률을 알 수 없다. E-06은 미실행, 엘리스 비교·실제 교정 후보 생성·브라우저 표시·사람의 선택 도움은 미검증이다.

검증 도구의 dry run으로 6개 입력·7개 후보의 스키마를 확인했다. `node --check`, 타입 검사, 단위·API 테스트 42개가 통과했다. 저장된 실행 도구·fixture 해시를 현재 파일과 대조했다. 테스트 통과는 실제 설명 품질의 통과를 의미하지 않는다. 제품 화면 동작을 바꾸지 않아 브라우저 테스트·빌드는 반복하지 않았다.
