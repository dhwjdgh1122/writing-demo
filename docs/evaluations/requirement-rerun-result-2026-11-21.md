# 요구 반영 재교정의 실제 연결 점검 결과

2026-11-21 / #49. [실행 전 계획](requirement-rerun-plan-2026-11-21.md)에 따른 제한 점검이다. 요구 전달과 실제 생성 후보의 설명 연결은 확인했으나, **모델이 요구를 온전히 충족하거나 설명을 정확히 제공한다는 결과는 아니다.** #22의 내용 품질은 미완료로 유지한다.

## 조건과 원자료

- 구현·계획 커밋 `3a581d9`, 최신 main 통합 후 실행 기준 `ad72211`. 두 보고서의 실행 시 작업 트리·파일 해시·전송 프롬프트·설정을 보존했다. 두 번째 제공자 실행 때 생긴 첫 보고서·호출 장부 변경은 실행 기록이며 제품 입력·프롬프트 변경이 아니다.
- Gemini `gemini-3.5-flash-lite`, 엘리스 `gpt-4o-mini` 각각 교정2회·실제 생성 후보의 설명1회, **총6회**. 모든 API가 HTTP 200을 반환했고 출력은 정상 종료했다. 자동 재시도·대체 모델·결과 선별은 없다.
- [Gemini 전체 출력](requirement-rerun-gemini-2026-11-21.json), [엘리스 전체 출력](requirement-rerun-elice-2026-11-21.json). 입력은 합성 예문이며 기업 원문을 전송하지 않았다.
- [공통 호출 장부](approved-model-calls-2026-11-21.json)의 이번 승인 작업 누적은 **개발19/24·최종0/84·총19/108회**다. 이전 PR #43의 실험24회와 별개다.

## 1. 적용 전 ‘다른 표현’

현재·이전 선택 원문은 `금요일까지 자료를 보내 주세요.`, 이전 후보는 `금요일까지 자료를 보내 주시기 바랍니다.`다.

| 모델·후보 | 실제 새 후보 | 판정 |
|---|---|---|
| Gemini 1 | 금요일까지 자료를 제출해 주세요. | 이전 후보와 다른 표현·기한 유지. ‘보내다’가 ‘제출하다’로 좁아져 문맥 없이 의미의 완전한 보존은 확정하지 못함 |
| 엘리스 1 | 금요일까지 자료를 보내주시길 부탁드립니다. | 다른 표현과 기한·자료 전달 요청 유지 확인 |
| 엘리스 2 | 금요일까지 자료를 보내 주시면 감사하겠습니다. | 다른 표현과 기한 유지. 간접적 부탁으로 읽혀 요청 강도가 완화될 가능성 있음 |

후보가 달라졌다는 사실과 사용자 의도 충족은 구분한다. 실제 사용자 판단은 수집하지 않았다.

## 2. 적용 후 ‘원래 뜻 유지’

현재 문장은 `목요일에 10명에게 안내합니다.`, 이전 선택 원문은 `담당자 확인 후 목요일에 8명에게 안내할 예정입니다.`다. 현재 문장뿐 아니라 이전 선택 원문·후보와 선택 요구를 실제 모델 요청에 전달했다.

| 모델 | 실제 새 후보 | 필수 기준 대조 |
|---|---|---|
| Gemini | 담당자 확인 후 목요일에 8명에게 안내합니다. | 담당자 확인 조건·8명·목요일은 복원/유지. **예정 표현은 미복원** |
| 엘리스 | 목요일에 8명에게 안내합니다. | 8명·목요일은 복원/유지. **담당자 확인 조건·예정 표현은 미복원** |

두 후보 모두 실행 전에 정한 의미 유지 기준 전체를 충족하지 못했다. 일부 숫자를 복원한 결과를 요구 충족으로 표시하지 않는다.

## 3. 실제 생성 후보에 대한 설명

준비한 정답 후보로 교체하지 않고 위 두 결과를 각각 설명 요청에 사용했다. 비교 대상은 현재 `목요일에 10명에게 안내합니다.`와 실제 새 후보이며, 이전 선택 원문은 사용자의 요구를 해석하는 자료다.

- **Gemini:** 현재 문장의 `10명 → 8명`, `담당자 확인 후` 추가를 정확하게 짚었다. 다만 다음 문장의 “이전 선택 원문에서 유지하고자 했던 의미와 사실 관계 중 인원수와 조건에서 차이가 발생했습니다”는 이전 원문과의 비교 기준이 모호하다. 예정 표현 미복원도 안내하지 않았다.
- **엘리스:** `10명 → 8명` 차이는 정확하지만, 이로 인해 “사용자가 이전 원문에서 원하는 의미의 유지가 불가능하게 됩니다”라고 설명했다. 이전 원문의 8명으로 복원한 것을 의미 유지 불가능의 원인처럼 설명하는 오류가 있다. 조건·예정 미복원도 안내하지 않았다.
- 설명2개 모두 현재 원문·후보의 인용 검사를 통과했다. **인용 일치 검사는 위 의미 오류와 누락을 막지 못한다.** 요구를 받았다는 사실만으로 요구 충족을 주장하지 않도록 한 지시도 안정적인 보장이 아니다.

## 판단과 남은 범위

#49는 요구·이전 문장의 요청 연결, 적용 전후 기준 구분, 이력·행동 기록과 내보내기의 동작 범위로 관리한다. 위 의미 복원 누락·설명 오류는 #22의 품질 후속 근거로 연결하며 완료 처리하지 않는다. 자동 평가 통과나 90점 달성으로 표현하지 않는다.

이번6회는 사례·모델별 단회 점검이며, 반복 성능·모델 우열·오류 빈도·사용자 만족·설명 효과를 추정하지 않는다. `polite`, `plain`, `errors` 유형은 요청 계약·프롬프트와 주입 응답으로 검증했으며 실제 모델 내용 평가는 하지 않았다. UI·기록의 자동 검증은 [DEMAND-RERUN-01](../검증%20기록.md#demand-rerun-01)에 구분한다. 추가 호출로 같은 예문을 반복해 성공 결과를 찾지 않고 이 결과에서 제한 점검을 종료한다.
