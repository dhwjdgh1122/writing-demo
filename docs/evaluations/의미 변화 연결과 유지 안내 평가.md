# 의미 변화 연결과 유지 안내 평가 — H

2026-11-16 / #22 / Codex AI 보조 예비 평가. 사람의 독립 평가·실제 사용자 효과 검증은 아니다.

## 결론

**미완료다. PR #23을 초안으로 유지하고 main에 병합하지 않는다.** 감지된 의미 변화와 원문 정보를 연결하는 코드는 검증했지만, 실제 모델 설명은 여전히 조건·확정 변화 등을 누락하고 잘못된 수정 내용을 설명했다. 원문의 오타가 포함된 문구를 유지하라는 응답도 나왔다. 자동 검사의 성공이나 API 응답 성공을 품질 통과로 해석하지 않는다.

## 변경과 범위

- 코드 `3931a75`: 모델 내부 출력에 `meaningChanges`를 추가했다. 변화 종류와 원문·후보 참조를 연결하고, 서버가 참조의 출처·요약 사용 여부를 확인한다. 의미 변화가 선언되면 연결된 원문 정보로 유지 안내를 조합한다. 후보의 변경된 값을 원문 유지 정보로 연결하거나 별도의 자유 안내를 섞으면 거부한다. 순수 추가 정보는 별도로 의도 확인을 안내한다.
- 단순 수정에는 기존 짧은 요약을 사용한다. 미수정 용례 문제만 남았을 때의 자유 안내는 허용한다. 프롬프트에 조사 연결을 자연스럽게 쓰도록 명시했다. 의미 변화의 탐지·분류와 요약 내용은 여전히 모델에 의존한다.
- 검증 실패를 `schema`, `ids`, `reference`, `template`, `meaning-link`, `length`로 분류해 평가 자료에만 기록한다. 공개 API 오류와 `{candidateId, explanation}` 형식은 유지한다. 이 검사 전의 제공자 응답 해석 오류는 세부 코드가 없을 수 있다.
- 원시 구조 응답은 저장하지 않는다. 따라서 실패 단계는 확인할 수 있어도 어느 참조 번호나 문구가 원인이었는지는 확정할 수 없다. 성공 자료도 조합 후 설명이므로 개별 의미 분류를 직접 감사한 자료는 아니다.
- 코드 `0cc089f`: Gemini가 새 중첩 스키마를 거절하여 전송 스키마의 `meaningChanges` 배열 개수·참조 번호 범위 제약만 단순화했다. 서버의 Zod 상한·정수·출처·연결 검사는 그대로다. 프롬프트·엘리스 요청·렌더링 동작은 바꾸지 않았다.
- 교정 후보 생성·화면·기본 `.env`는 변경하지 않았다. 기업 데이터 대신 기존 합성 원문·고정 후보를 사용했고 실제 사용자 문서를 전송하지 않았다.

## 검증과 남은 작업

- `3931a75`: 타입 검사·단위/API 61개·빌드·Edge 20개 통과. 브라우저는 모델 응답을 주입한 기존 흐름 검사이며 실제 모델 품질 평가와 다르다.
- `0cc089f`: 타입 검사·단위/API 62개·빌드 통과. 새 검사에는 전송 스키마를 단순화해도 서버의 중첩 상한을 유지하는 시험이 포함된다. CI 결과는 로컬 검사와 구분해 확인한다.
- 기록 검증: 실행 5묶음의 커밋·프롬프트·출력 처리·도구·입력 해시, 기존 G와 같은 사례·파생 입력, 실제 호출 수를 대조했다. 관련 문서 7개의 내부 링크·앵커 153개와 diff 검사를 통과했고, 알려진 인증값 패턴 및 로컬 비밀값의 혼입이 없으며 `.env` 해시가 그대로임을 확인했다.
- 남은 핵심은 **단순 수정과 중요한 의미 변화의 구분, 조건·확정·관계 영향의 누락, 잘못된 원문 유지 안내, 구조 출력의 안정성**이다. 모든 설명을 차단하거나 모든 입력을 원문 유지 안내로 처리해서 완료로 삼지 않는다.
- 다음 실험은 중요한 원문 정보를 오타·표면 표현과 분리하는 방법, 누락/오분류를 확인할 수 있는 안전한 평가 증거 수집을 먼저 설계해야 한다. 이것은 다음 제안이며 이번에 구현·검증 완료한 내용은 아니다.
