# 실제 인용·사전 참조 구분의 최소 모델 진단 계획

2026-11-22 / #22·Draft PR #55. [오프라인 설계 검증](explanation-typed-reference-plan-2026-11-22.md)을 바탕으로 **모델이 출처가 다른 조각을 구분해 응답하고, 필요한 단어 설명을 정확하게 전달하는지** 확인한다. 제품 계약 변경이나 전체 품질 통과 결과가 아니다.

## 가설과 고정 입력

[사전 참조 배치 실험](explanation-lexical-reference-result-2026-11-22.md)에는 실제 남은 단어 문제를 찾고도 기본형·대안 용어를 원문 인용처럼 출력해 차단된 사례가 있었다. 서버가 실제 문장 인용과 고정 사전 항목을 따로 검사하면 이 차단 원인을 줄일 가능성이 있다. 반면 일반 설명의 의미 오판·누락과 사전 뜻의 부적절한 적용은 이 구조만으로 해결되지 않는다.

- 기존 `referenceInstruction`의 내용 기준을 유지한다. 한국어1~2문장·최종400자·후보별 독립 비교·잔존 오류·문맥의 모호함·실제 변경과 사전 뜻 구분을 유지한다.
- 기존 출력 JSON·인용 형식 지침만 새 `segments` 계약으로 명시적으로 교체한다. 상충하는 두 형식을 동시에 요구하지 않는다.
- 입력은 `sourceText`, `candidates`, `typedReferenceCatalog`다. 사전 항목은 이전 실험에서 사용한 공식 두 정의와 출처에 고정 ID를 붙인 동일 자료다. 원본 사례의 `required`, `expectedNotes`, 평가 의견, 과거 모델 출력은 보내지 않는다.
- 출력은 `text`, `input_quote`, `lexical_reference` 세 종류다. 실제 인용은 지정한 원문 또는 해당 후보에 있는 연속 문자열이어야 하며, 사전 항목은 서버의 고정 ID만 허용한다. 일반 설명에 인용 부호나 서버의 사전 라벨을 직접 쓰면 거부한다.
- 이 최소 proof는 중첩 인용을 지원하지 않는다. 현재 두 사례에 중첩 인용은 없으므로 결과를 전체 원문 범위의 지원으로 확대하지 않는다.

## 실행 범위와 제품 경로 구분

**R-03·E-04 × 두 제공자 = 최대4회**, 제공자별2회다. 후보 결과는 제공자별3개, 합계6개다. 동일 실험 반복 없이 R-03 다음 E-04 순서로 실행한다.

Gemini `gemini-3.5-flash-lite`와 엘리스 `gpt-4o-mini`, 기존 출력 토큰·LOW 추론 설정을 유지한다. 응답 형식이 제품과 다르므로 별도 실행기로 제공자에 직접 요청한다. **제품 API·브라우저의 표시 성공으로 기록하지 않는다.** 새 형식 지원 오류가 나면 그 사실을 남기고 해당 제공자의 나머지 호출을 중단한다.

전체 응답의 후보 ID 누락·중복·외부 ID를 먼저 검사한다. 이 검사를 통과하면 각 후보의 조각을 오프라인 파서에 독립적으로 넣어 후보별 형식·출처·최종 길이 결과를 기록한다. 한 후보의 실패가 다른 후보의 진단 결과를 지우지 않게 하려는 평가 방식이며 제품의 실패 처리 정책을 바꾸는 것이 아니다.

실제 지침·입력·스키마·원출력·후보별 파서 결과·요청 시간·토큰·코드/입력 해시를 보존한다. 파서 통과와 내용 평가는 별도다. 사전 참조가 표시되었다는 사실만으로 모델 설명의 근거가 모두 검증됐다고 하지 않는다.

## 내용 평가와 다음 판단

| 사례 | 기존 필수 내용 |
| --- | --- |
| R-03 | 실제 오타 변경을 설명하고, 지불 문맥에 남은 결재의 문제를 별도로 알린다. 이미 결제로 고쳤다거나 새 의미 변화가 생겼다고 하지 않는다. |
| E-04-p1 | 원문의 결재가 후보에서 결제로 바뀐 사실과 납부 문맥의 차이를 정확하게 설명한다. |
| E-04-p2 | 양쪽에 결재가 남아 있다는 사실을 실제 수정과 구분하고, 납부 문맥의 잔존 단어 문제를 알린다. 이를 생략한 형식 통과는 내용 통과가 아니다. |

두 제공자의 세 후보에서 기존 필수 내용과 출처 형식을 함께 충족하고 새 오류가 없어야 정상 승인·모호한 문맥·정상 지불의 경계 검토를 다음 후보로 삼는다. 일부만 좋아지면 무엇이 좋아졌고 무엇이 남았는지 구분한다. 원출력의 단어를 자동 치환하거나 사람이 조립해 성공으로 바꾸지 않는다.

단회·알려진 두 사례이며 과거 자유문 출력과 동시 대조하는 실험도 아니다. 출처 구분이 일반적으로 더 낫다는 인과효과·모델 우열·사용자 효과를 주장하지 않는다. 긍정적이어도 [기존14사례 전체 기준](issue22-original-gate-2026-11-22.md)을 대체하지 않는다.

## 호출·중단·기록

기존 후속 장부 **56회**에 이어 호출 직전 예약한다. 전체 횟수 상한은 사용자가 해제했지만 이번 진단은 제공자별2회로 고정한다. 실제 요청 실패·시간 초과·결과 불명도 횟수와 원인에 남긴다. 서비스 오류 시 해당 제공자 나머지 요청은 미실행으로 보존하며 자동 재시도·제공자 대체·동일 실험 재실행은 없다. 이전19회 및 실패 기록을 수정하지 않는다.

제품 코드·프롬프트·UI·후보 생성 경로와 main은 바꾸지 않는다. 준비한 실행기를 자동 테스트나 서버 시작에서 실제 호출하지 않으며 기본 실행은 dry-run이다.
