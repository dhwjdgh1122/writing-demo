# 조건 해석과 분류 분리 진단

2026-11-17 KST / #22 / 기준 코드 `8d4b5b3`. **진단 방식은 서비스에 적용하지 않는다.** 조건 분류를 맞히더라도 설명에 원문에 없는 배타적 의미가 추가돼 병합 기준을 충족하지 못했다.

## 확인하려던 문제

원문과 후보를 각각 해석한 뒤 비교하면, 같은 조건을 다른 말로 표현한 경우와 조건을 삭제·추가·교체한 경우를 구분할 수 있는지 확인했다. 두 문장의 조건 인용(`conditionQuote`), 행동 범위 요약(`scope`), 관계(`relation`), 영향(`impact`)을 반환하게 했다.

이 진단은 실제 설명 기능의 지침·입력·출력 형식을 함께 바꾼 별도 과제다. 제품 품질의 전후 비교나 특정 원인의 입증으로 해석하지 않는다. 기업 데이터나 주변 문맥은 사용하지 않았다.

## 사례별 관찰

| 사례 | V1 관찰 | V2 관찰 |
|---|---|---|
| CT-02: 허가가 없으면 출입 불가 → 조건 없는 출입 불가 | 두 모델 모두 삭제로 분류했다. Gemini는 `항상`으로 강하게 표현했고, 엘리스는 `더 넓은 문맥`이라는 모호한 영향을 적었다. | 두 모델 모두 삭제를 인식했다. Gemini는 조건 없는 금지, 엘리스는 조건부 불가와 단순 불가를 대조했다. 실제 정책 변경으로 단정하지 않는 표현은 계속 검토해야 한다. |
| CS-02: 환불 불가 → 상품 사용 시 환불 불가 | 두 모델 모두 추가로 분류했지만 Gemini의 `조건이 추가되었습니다`, 엘리스의 `명확해졌습니다`만으로는 전후 범위의 차이가 충분히 설명되지 않았다. | 두 모델 모두 후보 요약에 `경우에만`을 추가했다. 엘리스는 영향 설명에도 `특정 경우에만`을 써서, 조건 밖의 경우를 규정하지 않는 원문을 배타적 조건으로 강화했다. |
| CT-03: 회원인 경우에만 → 회원만 | 두 모델 모두 조건 유지로 분류했다. 앞선 제품 형식 시험에서의 조건 삭제 오분류가 이번 과제에서는 나타나지 않았다. | 두 모델 모두 유지로 분류했다. 엘리스의 후보 요약은 `회원일 경우`로만 적어 제한을 명시하지 않았지만 최종 영향에는 회원 제한을 유지했다. |
| CT-01: 담당자 동의 → 예산 확보 | Gemini는 교체로 분류했다. 엘리스는 양쪽 조건을 인용하고도 삭제로 분류했으며 `경우에만`, `변경할 수 있다`로 원문의 진술까지 바꿨다. | 두 모델 모두 교체로 분류했다. 그러나 Gemini의 양쪽 요약에는 여전히 원문에 없는 `경우에만`이 추가됐다. |

예를 들어 `상품을 사용한 경우에는 환불하지 않습니다`는 사용하지 않은 상품의 환불 여부까지 정하지 않는다. 이를 `상품을 사용한 경우에만 환불하지 않습니다`로 요약하면 원문보다 강한 뜻이 된다. 조건 구절을 정확히 인용하고 분류값을 맞혀도 자유롭게 작성한 요약·영향에는 이런 오류가 남을 수 있다.

## 판단과 다음 수정 범위

- 문장별 조건 추출과 관계 분류는 추가 검토할 수 있는 방향이다. 다만 V2의 분류 8건 일치만으로 안정성·설명 품질 개선을 확정하지 않는다.
- 자유 요약이 새로운 의미 오류를 만들었으므로 이 요약 필드를 제품 계약에 추가하거나 사용자에게 보여주지 않는다. 추가 모델 호출로도 연결하지 않는다.
- 후속 실험에서는 조건 구절뿐 아니라 **조건이 붙는 행동·부정·한정 표현을 원문 그대로 연결**하고, 영향 설명이 그 근거를 넘어서는지 확인하는 범위로 좁힌다. 인용 일치 검사는 의미 검증의 대체가 아니다. 알려진 사례 밖의 대조 사례도 별도로 필요하다.
- 서비스 프롬프트·응답 검사·화면은 유지한다. 남은 단어 문제와 실제 사용자 효과도 미해결이다. [14사례·모델별 3회 병합 검증](../교정%20설명%20평가%20기준.md#issue22-merge-gate)은 아직 실행하지 않는다. #22 진행 중·PR #23 Draft·main 미병합을 유지한다.
