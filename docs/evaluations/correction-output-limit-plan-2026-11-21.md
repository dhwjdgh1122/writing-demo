# 교정 출력 한도 중단 제한 점검 계획

2026-11-21 실행 전 기준. #44는 #1의 문장 누락·#22의 설명 내용 품질과 구분한다. 제보 원문을 재전송하지 않고 직접 작성한 합성 문장을 사용한다.

## 문제와 개선 가설

Elice는 기존 실행 설정에서 비스트리밍 출력 상한 2,000토큰을 사용한다. 최대3개 후보를 생성하면 긴 입력을 반복 출력하는 부담이 있다. **입력 전체의 완결 후보1개만 요청하면 잘림을 줄일 수 있는지** 확인한다. 모델·출력 한도·원문은 같게 유지하며, 중단된 JSON을 복구하거나 조각을 이어붙이지 않는다.

제품에는 우선 종료 사유 `length`/`MAX_TOKENS`를 `MODEL_OUTPUT_TRUNCATED`로 구분하는 처리를 구현했다. 원문·선택 유지, 교정 범위 축소 안내, 설명 실패 시 후보 비교·적용 유지를 자동 회귀로 검사한다. 이 동작 검증은 실제 발생 빈도 검증이 아니다.

## 사전 고정 입력과 순서

실행기: [evaluate-correction-limit.mjs](../../scripts/evaluate-correction-limit.mjs). 전체 입력을 원자료에 보존한다.

| 사례 | 길이 | 확인할 정보 | 순서 |
|---|---:|---|---|
| L-01 | 800자 | 준비반9개·금요일3시·자료8개·담당자 승인 조건·토요일 발송·승인 없을 때 부정·9줄 | 기존안 → 1개안 |
| L-02 | 990자 | 상담실8개·운영9~18시·목요일 취소·12명 미만 조건·예정/미확정·항목 사이 빈 줄 | 1개안 → 기존안 |
| S-01 | 57자 | 승인 조건·금요일·8명·미확인 시 발송 금지 | 1개안 |

각 조건1회, **Elice gpt-4o-mini 총5회**만 시도한다. 전체 위임 호출108회 중 개발24회에 포함하며, 최종 평가84회와 구분한다. 공통 호출 장부는 외부 fetch 직전에 예약하고 실패·중단도 차감한다. `.env`나 제공자를 바꾸지 않는다.

## 판단과 중단 기준

- 완결된 유효 후보, 각 항목과 필수 정보, 직접 줄바꿈·빈 줄 보존을 확인한다. 단순 숫자 목록 일치만으로 의미 보존을 판정하지 않는다.
- 한쪽만 실행되면 짝 비교를 보류한다. HTTP 성공과 모델 출력 완결, 내용 정확성을 구분한다.
- 1개안이 완결돼도 반복 안정성·모든 입력 성공은 주장하지 않는다. 기존안보다 후보 선택지가 줄어드는 trade-off를 기록한다.
- 설정·사용량·서비스·시간 초과 문제가 나면 중단하고 미실행을 남긴다. 자동 재시도·다른 모델 전환 없음.
- 기존안이 잘리지 않으면 제보를 직접 재현했다고 쓰지 않는다. 근거가 없거나 1개안에 중요한 내용 손상이 생기면 채택을 보류한다.

실행: 기본 `node --import tsx scripts/evaluate-correction-limit.mjs`는 dry-run이다. 실제 호출은 승인된 장부 경로를 `MODEL_CALL_LEDGER`로 지정하고 `--live`를 명시한다. 기본 테스트·서버 시작에 포함하지 않는다. API 키·URL·헤더는 기록하지 않는다.
