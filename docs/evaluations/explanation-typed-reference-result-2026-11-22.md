2026-11-22 / #22·Draft PR #55. 실행 기준 `2c4e123`. [오프라인 검증](explanation-typed-reference-plan-2026-11-22.md)과 [실행 전4회 계획](explanation-typed-reference-live-plan-2026-11-22.md)을 보존한다. **현재 안은 제품에 채택하지 않는다.**

## 실행과 형식 결과

| 제공자 | 실제 요청 | 구조·출처 결과 | 남은 요청 |
| --- | --- | --- | --- |
| 엘리스 `gpt-4o-mini` | R-03·E-04 총2회 HTTP200 | 후보 ID는 유효했지만 R-03은 자유문 인용, E-04의 두 후보는 조각 필드 위반으로 세 후보 모두 proof 실패 | 없음 |
| Gemini `gemini-3.5-flash-lite` | R-03 1회 HTTP400 | 정상 생성 원출력 없음. 실행기는 설정/요청 오류 범주로 기록 | E-04 1회 미실행 |

실제 호출은 **3회**, 정상 HTTP 응답의 후보 출력은3개다. Gemini의2후보 E-04는 미실행이며 R-03도 설명을 받지 못했다. 합계6개 예정 후보 중3개의 내용을 관찰했고, 나머지3개를 내용 오류나 성공으로 분류하지 않는다. 제공자 응답의 JSON 파싱 성공·후보 ID 성공과 개별 조각 계약 통과를 구분한다.

이번 실행은 제품 API가 아니라 제공자 직접 요청과 오프라인 파서의 진단이다. `proof.ok`는 실제 화면 표시 성공이 아니며, 이번에는 세 출력 모두 실패했다. 제품의 후보별 실패 처리·프롬프트·UI를 바꾸지 않았다.

## 원출력 내용 검토

| 사례 | 확인한 내용 | 남은 문제와 판정 |
| --- | --- | --- |
| 엘리스 R-03 | 지불 문맥에는 결재가 아닌 결제 뜻이 맞다는 잔존 문제를 짚었다. | `햇습니다→했습니다`를 **시제 오류 해결**이라고 설명했다. 두 표현은 모두 과거를 나타내려는 형태이며 이 오타를 시제 변경으로 설명할 근거가 없다. 일반 `text` 안에 인용을 직접 쓰고 그 뒤 인용·사전 조각을 덧붙여 요구한 구분도 지키지 못했다. 형식과 내용 모두 미충족이다. |
| 엘리스 E-04-p1 | 결재→결제 변경과 납부 문맥의 뜻 차이를 짚은 문장이 응답에 있었다. | 그 문장을 `text` 값으로 쓰지 않고 객체의 임의 키로 사용했고, 같은 조각에 `quote`도 넣었다. JSON 자체는 읽혔지만 지정 스키마와 다르다. 일반문 인용·3문장도 지침과 다르다. 잘못된 객체의 키를 설명으로 자동 복구하지 않는다. |
| 엘리스 E-04-p2 | 결재가 그대로 남았고 지불 문맥에 부적절하다는 지적은 응답 안에 있었다. | p1과 같은 조각 필드 위반이며 실제 띄어쓰기·오타 수정 설명은 빠졌다. 남은 단어 문제를 짚었다는 부분 관찰과, 실제 제공 가능한 정확한 설명을 만들었다는 판정을 구분한다. 이 응답도 자동 복구하지 않는다. |

형식이 통과했더라도 R-03의 잘못된 문법 설명은 내용 실패다. 반대로 E-04의 부분적으로 유용한 언급을 모두 틀린 내용이라고 처리하지 않는다. 원출력과 입력을 그대로 보존하며 모델이 성공한 형식으로 사람이 재조립하지 않는다.

## Gemini 요청 거절의 한계

HTTP400은 요청을 받아 생성한 설명의 품질 결과가 아니다. 새 스키마는 `anyOf` 조각 유형을 포함한다. 앞선 단순 조건 추출 스키마는 같은 제공자·모델에서 동작했지만, 그 사실과 이번400만으로 거절된 정확한 키나 복잡도 원인을 확정할 수 없다.

실행기는 비정상 응답 본문을 읽거나 저장하지 않으므로 이번 자료에는 제공자의 상세 오류 메시지가 없다. **현재 요청 조합이 거절됐다는 것까지만 확인했다.** 공식 문서의 스키마 지원 안내를 해당 모델의 이번 요청 성공 보장으로 해석하지 않는다. 동일 요청 재시도나 스키마를 임의로 축소한 재호출은 하지 않았다.
