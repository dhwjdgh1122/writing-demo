# 문장별 독립 입력의 조건 추출 진단 계획

2026-11-22 / #22·Draft PR #55. 앞선 [교차 검토](explanation-cross-review-result-2026-11-22.md)는 선택 기준·잔존 단어 문제를 해결하지 못했다. 다음은 **원문과 후보를 한꺼번에 볼 때와 각각 따로 볼 때, 문장에 실제 있는 조건을 놓치는 양상이 달라지는지** 확인하는 별도 진단이다. 제품 채택 계획이나 설명 완성 결과가 아니다.

실행 후 [18회 결과·미채택 근거](explanation-isolated-conditions-result-2026-11-22.md)를 연결한다. 아래는 실행 전 기준으로 보존한다.

## 기존 실험과 다른 점

PR #23의 조건 해석 V1/V2·조건 근거 V1/V2 실행기와 원자료8개를 대조했다. 당시40회는 모두 사례당 한 요청으로 원문과 후보를 함께 보냈다. 각각 읽으라는 지시는 있었으나 상대 문장을 입력에서 숨기지는 않았다. `253d4c1`의 후보만 받는 잔존 단어 검토도 원문·후보의 조건을 독립 추출해 비교한 실험과 다르다.

독립 입력이면 비교 상대의 문구에 끌려 원래 조건을 놓치는 문제를 줄일 가능성이 있다. 이는 아직 가설이다. 별도 요청을 늘렸다는 사실만으로 개선을 기대하거나 확정하지 않는다.

## 같은 지침, 두 가지 입력

- **함께 입력(joint):** 한 요청의 `texts`에 두 문장을 넣고 각 문장에 있는 조건·그 조건이 걸린 행동 또는 상태 구절을 추출한다.
- **독립 입력(isolated):** 같은 지침과 같은 구조에서 `texts`를 한 문장만 포함하게 한다. 원문을 처리할 때 후보를, 후보를 처리할 때 원문을 보내지 않는다. 이전 응답도 전달하지 않는다.
- 각 항목은 역할을 나타내지 않는 ID와 문장뿐이다. fixture의 필수 기준·정답·기존 설명·평가 결과는 보내지 않는다.
- 출력은 항목 ID와 조건/행동의 정확한 인용 배열이다. 명시된 조건·대상 제한이 없으면 빈 배열이며, 새 표현·반대 상황의 결과·상태 판단을 생성하지 않는다. 코드가 각각 해당 입력에 존재하는 연속 문자열인지 확인한다.
- 두 항목에 모두 조건이 있다고 의미가 같다고 판정하지 않는다. 코드로 비교할 수 있는 것은 추출된 조건의 존재 여부·인용 유효성뿐이다. 조건의 의미·누락·범위는 원문과 대조해 별도 판정한다.

## 고정 범위와 평가

기존14사례 중 E-03·CT-02·CT-03을 그대로 사용한다. 날짜·숫자·미확정 표현도 원문에서 삭제하지 않지만 이번 추출의 합격을 전체 설명 기준 충족으로 계산하지 않는다.

| 사례 | 확인할 조건과 경계 |
| --- | --- |
| E-03 | 원문의 담당자 확인 제한을 찾고, 조건이 없는 후보에 조건을 만들지 않는가 |
| CT-02 | 원문의 허가 부재 조건과 출입 불가 구절을 보존하고, 후보의 부정을 출입 허용으로 뒤집지 않는가 |
| CT-03 | ‘경우에만’과 ‘만’ 두 표현에 있는 회원 제한을 모두 찾는가. 정확한 인용만으로 의미 동치를 증명했다고 하지 않는가 |

**3사례 × (함께1회 + 독립2회) × 2제공자 = 최대18회**, 제공자별9회다. 사례마다 두 조건의 실행 순서를 번갈아 배치한다. Gemini `gemini-3.5-flash-lite`·엘리스 `gpt-4o-mini`, 기존 출력 토큰·LOW 추론 설정을 유지한다. 이 추출 JSON은 제품의 설명 계약과 다르므로 별도 실행기로 실제 제공자에 요청하며, 제품 API·브라우저 설명을 검증했다고 표현하지 않는다.

양쪽 조건에서 같은 지침·출력 스키마를 쓰고 실제 입력·원출력·구조/인용 판정·시간·토큰·코드 해시를 남긴다. 독립 방식의 총2회 지연·호출량도 함께 비교한다. 단회·세 개의 알려진 사례이므로 발생률·인과효과·일반화 증거는 제한적이다.

## 확대·중단 기준

독립 입력이 함께 입력의 누락/오판을 줄이고 새 오류가 없어야 후속 설명 연결을 검토한다. 동일하거나 나빠지면 이 배치를 반복하지 않는다. 구조·정확 인용만 통과하고 중요한 조건이 빠진 경우는 추출 성공으로 세지 않는다. 긍정적이어도 조건 교체·추가 등 추가 경계와 설명 출력까지 별도로 확인해야 하며 기존 전체 품질 기준은 유지한다.

기존 후속 장부38회에 이어 호출 직전 예약한다. 전역 호출 상한은 사용자가 해제했지만 이번 진단은 각9회로 고정한다. 실패·시간 초과·결과 불명도 남기고, 서비스 오류 시 해당 제공자의 남은 호출을 중단한다. 같은 실험 재실행·자동 제공자 전환은 없다. 원자료와 평가 기준을 보존하며 제품 코드·UI·후보 생성은 바꾸지 않는다.
