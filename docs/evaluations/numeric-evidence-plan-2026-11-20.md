# #22 숫자 자료 입력 제한 실험 — 실행 전 계획

**작성일:** 2026-11-20. 기준 코드 `9dd6bea`(PR #42 이후 main). 제품 채택이나 #22 완료 기준을 변경하는 문서가 아니다.

## 확인할 질문과 변경 범위

원문·후보와 함께 코드가 계산한 **숫자 표기·등장 횟수 차이**를 주면, 설명에서 원래 숫자나 변경 내용을 빠뜨리는 문제가 줄어드는가?

- 기준안: 현재 main의 설명 프롬프트·요청·검사 그대로.
- 수정안: 같은 요청에 `numericEvidence` 자료와 그 자료의 해석 범위 지침만 추가. 이 묶음의 효과를 비교하며, 자료와 추가 지침 각각의 효과를 분리해 입증하는 실험은 아니다.
- Draft [PR #34](https://github.com/dhwjdgh1122/writing-demo/pull/34)의 `70f5d57:client/src/lib/numeric-comparison.ts` 표기 추출·횟수 계산·상한을 재사용한다. `null`을 차이 없음과 상한 초과로 구분하고 숫자가 같다고 의미 보존으로 안내하지 않는다.
- 기준안·수정안 모두 원문과 후보 전체를 유지한다. 숫자 교체의 대상·단위·원인은 코드가 추정하지 않는다. `1,000→1000`은 표기 차이이며 수량 변화라고 단정하지 않는다.
- 제품 어댑터·교정 생성·화면·인용 검사·응답 계약·모델 설정·실제 `.env`를 변경하지 않는다. 수동 평가의 fetch 주입에서만 요청을 수정한다. 출력에 고정 설명을 붙이거나 잘못된 출력을 복구하지 않는다.
- PR #23의 일반 변경 구간 입력·의미 분류 실험과 PR #34의 근거 구조·프롬프트 실험은 보존한다. 이번 기준선은 최신 main으로 새로 실행하며 과거 다른 프롬프트의 출력을 기준안인 것처럼 비교하지 않는다.

## 고정 사례와 호출 상한

[입력·필수 판단 기준](../../tests/fixtures/explanation-numeric-cases.json)은 실행 전에 고정한다. 기업 데이터가 아닌 개발자 작성 문장 쌍이다.

| 사례 | 확인 사항 |
|---|---|
| 기존 E-03 | 8→10뿐 아니라 승인 조건 삭제·예정/미확정 소실·정보 유지 기준도 안내 |
| 새 N-01 | 12→9의 원래 인원과 바뀐 인원을 모두 알림 |
| 새 N-02 | 1,000→1000의 표기 차이를 수량 변화로 오해하지 않음 |
| 새 N-03 | 반복 숫자 횟수 감소와 파랑 팀 안내 대상 삭제를 구분 |
| 새 N-04 | 숫자 집합은 같아도 학생/교사의 인원이 바뀜을 확인 |
| 기존 E-01 | 숫자 없는 주세여→주세요 수정에 새로운 의미·정중함 변화 주장 없음 |

- `gemini-3.5-flash-lite`, `gpt-4o-mini` 각각 **6사례 × 2조건 × 1회 = 12요청**, 합계 **최대 24회**. 교정 후보 생성 0회.
- 각 모델에서 같은 사례의 두 조건을 연속 수행하며 사례별 순서를 번갈아 배치한다. Gemini LOW/8,192 출력 토큰, 엘리스 비스트리밍/2,000 출력 토큰 등 현재 설정을 유지한다. 제공자별 다른 기본값을 맞추는 실험은 아니다.
- 서비스·설정·한도·시간초과 오류가 나면 해당 모델 실행을 중단하고 나머지 계획을 미실행으로 남긴다. 자동 재시도·모델 전환·잘 나온 응답을 고르는 재호출은 하지 않는다. 다른 모델은 원래 계획한 독립 비교로 실행한다.
- 긴 숫자·요약 상한·숫자 추가/삭제·부호/단위 경계는 호출 없는 테스트로 확인한다. 실제 모델 사례 수를 늘리지 않는다.

## 판정 및 중단 기준

1. 원래 값과 후보 값 누락, 사실 오류, 필수 조건·미확정·선택 정보 누락을 **서로 구분해** 평가한다. 형식 통과·HTTP 200과 내용 정확성을 구분한다.
2. 숫자 누락이 줄어도 조건 설명이 빠지거나 새 오류·정상 사례 회귀가 생기면 채택 근거로 삼지 않는다. 인용 검사에 막힌 설명도 사용자에게 제공된 성공으로 세지 않는다.
3. 기준안이 이미 통과한 사례는 추가 자료의 개선으로 세지 않는다. 짝이 미실행이면 비교 불가로 남긴다.
4. 모든 대조를 통과하고 숫자 누락 감소가 관찰되면 **확대 검증 후보**로만 남긴다. 각 조건 1회는 재현성·발생 빈도·전체 #22 품질 기준의 근거가 부족하므로 바로 제품에 반영하지 않는다.
5. 실패·개선 없음·미실행이면 이번 안은 채택 보류/미채택으로 기록하고 같은 실험을 반복하지 않는다.

결과는 입력·프롬프트·코드/자료 해시·응답·인용 차단·미실행 목록과 함께 보존한다. 내용 평가는 AI 보조 검토이며 실제 사용자 판단·만족·설명 효과 검증이 아니다. #22의 기존 14사례×두 모델×3회 기준과 미완료 범위를 유지한다.

## 실행

```powershell
# 호출 없이 계획·파생 자료 확인
node --import tsx scripts/evaluate-explanation-numeric.mjs --provider=gemini
node --import tsx scripts/evaluate-explanation-numeric.mjs --provider=elice

# 명시적 실제 호출. 저장된 동일 실험을 재실행하지 않는다.
node --import tsx scripts/evaluate-explanation-numeric.mjs --provider=gemini --live
node --import tsx scripts/evaluate-explanation-numeric.mjs --provider=elice --live
```

기존 로컬 `.env`에서 필요한 제공자 설정만 읽는다. 키·헤더·URL·오류 원문은 기록하지 않는다. 서버 시작·자동 테스트·CI에 실제 평가 호출을 넣지 않는다.
