# 회의 안내 후보 3개와 설명의 수동 제보 검토

2026-11-22 기록. **후보 2에는 `다음주`라는 표기 문제가 남아 있다. 후보 1·3의 `읽어보시고 → 읽어 보시고`는 허용 표기에서 원칙 표기로 바꾼 것이므로 필수 오류 수정과 구분해야 한다.**

## 출처와 보존 범위

사용자가 대화에 전달한 원문 비교·후보 3개·교정 이유를 [고정 자료](../../tests/fixtures/explanation-manual-meeting-2026-11-22.json)에 보존했다. 후보 본문과 교정 이유는 문구를 고치지 않았으며, 원문은 비교 블록에서 취소선 마크업을 제외해 복원했다. 원문에 표시된 네 줄과 공백은 유지했지만 당시 입력의 끝 줄바꿈 유무는 확인되지 않았다. 후보 ID는 기록용으로 부여했다.

**당시 제공자·모델·실행 시각·코드 커밋·프롬프트 버전·API 원응답은 미확인이다.** 현재 환경변수나 main 버전을 과거 실행 정보로 대신하지 않는다. 이번 문서의 검토는 AI 보조 내용 대조이며 새 모델 실행·브라우저 재현·사람의 최종 평가가 아니다. 빈도나 사용자 효과도 측정하지 않았다.

## 후보 품질과 설명 품질의 구분

| 후보 | 실제 후보에서 확인한 점 | 전달된 설명의 판정과 이유 |
|---|---|---|
| 1 | 주로 띄어쓰기 변경. 날짜·시간·댓글 기한·참석 불가 시 공유 내용을 유지한다. `읽어보시고`는 허용 표기에서 원칙 표기로 바뀌었다. | 실제 변경 나열은 대체로 일치한다. 다만 허용 표기 변경까지 ‘올바르게 수정’으로 묶어 오류 수정과 혼동할 수 있어 **보완 필요**다. 모든 항목이 틀렸다고 명시한 것은 아니므로 문법 사실 오류 확정으로 과장하지 않는다. |
| 2 | `다음주`가 그대로 남아 있다. `읽어보시고`는 허용 표기이므로 잔여 오류가 아니다. `분들에게는 → 분께는`, `공유 하겠습니다 → 공유해 드리겠습니다`는 높임 표현도 바뀐다. | 높임 변화와 열거한 표기 수정은 실제와 일치한다. 남은 `다음주` 문제를 알리지 않아 **보완 필요**다. 이 단어를 고쳤다고 주장한 것은 아니므로 없는 수정의 발명과 구분한다. |
| 3 | 표기·높임 변화와 함께 `자료는 → 자료를`, 쉼표 삭제가 있다. 주요 일정과 요청 내용은 유지한다. | 높임 변화 설명은 실제와 일치한다. 후보 1과 같이 허용 표기 변경을 오류 수정처럼 묶을 가능성이 있어 **보완 필요**다. 조사·쉼표를 전부 설명하지 않았다는 이유만으로 실패 처리하지 않는다. |

세 설명 모두 날짜·시간·기한이 바뀌었다는 주장은 하지 않았다. ‘맞춤법’은 띄어쓰기를 포괄할 수 있으므로, 해당 용어를 썼다는 이유만으로 틀린 문법 설명이라고 판정하지 않는다. 원문도 이미 존댓말이므로 후보 2의 ‘예우를 갖추었다’는 표현은 ‘높임 표현을 더했다’로 좁히면 더 명확하지만, 이 문구만으로 원문을 무례하다고 단정했다고 판단하지 않는다.

## 규범 확인 근거

아래 링크는 이번 검토자가 판정 범위를 확인한 근거다. 제품에 외부 검색이나 사전 연동을 추가했다는 뜻이 아니다.

| 확인 대상 | 근거와 적용 | 신뢰도·범위 |
|---|---|---|
| `다음주 / 다음 주` | 국립국어원은 ‘다음’과 ‘주’가 각 단어이므로 띄어 쓰도록 답했다. 따라서 후보 2에는 실제 표기 문제가 남는다. [온라인가나다, 2025-07-02](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&pageIndex=1&qna_seq=317412) | 높음. 해당 표현에 대한 직접 답변이다. |
| `읽어보시고 / 읽어 보시고` | 보조 동사 ‘보다’가 앞말의 `-아/-어` 뒤에서 시험·경험을 나타내면 띄어쓰기가 원칙이고 붙여 쓰기도 허용된다. 이 문장의 ‘읽어 보다’에 그 규칙을 적용한다. [온라인가나다, 2026-04-15](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=27&pageIndex=1&qna_seq=329455) | 높음. 공식 규정을 문맥상 보조 동사인 해당 표현에 적용한 판단이며, 문장 전체에 대한 국립국어원의 직접 감수는 아니다. |
| `알려주시기 / 알려 주시기` | 국립국어원은 둘 다 가능하다고 답했다. 이번 실제 원문은 `알려 주시기바랍니다`이므로, `알려` 뒤의 공백을 새로 넣은 것이 아니라 `주시기`와 `바랍니다`를 나누었다. [온라인가나다, 2024-11-25](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=216&pageIndex=1&qna_seq=306556) | 높음. 해당 활용형에 대한 직접 답변과 입력 문자열 대조다. |
| `공유 하겠습니다 / 공유하겠습니다` | 한국어기초사전에 `공유하다`가 동사로 등재돼 있다. 붙여 쓴 후보 1·3은 이 단어의 활용형이다. 후보 2는 여기에 `드리다`를 사용한 높임 표현까지 추가한다. [국립국어원 한국어기초사전](https://krdict.korean.go.kr/eng/dicSearch/SearchView?ParaWordNo=85036&lang=eng) | 높음. 표제어 확인과 실제 문자열 대조다. |

## 기존 평가 기준과의 연결

[교정 설명 평가 기준](../교정%20설명%20평가%20기준.md)의 E-01·E-04와 아래 항목을 재사용한다. 새 점수 체계나 단일 100점 점수를 만들지 않는다.

| 기존 항목 | 이번 사례에서 확인할 질문 |
|---|---|
| 사실 일치·후보별 대응 | 후보 1·3에서 고친 `다음주`를 후보 2에서도 고쳤다고 혼동하지 않는가? 실제 공백 변경 위치를 설명하는가? |
| 근거 범위 준수 | 허용되는 붙여쓰기를 잘못된 문법이라고 단정하지 않는가? 일부 수정을 전체 정확성 보증으로 확대하지 않는가? |
| 선택에 참고할 정보 | 후보 2에 남은 표기 문제와 실제 높임 변화를 구분해 알리는가? |
| 읽기 편의 | 단순 표기 수정은 짧게 설명하면서 필수 오류 수정과 말투 선택을 구분하는가? |
| 중요한 의미 변화 포착 | 이번 세 후보에는 평가할 주요 일정·조건 변화가 없다. 이 항목의 포착률 분모에 넣거나 의미 변화 검증을 통과했다고 기록하지 않는다. |

후보 생성 오류와 설명 오류는 별도다. 설명이 `다음주`를 지적하더라도 후보 자체가 고쳐진 것은 아니며, 이 사례의 개선만으로 조건·숫자·확정 여부·잔존 단어 관련 기존 실패가 해결됐다고 볼 수 없다. 모든 조사·쉼표를 열거하는 설명도 목표가 아니다.

## 후속 실험과의 경계

고정 후보 설명 시험에서 이 자료를 사용한다면 모델에는 `sourceText`와 `candidates`만 전달한다. 전달받은 기존 설명, `required`, 판정 메모, 공식 근거는 평가 자료이며 정답으로 프롬프트에 주입하지 않는다. 새 출력과 기존 제보는 다른 실행 기록으로 보존한다.

[자유문 계약용 대조 예시 모듈](../../scripts/lib/explanation-freeform-contrast.mjs)은 [PR #34](https://github.com/dhwjdgh1122/writing-demo/pull/34)의 기존 네 가지 합성 예시를 재사용한다. 원본은 [커밋 54c1bd4의 실험 모듈](https://github.com/dhwjdgh1122/writing-demo/blob/54c1bd416f3873622a83a3bc3ab03b0dac1adf8e/scripts/lib/explanation-contrast-experiment.mjs)이다. 현재 제품의 자유문 응답 계약을 유지한 상태에서 같은 대조 원리가 어떤 조건부 효과를 보이는지 확인하려는 것이며, 새로운 원리를 발명했거나 과거 실험이 성공했다고 해석하지 않는다.

이 모듈은 현재 `explanationInstruction`을 수정 없이 기준 지침으로 가져오고, 비교 지침에만 기존 예시 블록을 덧붙인다. 1~2문장·400자 제한과 `candidateId`/`explanation` 응답 형식은 동일하다. 이번 회의 안내의 정답·허용 띄어쓰기 규칙·잔여 오류 전용 지시를 예시에 추가하지 않는다. 예시 추가와 문법 지시 추가를 동시에 바꿔 효과를 구분하지 못하는 일을 피하기 위한 범위다.

**이 문서 작성만으로 실험이 실행되거나 제품 프롬프트가 채택된 것은 아니다.** #22의 기존 실패 기록·완료 기준·미완료 상태와 실제 모델 실행의 결과를 별도로 유지한다.
