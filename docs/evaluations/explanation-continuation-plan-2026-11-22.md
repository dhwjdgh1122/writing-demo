## 목적과 작업 경계

사용자가 전달한 회의 안내문 3후보를 기존 #22의 설명 평가에 연결한다. 실제 변경과 남은 문제를 구분하고, 중요한 의미 변화가 있는 경우 선택에 필요한 정보를 제공하는 것이 목표다. 후보 생성 품질·UI·새 기능 개발은 이번 범위에 포함하지 않는다. main 병합은 보류하며 실험·검증·기록은 작업 브랜치와 Draft PR에 보존한다.

전체 진행은 **1/4 문제 확정 → 2/4 개선안 설계·구현 → 3/4 모델 대조·회귀 검증 → 4/4 기록·Issue 현행화 및 커밋·푸시·Draft PR**로 보고한다. 단계 안에서 새 실험을 하더라도 이 번호를 다시 시작하지 않는다.

- main의 [숫자 자료 입력](numeric-evidence-review-2026-11-20.md), [별도 자기 재검토](explanation-review-result-2026-11-21.md)도 미채택이다. 같은 출력을 성공할 때까지 반복하지 않는다.

- [이번 수동 사례](explanation-manual-meeting-2026-11-22.md)는 실제 사용자 제보를 보존한 자료다. 원래 제공자·모델·버전·발생 빈도는 미확인이며, 새 호출과 별개다. 후보 2의 남은 `다음주` 문제와 허용되는 `읽어보시고` 표기의 설명 문제를 구분한다.

## 첫 실험의 가설과 통제

**가설:** 근거 배열을 생성·조합할 필요가 없는 현재 자유문 계약에서는, 별도 합성 문장의 적절/부적절 설명 예시가 사실·선택 정보 누락을 줄일 수 있는가?

기준안은 실행 기준 main의 `explanationInstruction` 그대로다. 대조안은 그 지시문을 바꾸지 않고 PR #34의 별도 합성 예시를 자유문 설명으로 제시한다. 두 안 모두 후보 ID·400자·1~2문장·인용 검사·모델·토큰/추론 설정을 유지한다. 사례별 정답·required·forbidden·이전 평가 판정은 모델 입력으로 보내지 않는다. 기준안을 먼저 보낸 결과를 대조안에 전달하지 않는다.

고정 개발 사례는 E-01, E-03, E-04, CT-03, R-03과 이번 회의문 M-01이다. **6사례 × 2안 × 2제공자 = 최대24회**다. 이는 새 전체 호출 한도가 아니라 첫 실험의 예상 실행량이다. 사례마다 두 안의 실행 순서를 번갈아 배치한다. 단회 결과로 일반적인 발생률이나 인과 효과를 확정하지 않는다.

- 제공자: 현재 설정된 Gemini `gemini-3.5-flash-lite`, 엘리스 `gpt-4o-mini`.
- 실제 경로: 고정 후보 → 로컬 API → 실제 제공자 → 기존 파서·인용 검사. 후보 생성·브라우저 UI는 실행하지 않는다.
- 보고: 실제 전송 입력, 프롬프트 원문·해시, 코드/fixture 해시, 원응답, 파싱 결과, API 표시·미제공, 응답 시간·토큰 사용량을 분리한다.
- 내용 판정: 사실 오류, 필수 변화 누락, 조건부 선택 정보, 잔존 오류, 허용 표기의 과잉 교정 주장을 별도로 검토한다. 결과 전체 합격 여부와 항목별 부분 개선을 혼동하지 않는다.
- E-04-p2는 원래 fixture의 유지/변경 구분에 더해 **후보에 남은 `결재`가 등록비 납부 문맥에 맞지 않는다는 안내**도 원래 gate의 필수 항목이다. pilot의 report-only `gateAddenda`에 보존하며 모델 입력에는 보내지 않는다. 기존 `notes` 필드명 자체를 현재 자유문 출력에 요구하지 않는다.
- 비교·확대: E-03·R-03의 필수 누락이 유지되면 같은 대조안의 반복·최종 gate로 확대하지 않는다. 개선한 제공자만 독립적으로 후속 대조를 검토할 수 있지만 양 모델 기준을 통과한 것으로 계산하지 않는다. 새로운 사실 오류·정상 대조 퇴행도 채택을 막는다.
- 서비스·쿼터·시간 초과 시 해당 제공자의 남은 호출을 중단한다. 다른 제공자의 독립 실행이나 원출력 분석을 이어가며 자동 재시도·모델 전환을 하지 않는다.

## 호출 권한과 과거 기록

사용자는 이번 재개에서 기존 개발24회·최종84회·총108회 및 3시간 상한을 해제하고, 중단 요청 전까지 근거 있는 개선 작업을 계속하도록 지정했다. 기존 [19회 장부](approved-model-calls-2026-11-21.json)의 당시 한도와 사용 내역은 수정하지 않는다. 새 [후속 장부](approved-model-calls-continuation-2026-11-22.json)는 이전 파일의 해시·건수를 연결하고 이후 호출을 별도로 누적한다. 장부는 이 평가 도구가 기록한 호출이며 수동 브라우저 사용까지 포함한 계정 전체 사용량이 아니다.

각 실험은 입력·가설·판정 기준·호출 계획을 먼저 고정한다. 실제 외부 요청 직전에 장부에 예약하고, 실패·시간 초과·결과 불명 예약도 남긴다. 반복 실험이 필요하면 무엇이 달라졌는지 새 계획으로 기록한다. 호출 제한 해제를 성과 없는 같은 실험의 무한 반복으로 해석하지 않는다.

## 완료 판정과 복구

원래 14사례·15후보 × 두 모델 × 3회 기준을 충족하지 못하면 #22는 미완료다. 미제공·미실행을 성공으로 처리하지 않는다. 임의의 0~100 점수를 설명 품질 달성 근거로 사용하지 않으며, AI 보조 판정과 실제 사람의 판단 도움 검증을 구분한다.

작업 시작 시 main은 원격과 같은 `17a2a20`이며 미커밋 변경이 없었다. 전용 브랜치 `fix/issue22-explanation-quality-continuation`에서 진행하므로 main의 시작 상태는 유지된다. 되돌릴 때는 이번 브랜치의 변경과 외부 Issue 기록을 식별해 처리하며 과거 이력·팀원 작업을 덮어쓰지 않는다. 이미 실행한 모델 호출·비용·원출력 기록은 취소 대상이 아니다.
