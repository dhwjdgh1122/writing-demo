# 설명 지침 보완 전후 비교 — 검토안

관련 작업: [#22](https://github.com/dhwjdgh1122/writing-demo/issues/22). 기준: [교정 설명 평가 기준](../교정%20설명%20평가%20기준.md).

**판정: 날짜·조건 사례의 선택 안내는 보완됐지만, 마지막 평가에서 부정 변화 누락과 인용 차단이 남았다. 전체 개선 완료로 보지 않으며 main 반영 전 검토안으로 둔다.** Codex의 AI 보조 예비 판정이며 사람의 검토·사용자 효과 검증이 아니다.

## 비교 조건과 실행 자료

- 모두 Gemini `gemini-3.5-flash-lite`, 동일한 고정 입력 6사례·7후보, 같은 API·어댑터·인용 검사 경로다. 각 버전·사례당 1회이며 통계적 비교가 아니다.
- 이번 작업의 추가 호출은 A 6회 + B 6회 = **12회**다. A에서 문법 명명이 남고 미수정 단어의 선택 정보가 줄어든 것을 보고 지침을 더 명확히 한 뒤 B를 실행했다. A의 실패·부족한 결과도 보존했다. 기존 기준선 6회까지 합치면 누적 18회다.
- 자동 재시도·모델 변경·교정 후보 생성·기업 데이터 전송 없음. E-06은 계속 제외하고 E-05는 동일 후보 고정 안내로 모델 품질 집계에서 제외한다.
- 제품 변경은 `explanationInstruction`뿐이다. 교정 생성 지침, API 형식, 인용 검사, UI는 변경하지 않았다. 실제 화면을 확인한 결과가 아니라 설명 API 평가다.
- 실행 JSON에 프롬프트 원문·해시, 실행 도구·fixture 해시와 시각을 기록했다. 기준선과 후속 실행의 파일 해시는 Git 체크아웃의 LF/CRLF 차이로 달라졌지만, 파싱한 입력과 줄바꿈을 통일한 실행 도구 내용이 같은지 확인했다. 설명 지침 자체의 변경과 구분한다.

## 보완한 지침

1. 단순 오탈자는 실제 수정만 짧게 설명하고 불필요한 경고·권고를 붙이지 않는다.
2. 중요한 의미 변화에는 그 영향과 원문의 정보·관계를 유지하려는 경우의 조건부 선택 기준을 덧붙인다. 의도가 불명확하면 확인할 정보를 제시한다.
3. 문법 성분을 명명하기보다 보내는 사람·받는 사람·행동 등 전달 내용을 쉽게 설명한다. A에서 문법 용어가 남아 B에서는 문장 성분 명칭을 사용하지 않도록 명시했다.
4. B에서는 명확한 용례상 문제가 수정되지 않고 남은 경우, 그 사실과 추가로 확인할 뜻을 안내하도록 보완했다. 문맥이 불명확하면 오류라고 단정하지 않도록 했다.

## 대표적인 실제 응답 비교

### E-02 날짜의 구체성 감소

**기존:**

> 원문의 '목요일에'가 '이후에'로 바뀌어 안내 시점이 특정 요일에서 불분명한 시점으로 변경되었습니다. 날짜와 시기 조건이 달라졌으므로 의미가 유지되었다고 볼 수 없습니다.

**보완 B:**

> 원문의 '목요일에'가 '이후에'로 바뀌어 안내 시점이 특정한 요일에서 모호한 기간으로 변경되었습니다. 구체적인 요일 정보를 유지해야 한다면 이 후보를 적용하지 말아야 합니다.

차이를 알리는 설명에서 원문의 요일을 유지하려는 경우의 선택 안내까지 포함하는 출력으로 바뀌었다. 단 1회씩의 관찰이며 효과를 확정하지 않는다.

### E-03 조건·인원·확정 여부

**기존:**

> 원문의 '담당자의 확인을 받은 경우에만'이라는 조건과 '발송은 확정되지 않았습니다'라는 유보적 표현이 삭제되고, '10명에게 자료를 발송합니다'와 같이 확정적인 내용으로 변경되었습니다. 또한 인원수가 8명에서 10명으로 달라졌습니다.

**보완 B:**

> 원문의 '담당자의 확인을 받은 경우에만'이라는 조건과 '발송은 확정되지 않았습니다'라는 유보적 표현이 사라지고, '화요일까지 10명에게 자료를 발송합니다'와 같이 대상 인원이 8명에서 10명으로 늘어나며 확정된 일정으로 바뀌었습니다. 원문과 조건 및 확정 여부가 완전히 달라지므로, 발송 여부가 아직 불확실하고 조건부일 때는 이 후보를 적용하지 말아야 합니다.

세 변화가 유지되면서 선택 기준이 추가됐다. 표현이 강하고 길어졌으므로 읽기 부담과 안내 강도의 적절성은 사용자 의견을 확인할 부분이다.

### E-07 주체·수신 대상·부정 변화

**기존:**

> 원문의 주어와 목적어가 '신청자는'과 '운영진에게'에서 '운영진은'과 '신청자에게'로 서로 바뀌었으며, 서술어도 부정 표현인 '보내지 않습니다'에서 긍정 표현인 '보냅니다'로 변경되어 주체와 행위의 방향이 완전히 역전되었습니다.

**보완 B:**

> 원문의 "신청자는 운영진에게 자료를 보내지 않습니다."에서 자료를 보내는 주체와 받는 대상이 서로 바뀝니다. 행동의 주체가 완전히 달라지므로 원문의 전달 내용을 유지하려면 이 후보를 적용하지 않아야 합니다.

부정확한 ‘목적어’ 명명은 없어지고 선택 기준이 추가됐지만, 보내지 않는다는 내용이 보낸다는 내용으로 바뀌었다는 설명이 빠졌다. **원문을 인용한 것만으로 부정 변화의 영향을 설명했다고 점수화하지 않는다.** A에서는 부정 변화를 설명했으나 ‘목적어’ 용어가 다시 나왔다. 두 출력 모두 개선점과 미충족 항목이 있다.

## 검증과 다음 판단

- 각 프롬프트 수정 후 타입 검사·단위/API 테스트 42개 통과. 같은 입력·실행 도구를 사용했고 원문·후보별 ID와 응답을 보존했다. 제품 화면·선택 동작은 바꾸지 않아 로컬 브라우저 테스트를 반복하지 않았다.
- 이번에는 실제 평가에서 새로 드러난 차이를 숨기지 않고 A·B를 모두 보존했다. 추가로 좋은 출력이 나올 때까지 재시도하지 않는다.
- 현재 B는 중요한 의미 변화 포착 기준을 모두 만족하지 못한다. PR은 초안으로 두고, 선택 안내의 유용성·문장 강도에 대한 사용자 의견과 핵심 변화 누락에 대한 후속 보완을 확인한 뒤 병합 여부를 정한다.
- 인용·대안 표현 구분과 후보별 차단 범위는 별도 작업이다. 이번 프롬프트 수정으로 해결됐다고 판단하지 않는다.
- 평가에 사용한 고정 사례로 지침을 보완했으므로 이 결과는 독립적인 일반화 시험이 아니다. 채택 전에는 새로운 사례와 반복 실행에서도 의미 변화 누락·불필요한 경고를 확인할 필요가 있다. 비용·횟수와 범위는 다음 평가에서 정한다.
