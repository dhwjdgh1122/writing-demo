2026-11-17 KST / #22 / Codex AI 보조 진단. 설명 개선 완료나 사용자 효과 평가가 아니다.

## 확인한 원인

엘리스의 E-03 재실행에서 **surfaceChanges[0].kind에 action이 들어가 거부된 것**을 확인했다. action은 의미 변화 배열에서만 허용되는 종류다. 실제 값 전체를 수집하지 않고 코드에 정의된 종류 목록과 일치할 때만 식별했다. 이는 이번 응답의 직접 관찰이며 M·N의 저장되지 않은 응답도 같은 값을 가졌다고 단정하지 않는다.

## 진단 기능

- 스키마 거부 시 필드 경로·오류 코드·허용 목록의 추가 필드명을 최대 20항목 기록한다. 경로는 6단계, 추가 필드는 12개까지이며 그 밖의 필드명은 `[unknown]`으로 가린다.
- 후속 진단은 단순/의미 변화 배열의 kind 오류에서 기존 수정 종류 상수와 일치하는 경우만 `recognizedKind`를 기록한다. 임의 문자열·원문·후보·응답값·Zod 오류 메시지는 저장하지 않는다.
- 수동 평가 JSON의 `schemaDiagnostics`에만 보존한다. 공개 API 오류 응답, 설명 생성 지침, 인용 검사, 실패 차단, 최대 3모델 호출·45초 제한은 유지한다. 값이 잘못된 배열에 있다고 자동 이동하거나 승인하지 않는다.
- 진단은 오류가 없으면 null이다. 제공자 응답 해석 단계나 인용·내용 형식 검사의 오류에는 이 스키마 진단이 없을 수 있다. 의미 오류 탐지 기능이 아니다.

- 타입·단위/API **76개**·빌드 통과. 이전 72개에 진단의 값·알 수 없는 키 비노출, 항목 상한, 허용된 종류 식별, 공개 API 비노출 검사 4개를 추가했다. 진단 추가로 기존 응답 차단이 완화되지 않는지도 확인했다.

- 설명의 의미 정확성·사람의 내용 검토·사용자 선택 효과는 해결되지 않았다. #22와 PR #23은 미완료·Draft이며 main에 병합하지 않는다. [이전 M·N 평가](단순%20수정과%20의미%20변화%20출력%20분리%20평가.md)를 보존한다.
