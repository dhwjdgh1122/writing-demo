# 공백 변경 사실 안내의 독립 재사용 계획

2026-11-22 / #22·Draft PR #55. 첫 [대조 예시 재평가](explanation-freeform-contrast-result-2026-11-22.md) 미채택 후, PR #34 `d2d8c42`의 검증된 순수 함수를 현재 main 계약에 좁게 재사용한다. 새로운 모델 개선 원리를 발견한 것으로 기록하지 않는다.

실행 결과와 저장 출력 재처리는 [결과 문서](explanation-spacing-reuse-result-2026-11-22.md)에 별도로 보존한다.

## 해결하려는 문제와 적용 조건

M-01 후보 1은 일반 공백(U+0020) 5개 추가·4개 삭제만 있다. 그런데 기준안과 대조안 모두 원문에 없는 표현을 만들어 설명했다. 이 유형은 모델이 적절성을 추측할 필요 없이 변경 사실을 코드로 계산할 수 있다.

- 원문과 후보가 다르지만 U+0020을 제거한 글자열이 완전히 같을 때만 적용한다. 위치별 공백 추가·삭제 개수를 계산한다.
- 일반 공백 외의 글자·숫자·문장부호·탭·줄바꿈·NBSP·Unicode 조합 변경은 이 안내로 대체하지 않는다. 유지된 줄바꿈·이모지는 그대로 비교한다.
- 공백만 바뀌어도 `아버지가 방`과 `아버지 가방`, `1 5명`과 `15명`은 해석이 달라질 수 있다. 따라서 의미 유지·맞춤법 개선·사용자 의도 충족을 주장하지 않는다.
- M-01 후보 2·3은 범위 밖이다. 원래 설명 생성·후보별 인용 검사와 실패 재요청을 유지한다.

## 최소 구현 범위

현재 제공자의 모델 응답과 전체 JSON·후보 ID 검증을 거친 뒤 해당 후보만 계산 안내로 바꾼다. PR #34의 근거 배열 응답 구조·숫자 비교 화면은 가져오지 않는다. 원문과 완전히 동일한 후보의 고정 안내도 보존한다.

모델 요청 후 처리이므로 요청당 실제 제공자 호출은 1회 그대로이며 추가 호출은 없다. 모델 호출 생략·503 복구·문법 판정 기능으로 표현하지 않는다. 서비스 오류·시간 초과·읽을 수 없는 전체 JSON·잘못된 후보 ID를 성공으로 바꾸지 않는다. 생성 주체가 섞이는 안내 한 줄만 중립적으로 정리하고 화면 배치·버튼·교정 후보는 바꾸지 않는다.

## 검증과 평가 구분

1. 과거 함수의 경계 사례와 의미가 달라질 수 있는 공백 사례를 재사용한다.
2. 두 제공자 어댑터의 응답을 주입해 혼합 후보에서 계산 안내·정상 모델 설명·실패가 서로 섞이지 않고 호출 1회를 유지하는지 확인한다.
3. 실패 후보만 재요청, 전체 응답 형식/ID 실패·503 유지와 기존 단위/API 회귀를 확인한다.
4. 첫 실험의 M-01 실제 원출력을 새 파서에 다시 넣어 후보 1의 안내 변화를 확인한다. 이는 **저장된 출력 재처리**이며 새 모델 호출·모델 품질 향상·사용자 효과 검증이 아니다. 원래 원자료는 수정하지 않는다.

계산 안내는 코드 동작 평가로 따로 집계한다. 해당 후보의 모델 원출력 실패를 성공으로 다시 분류하지 않는다. #22의 조건·어휘·선택 기준을 포함한 원래 14사례 반복 기준과 미완료 상태는 유지한다. main 병합은 하지 않는다.
