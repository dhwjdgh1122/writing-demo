# 문장별 독립 입력의 조건 추출 진단 결과

2026-11-22 / #22·Draft PR #55, 실행 기준 `118ab3e`. [계획](explanation-isolated-conditions-plan-2026-11-22.md)의18회를 모두 실행했다. **독립 입력이 함께 입력보다 조건 누락을 줄인 근거가 없고, 인용 재작성·범주 혼동이 남아 제품 미채택**이다. 설명 출력까지 확대하거나 같은 배치를 반복하지 않는다.

## 실행과 구조 검사

| 제공자 | 호출·서비스 응답 | 구조·정확 인용 통과 | 원자료 |

| Gemini | 9·9 | 9/9요청 | [보고서](explanation-isolated-conditions-2026-11-22-gemini.json) |

서비스 실패·미실행은 없다. 모델에 전달한 데이터는 역할을 명시하지 않은 ID와 해당 문장뿐이다. joint는 한 요청에 두 문장, isolated는 요청마다 한 문장으로 상대 문장·기존 출력·평가 정답을 숨겼다. 지침·추출 스키마·제공자 설정은 동일했다. 구조 검사는 제품 API의 설명 통과나 의미 정확성 판정이 아니다.

## 실제 관찰

- **E-03 / 엘리스 함께 입력:** 담당자 확인 조건과 예정·미확정이 포함된 행동 구절을 찾았지만 `t1`을 중복 출력해 3항목이 됐다. 구조 검사 실패를 통과로 계산하지 않는다.
- **E-03 / 엘리스 독립 원문:** 조건은 찾았지만 행동을 원문에 없는 `보낼 예정이다.`로 재작성했다. 정확 인용 실패다. 별도 미확정 표현도 그 구절에 담기지 않았다.
- **E-03 / Gemini 원문:** 두 방식 모두 담당자 확인 조건과 `화요일까지 8명에게 자료를 보낼 예정이며`를 추출했다. 조건에 연결된 예정 표현은 유지됐다. 뒤의 별도 발송 미확정 문장은 추출하지 않았으므로 이 자료만으로 전체 의미 정보가 확보됐다고 볼 수 없다. 이번 조건 추출과 전체 설명 기준을 구분한다.
- **E-03 / 두 모델의 독립 후보:** `화요일까지`를 condition으로 넣었다. 실제 문장에 있는 기한이므로 없는 표현을 만든 것은 아니다. 다만 이번에 찾으려던 승인·자격 전제와 기한이 같은 배열에 섞였다. 함께 입력에서는 두 모델 모두 해당 후보의 conditions를 빈 배열로 반환했다. **조건 존재 수만 비교하면 담당자 확인 제한의 소실을 놓칠 수 있다는 한계**다.
- **CT-02:** 두 모델·두 방식 모두 `허가가 없으면`과 `출입할 수 없습니다.`를 연결했고, 조건이 없는 후보는 빈 배열이었다. 부정을 출입 허용으로 바꾸지 않았다. 독립 입력의 추가 이득은 없다.
- **CT-03:** 두 모델·두 방식 모두 `회원인 경우에만`/`회원만`과 `자료를 받을 수 있습니다.`를 추출했다. 조사 `만`까지 유지했다. 이 단회 추출은 바람직하지만 그 자체가 모든 표현의 의미 동치를 코드로 확인한다는 증거는 아니다.

## 결정과 남은 범위
