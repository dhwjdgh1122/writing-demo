# 의미 동등성의 방향 일관성 진단

2026-11-17 KST / #22 / 기준 코드 `7515bf9`. **문장 순서만 바꿔도 엘리스의 의미 판단이 달라지는 사례를 확인했다.** 제품 설명 기능에는 적용하지 않으며, 방향 불일치·실패·미실행을 드러내는 오프라인 집계 도구와 회귀 테스트를 추가했다.

## 범위와 방법

앞선 [조건 근거 추출 진단](조건%20근거%20추출과%20고정%20문구%20조합%20진단.md)의 후속이다. 조건·행동 추출과 설명 조합을 모두 빼고 두 문장이 명시적으로 전달하는 정보가 같은지 하나만 판단하게 했다. 출력은 `verdict`와 짧은 `reason`이다. 이 지침·입력·출력은 제품과 다르므로 제품 품질 개선이나 원인 하나의 증명으로 보지 않는다.

[fixture](../../tests/fixtures/explanation-equivalence-cases.json)는 다음 6개다. 정답·필수 요소는 실제 모델 입력에 포함하지 않았다.

| 사례 | 비교 | 사전 판정 |
|---|---|---|
| EQ-01·02 | 회원인 경우에만 ↔ 회원만, 나머지 문장 동일 | 양방향 모두 equivalent |
| EQ-03·04 | 승인을 받은 경우에만 ↔ 승인을 받으면, 나머지 문장 동일 | 명시적 한정 표현 차이로 양방향 different |
| EQ-05 | 완전히 같은 환불 문장 | equivalent |
| EQ-06 | 자료를 공개하지 않습니다 → 공개합니다 | different |

처음 두 쌍은 기존 실패 문장과 역방향을 사용했다. 같은 문장과 부정 차이는 대조 사례다. 서로 독립인 일반 사용자 문장 6개를 표집한 것이 아니며, 알려진 문제를 좁히는 진단이다. EQ-03·04는 명시적인 `만` 제한의 유무를 보는 기준으로, 실제 무승인 공개 허용 여부를 판정하지 않는다.

## 실제 결과

| 제공자·설정 모델 | 모델 호출 | 사전 verdict 일치 | 역방향 쌍 일관성 | 기록 |
|---|---:|---:|---:|---|
| Gemini `gemini-3.5-flash-lite` | 6 | 6/6 | 2/2 | [응답](equivalence-gemini-2026-11-17.json) |
| 엘리스 `gpt-4o-mini` | 6 | 5/6 | 1/2 | [응답](equivalence-elice-2026-11-17.json) |

총 12모델 호출. 서비스 오류·미실행·자동 재시도는 없었다. 각 경우 한 번만 호출했으므로 모델의 일반 정확도나 안정성을 뜻하지 않는다. `reason`의 품질은 이 표에 포함하지 않는다.

- 엘리스는 EQ-03에서 조건 제한의 차이를 인정했지만 EQ-04에서는 같은 두 문장을 반대 순서로 받고 `equivalent`로 판단했다. 추출과 설명을 빼도 이번 진단에서 의미 판단의 일관성 문제가 남았다.
- 두 모델 모두 회원 조건의 표현 수정과 동일 문장·부정 대조의 verdict는 일치했다. 앞선 진단보다 과제가 달라졌으므로 이를 제품 개선 결과로 표시하지 않는다.
- Gemini의 verdict가 모두 일치해도 이유 전체가 합격인 것은 아니다. 회원 자격을 자료 수령의 `유일한 조건`이라고 설명한 표현은 원문에 명시되지 않은 다른 요건까지 없다고 읽힐 수 있어 검토가 필요하다. 회원 제한을 유지한다는 판단과 추가 요건이 전혀 없다는 주장은 구분한다.
- 제품용 어댑터는 캡처한 진단 JSON을 교정 후보 형식으로 해석할 수 없어 예상대로 `invalid`를 반환했다. 어댑터 생성 함수를 재사용하되 전송 전에 지침·입력·출력 형식을 바꾼 진단이다. 교정 후보를 실제로 생성했거나 앱 HTTP·화면에서 설명이 성공했다는 의미가 아니다. 동일 문장의 진단 호출도 제품의 동일 후보 무호출 정책을 변경하지 않는다.

## 추가한 도구와 확인

- [진단 실행기](../../scripts/diagnose-explanation-equivalence.mjs): 기본은 dry run. `--live`가 있을 때만 설정된 제공자로 최대 6회 호출한다. 한 사례의 서비스·인증·사용량·전송 오류 발생 시 후속 호출을 중단한다. 키·인증 헤더·원시 응답 봉투는 저장하지 않는다.
- [오프라인 집계기](../../scripts/summarize-explanation-equivalence.mjs): 보고서의 입력과 저장소 fixture가 일치하는지 확인한 뒤 verdict 일치/불일치/판정 불확실/미제공/미실행을 전체 사례 기준으로 집계한다. 역방향 두 판정의 불일치를 별도로 드러낸다. **두 방향 모두 같은 오답인 경우에도 일관성만으로 정답 처리하지 않는다.**
- [회귀 테스트 4개](../../tests/equivalence-report.test.mjs): 예상된 어댑터 오류와 서비스 실패 구분, 방향 불일치와 양쪽 오답, 미실행·불확실·차단의 누락 방지, 기준·입력 변조 및 중복 기록 거부를 확인한다. 자동 검사에 포함되지만 실제 모델을 호출하지 않는다.
- 로컬 타입 검사·전체 자동 테스트 **84개** 통과. 기존 80개에 집계기 테스트 4개를 추가한 수치다. 서비스·프롬프트·화면이 바뀌지 않아 로컬 브라우저 반복 검사는 생략했다. 직전 `7515bf9`의 [CI](https://github.com/dhwjdgh1122/writing-demo/actions/runs/44045298828)는 성공했으며 이번 커밋 CI와 구분한다.

```powershell
# 입력 확인 — 외부 호출 없음
node --import tsx scripts/diagnose-explanation-equivalence.mjs
# 제공자·사용량을 확인하고 승인된 실제 호출을 할 때만 --live 사용
$env:LLM_PROVIDER='gemini' # 또는 elice
node --import tsx scripts/diagnose-explanation-equivalence.mjs --live
# 저장한 기록 집계 — 외부 호출 없음
node scripts/summarize-explanation-equivalence.mjs docs/evaluations/equivalence-elice-2026-11-17.json
```

실행기와 fixture는 LF로 보존하며 보고서에 실행기·fixture·지침 SHA-256, 코드 기준 버전·실제 입력을 남겼다. `worktreeEvaluation`은 당시 아직 커밋하지 않은 새 실행기·fixture를 사용했다는 뜻이다. 실행기의 dry run·문법과 중복 `--live` 거부를 확인했다. 집계기는 이유의 진실성이나 설명 품질을 자동 채점하지 않으며 병합 승인 도구가 아니다.
