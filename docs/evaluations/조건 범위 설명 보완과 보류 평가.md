## 사례별 판단

| 사례 | 확인한 내용과 남은 문제 |
|---|---|
| CT-02: 허가 조건 삭제 | 기존에는 허가 제한이 명시되지 않는다는 설명에 그쳤다. 보완 Gemini는 조건 없는 출입 불가로 읽힌다고 설명했다. 엘리스 최종 실행은 영향 설명을 만들었지만 삭제 구절을 남은 단어 오류에도 넣어 인용 검사에서 차단됐다. |
| CS-01: 서류 누락 조건 삭제 | 보완 Gemini는 서류 누락 여부와 관계없는 접수 불가를 설명했다. 최종 실행에는 원문의 조건을 ‘누락 시에만’으로 좁히는 표현이 남아 엄격한 내용 기준은 미충족이다. 엘리스는 중복 또는 잘못된 notes로 차단됐다. |
| CS-02: 환불 불가 조건 추가 | 첫 보완 Gemini는 원문에 없는 배타적 ‘경우에만’을 사용했다. 최종 Gemini는 환불 불가를 말하는 범위가 특정됨을 설명했지만, 엘리스는 미사용 시 환불 가능으로 추론하는 문제가 남았다. |

| E-07: 역할·부정 변화 | Gemini에서 두 변화를 확인했다. 엘리스는 단순 수정 중복·역할 누락 등이 남아 차단됐다. |

## 판단과 다음 개선 범위

조건 영향 설명 일부가 나아졌지만, 정상적인 표현 수정의 오분류와 원문에 없는 배타성·반대 상황 추론이 남았다. 따라서 이번 지침 추가를 품질 개선 완료로 채택하지 않았다. 기존 프롬프트도 이 문제를 해결한 상태는 아니다.

다음 검증은 **글자 삭제와 의미 삭제를 구분하는 조건 분류**에 집중한다. CT-03처럼 같은 조건을 유지하는 대조 사례와 실제 조건 삭제·추가·교체를 함께 평가해야 한다. 실패를 통과시키기 위해 인용·중복 검사를 완화하거나, 특정 문장만 코드로 바르게 보이게 처리하지 않는다. 남은 단어 오용 검사는 별도 미해결 항목이다.

타입 검사·단위/API 80개 통과. 검사 실행은 첫 실험 지침 상태에서 했고, 이후 변경은 프롬프트 문자열뿐이며 최종 서비스 코드는 검증된 기준 커밋으로 복원했다. 화면 변경이 없어 로컬 브라우저 검사는 반복하지 않았다. 이 자동 검사는 실제 설명의 의미 정확성을 보증하지 않는다. main 미병합·PR Draft 유지.
