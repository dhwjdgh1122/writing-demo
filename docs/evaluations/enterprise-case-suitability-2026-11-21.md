# 기업 문장 24쌍의 평가 적합성 검토

**2026-11-21 / [#46](https://github.com/dhwjdgh1122/writing-demo/issues/46), 기업 데이터 탐색 후속.** 기존 [#38](https://github.com/dhwjdgh1122/writing-demo/issues/38)의 24쌍을 실제 CSV와 다시 대조하고 평가에 사용할 범위·필수 정보·보류 이유를 정리했다. **단회 AI 보조 판단**이며, 사람이 승인한 평가 정답·실제 설명 품질·사용자 효과 검증은 아니다. 이번 검토의 서비스 모델 호출은 **0회**다.

## 1. 결과와 적용 범위

| 구분 | 사례 | 이번 결정 |
|---|---|---|
| 설명 평가 준비 적합 6개 | P02·P04·P15·P18·P22·P23 | 실제 변화와 선택 질문을 적을 수 있는 후보. 외부 전송·실제 평가 수행을 뜻하지 않음 |
| 고정 안내 준비 적합 1개 | P09 | 원문과 선택문이 동일한 경우의 안내 확인. 모델 내용 품질 분모와 구분 |
| 문맥·대응 범위 보류 12개 | P01·P03·P05·P06·P07·P08·P10·P12·P17·P20·P21·P24 | 국소 변화는 보존하되 전체 의미·누락 여부의 주평가는 보류 |
| 한국어 교정 범위 제외 5개 | P11·P13·P14·P16·P19 | 번역·다국어 문서 변환이므로 현재 주평가에 포함하지 않음 |

준비 적합은 총 **7개(설명 평가 후보 6개 + 고정 안내 1개)**다. 원래 24개를 교체하거나 보류·제외 사례를 삭제하지 않았다. P번호는 기존 검토 번호를 그대로 사용하며 사용자 ID가 아니다.

P08은 문장 끝에 마침표가 있지만 원문 앞부분이 기간을 수식하는 내용 없이 시작한다. 앞부분이 빠진 발췌일 가능성을 배제할 수 없어 이번 평가 준비에서는 보류했다. 길이와 끝 문장부호만으로 완결성을 판단하지 않는 사례다.

선정 대응이 일치한다는 사실은 설명의 정확성이나 사람의 판단 도움이 입증됐다는 뜻이 아니다. 이번 산출물은 **평가 범위와 필수 판정 요소**이며, 외부 실행 전 데이터 사용 범위와 사람의 기준 확인이 남아 있다.

## 2. 근거와 재계산 확인

공동 근거는 [기존 선정 방법·24개 추상 요약](../research/evidence/enterprise-pair-review-2026-11-20.json)과 [11/20 탐색 기록](../research/기업%20데이터%20탐색.md#enterprise-pair-review)이다. 접근이 허용된 원본 CSV와 기존 비공개 선정본은 로컬에서만 읽었다. 저장소에는 원문·선택문 전문, 개인 이름, 원본 행 번호, 개별 순위 해시를 추가하지 않는다. 공동 문서를 이해하는 데 개인 폴더가 필요하지 않으며, 원문 재계산에는 같은 데이터에 대한 접근 권한이 필요하다.

기존 CSV 파서로 원본을 읽고 공동 근거의 제외 조건·출처별 할당량·해시 정렬을 쓰기 없는 일회성 Node 명령에서 재계산했다. 과거 산출물을 덮어쓰는 기존 실행기는 재실행하지 않았다. 첫 명령은 PowerShell 표준입력의 한글 인코딩 때문에 구문 단계에서 실패했고, 정규식의 한글 부분을 UTF-8 근거 파일에서 읽도록 바꿔 성공했다. 실패·성공 명령 모두 원본 쓰기와 외부 모델 호출은 없었다.

| 확인 항목 | 결과 |
|---|---|
| 원본 CSV SHA-256 | `faa9e00b3494dec6d7a838699cbd43fbde98c5f50485113c216c6af545f54caf` — 기존 근거와 일치 |
| 기존 공동 근거 SHA-256 | `817959f9a7bfd07b2136515e42b8744559fdc6e34d4530e495df8fe00d8d6d11` |
| 전체 CSV 행 / 고유 출처·문장쌍 / 선정 풀 | 75,881 / 25,211 / 24,947 — 기존 집계와 일치 |
| 제외 | 빈 값 18, 길이 경계 241, 연락처 형태 5 — 순차 제외 집계 일치 |
| 재선정 대응 | 24개 원문·선택문·출처·분류·순위·기존 레코드 대응 모두 일치 |
| 공동 근거의 P번호 대응 | 24개 모두 일치 |
| 요청 의도 필드 | 24개 모두 `user_prompt` 빈 값. 실제 요구가 없었다는 뜻으로 확정하지 않음 |
| 원본 보존 | CSV와 기존 비공개 선정본의 해시 불변 확인 |

선정 규칙 재현은 기계적으로 확인했지만, 아래 적합성과 설명 기준은 AI가 문장을 직접 읽고 정리한 판단이다. 자동으로 의미 정답을 계산한 결과가 아니다.

## 3. 24개는 전체 모집단이 아니다

원본의 고유 출처·문장쌍 25,211개에서 제외 조건을 적용한 24,947개가 선정 풀이다. 각 출처 3종에서 동일 1개·공백/기호 중심 1개·숫자 단서 차이 2개·조건 단서 차이 2개·기타 2개를 정해 총 24개를 고정 해시 순서로 골랐다.

그룹 이름은 문자열 탐색 규칙이다. 숫자 문자열이 달랐다고 수량이 바뀐 것도, 조건 관련 단어가 달랐다고 조건이 삭제된 것도 아니다. 이 24개로 의미 변화 빈도·사용자 어려움의 비율·설명의 필요성을 추정하지 않는다. 7개를 주평가 준비 대상으로 좁힌 것도 **완결성·제품 범위·판정 가능성 기준**이며, 나머지를 실패 자료에서 제거하는 처리가 아니다.

## 4. 적합성 판정 기준

| 판정 | 적용 기준 | 허용되는 후속 범위 |
|---|---|---|
| 준비 적합 | 한국어 교정 범위에 맞고, 제공된 작업 단위가 해석 가능하며, 실제 차이와 조건부 선택 질문을 구분해 적을 수 있음 | 사용 범위 확인 뒤 고정 문장쌍 설명 평가 후보로 검토 |
| 준비 적합·고정 안내 | 원문·선택문이 동일하고 제공 단위의 대응을 확인함 | 변경 없음 안내·불필요한 모델 호출 방지 검증. 모델 품질 분모와 구분 |
| 범위 보류 | 미완결 발췌·선행 문맥 부족·출력 대응 불명확으로 전체 의미를 판단하기 어려움 | 국소 변화만 기술하거나 별도 합성 예문을 만들 근거로 사용. 전체 의미 보존·누락 판단 금지 |
| 범위 제외 | 번역·다국어 문서 변환 등 현재 한국어 교정 주평가와 다름 | 범위 차이를 보존. 번역 전용 평가를 새로 확정하기 전 주평가에 넣지 않음 |

명사형 메모·날짜 라벨은 마침표나 서술어가 없다는 이유만으로 미완결이라고 판정하지 않는다. 반대로 문장 끝 마침표가 있다고 앞부분까지 온전하다고 가정하지 않는다. 내용의 실제 사실 여부와 선택 이유는 모든 사례에서 별도 미확인이다.

| P18 | 준비 적합 | 보충 설명의 줄표를 괄호로 바꾸고 공백·조사 연결을 정리. 목록과 필요하다는 서술 유지 | 기호·공백 변화만 짧게 설명. 문서 스타일에 따른 선택 | 별도 사실·의미 향상 또는 하나의 기호가 항상 우월하다는 주장 금지 |

| P20 | 범위 보류 | 앞부분 금액은 값이 같은 다른 표기. 결과 서술은 더 구체적으로 바뀜. 후반 금액·문장은 끊김 | 앞부분 동일 값과 표현 구체화를 분리. 더 구체적 결과를 말할 사실 근거가 필요한지 안내 | 뒤쪽 숫자·총액·전체 의미 보존 판단 불가. 법적 결과와 실제 사실성 검증 아님 |
| P21 | 범위 보류 | 시간대·상태 고려 취지는 남고 연결어 변경. 직접적 주의 표현은 빠졌으나 현실적 목표 표현 유지 | 남은 조건과 약해진 명시적 주의를 구분 | 끝부분 미완결. 주의·조건이 모두 사라졌다거나 건강상 더 안전해졌다고 단정하지 않음 |
| P22 | 준비 적합 | 이용 불가라는 직접 상태가 덜 구체적 상태로 바뀜. 현재 시점과 불편 가능성도 추가 | 상태 구체성 변화·추가된 정보·격식 변화를 구분. 실제 상태를 정확히 알릴지 완곡하게 안내할지 확인 기준 제시 | 일부 이용 가능이라고 단정하지 않음. 실제 장애·의도 미확인이므로 후보가 사실에 틀리다거나 사용자가 오판했다고 결론 내리지 않음 |
| P23 | 준비 적합 | 명사형 안내 메모가 독자 대상 행동·목표 권유로 바뀜. 대체 대상·기준 주제 유지 | 메모에서 안내로 발화 형식이 바뀐 점과 사용 위치·독자에 따른 선택 기준 제시 | 명사형을 자동으로 잘못된 문법·잘린 문장으로 취급하지 않음. 새 건강 효과·기준의 타당성 주장 금지 |
| P24 | 범위 보류 | 보충 발언 생략·연결·시제 표현 변경. 양쪽 끝부분 미완결 | 확인되는 보충 발언·연결·시제 차이만 분리 | 전체 주장·보이지 않는 후반부를 추정하거나 정보 추가의 정당성을 확정하지 않음 |

## 6. 주평가 준비 대상의 최소 판정표

아래는 정확히 같은 문구를 출력해야 한다는 정답 문장이 아니다. 동일한 내용을 다른 표현으로 전달해도 평가할 수 있도록 **필수 정보·해서는 안 되는 주장**을 고정한다.

| 사례 | 최소 통과에 필요한 정보 | 선택 정보 수준 | 사실 오류로 볼 예 |
|---|---|---|---|
| P02 | 문장 끝 마침표 추가 | 실제 표기 수정의 짧은 설명이면 충분 | 정중함·요청 내용이 바뀌었다는 주장 |
| P04 | 월 앞자리 영 제거, 날짜 값 유지 | 문서 날짜 표기의 차이라고 구분 | 날짜·일정이 바뀌었다는 주장 |
| P09 | 변경 없음 고정 안내 | 추가 선택 권고를 강제하지 않음 | 없는 수정·품질 향상 주장 |
| P15 | 열거·동사·개별 제시 강조의 실제 변화, 기본 과제 유지 | 개별 제시 강조가 원하는 출력 방식에 맞는지 확인 | 원래 없던 과제 전체를 새로 만들었다는 설명 |
| P18 | 줄표→괄호 및 공백·연결 정리, 목록 내용 유지 | 표기 스타일에 따른 선택으로 제한 | 사실·주제가 바뀌었다는 주장 |
| P22 | 기능 상태의 덜 구체적인 표현, 현재 시점·불편 가능성 추가를 구분 | 실제 상태를 분명히 알려야 하는지에 따른 조건부 선택 기준 | 후보가 일부 이용 가능을 확정한다는 주장, 실제 기능 상태를 안다고 단정 |
| P23 | 내부 메모·항목형에서 독자 대상 행동 안내로 전환, 주제 유지 | 메모·항목명인지 실제 안내 문구인지에 따른 선택 기준 | 단순 맞춤법만 고쳤다는 설명, 확인되지 않은 건강상 효과 주장 |

모든 사례에서 인용은 실제 제공 문자열에 근거해야 한다. 중요한 의미 변화에 필수 정보나 선택 기준이 빠지면 보완 필요, 사실 오류·없는 근거가 있으면 실패다. 짧고 읽기 좋다는 장점으로 사실 오류를 상쇄하지 않는다.

P09는 모델 품질 평가 분모에서 제외하고 고정 처리 동작을 따로 기록한다. P02·P04·P18처럼 단순 변경인 사례에 긴 선택 기준을 억지로 요구하지 않는다. 설명을 오래·많이 쓰는 것이 높은 품질이라는 기준을 만들지 않는다.

## 8. 남은 확인 사항

이번 준비에서 24개 대응 확인, 적합·보류·제외 이유 보존, 준비 대상의 필수 변화·금지 추론·선택 질문 정리를 마쳤다. **기업 원문을 외부 모델에 전송하거나 모델 설명을 평가한 것은 아니다.**

다음 실행 전에는 데이터 사용·외부 전송 범위와 평가 기준을 확인해야 한다. 공개 가능한 합성 예문을 만든다면 별도 ID와 작성 사례임을 표시하고, 기업 문장을 잘라 보충한 것을 실제 기업 원문쌍으로 소개하지 않는다. 합성 예문 결과를 실제 기업 문장이나 전체 사용자에 대한 효과로 일반화하지 않는다.

기존 #22 반복 평가와 기업 후속 평가는 서로 다른 표본이다. 내용 통과율을 계산할 때도 사전 고정 분모와 제공 실패·차단·미실행·보류를 드러내며, 사실 오류를 다른 항목의 장점으로 상쇄하지 않는다. 실제 사람의 판단 도움은 설명 정확성과 별도로 검증해야 한다. 채택된 문장이라는 사실만으로 정답·만족·의도 충족을 단정하지 않는다.
