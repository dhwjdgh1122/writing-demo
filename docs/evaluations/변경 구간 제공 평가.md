# 변경 구간 제공 평가 — F

관련 작업: [#22](https://github.com/dhwjdgh1122/writing-demo/issues/22), [초안 PR #23](https://github.com/dhwjdgh1122/writing-demo/pull/23). 이전 [E 평가](설명%20정확성%20보완%20평가.md)와 비교한다.

**실제 변경 구간을 모델에 전달하는 코드는 구현·검증했지만, 설명 품질 개선은 확인하지 못했다.** E-01에서 잘못된 수정 설명이 나왔고 E-07 요청은 모델 서비스 오류로 실패했다. 나머지 6사례는 실행하지 않았으며 PR은 미완료 초안으로 유지한다.

## 구현 범위

- 기존 화면의 코드 포인트 LCS 비교를 `shared/diff.ts`로 옮겼다. 화면은 기존 경로에서 재노출한 같은 함수를 사용한다. 알고리즘·표시·후보 적용 규칙은 그대로다.
- `server/llm/explanation-input.ts`가 각 후보를 선택 원문과 독립 비교한다. 연속된 삭제·추가를 묶어 실제 `before`·`after`, 각 문자열의 UTF-16 위치, 양쪽 최대 12코드 포인트 주변 구간을 만든다. 입력의 공백·오타·줄바꿈을 정규화하지 않는다.
- `spacing-only`는 공백 제거 시 글자가 같은 구간, `text-change`는 글자도 다른 구간이다. 코드가 맞춤법·의미·안전성을 판정한 결과가 아니다. 인용과 전체 의미 비교에 참고하도록 지침에 설명했다.
- 후보당 변경 구간이 32개를 초과하면 일부만 보내지 않고 `mode: whole-text`, 빈 목록으로 명시한다. 원문·후보 전체는 계속 전달한다. 이 경우 빈 목록은 변경 없음을 뜻하지 않는다.
- Gemini·엘리스 어댑터 모두 설명 요청에 후보별 `comparison`을 추가한다. 브라우저 요청·응답 API, 교정 생성 요청, 인용 차단 규칙, 모델·키 설정은 바꾸지 않았다. 원문 작업 공간 전체나 선택 범위 밖의 내용은 추가 전송하지 않는다.
- 평가 도구에 `derivedModelInputs`를 기록해 실제 변경 구간을 검토할 수 있게 했다. 런타임 서버가 사용자 문장을 저장하는 기능은 추가하지 않았다.

## 실행 자료와 중단

- 코드 `019acd7`, 2026-11-16 21:56 KST, Gemini `gemini-3.5-flash-lite`.
- [실제 응답·계산된 모델 입력 JSON](criteria-2026-11-16T12-56-23-237Z.json)에 입력·후보·출처·필수 요소·코드 커밋·프롬프트·해시·시각을 보존했다. 원문·후보는 이전 E와 같다. 이번에는 입력 구조와 그 사용 지침이 함께 바뀌어 효과를 하나의 변경에만 귀속할 수 없다.
- 계획은 기존 E 6사례 + G 3사례 + S 3사례였다. **E 6회만 요청했고 5회 성공, E-07은 503 `MODEL_UNAVAILABLE`**였다. 모델 응답이 없으므로 E-07의 의미 설명 품질은 평가하지 않는다. G·S 6사례는 서비스 오류 후 미실행이다.
- JSON의 `completed: true`는 해당 파일의 E 6사례가 모두 요청됐다는 뜻이며 모두 성공하거나 계획한 12사례를 완료했다는 뜻이 아니다. 요청 실패는 `runs`의 상태와 함께 읽는다.
- 이번 실제 호출은 6회, #22 누적 51회, #20 기준선까지 포함하면 57회다. 자동 재시도·모델 전환·교정 후보 생성·기업 데이터 사용은 없다.

## 실제 관찰

E-01의 후보는 `금요일까지 자료를 보내 주세요.`다. 전달한 변경 정보는 정확히 다음과 같다.

```json
{"before":"여","after":"요","sourceContext":"까지 자료를 보내 주세여.","candidateContext":"까지 자료를 보내 주세요.","changeType":"text-change"}
```

그러나 실제 반환 설명은 다음과 같았다.

> 주세여를주세오로수정했습니다.

후보에 없는 `주세오`를 고쳤다고 설명하고 띄어쓰기도 부자연스럽다. 닫힌 인용 표시가 없어 기존 인용 검사는 통과했다. **API 200과 정확한 비교 정보 제공만으로 설명 정확성을 보장할 수 없다.** 이 오류를 감추기 위해 응답을 자동 교체하거나 인용 검사를 완화하지 않았다.

| 사례·후보 | 사실·중요 변화 | 선택 정보·읽기 | API·예비 판정 |
|---|---|---|---|
| E-01 c1 | 후보에 없는 `주세오` 변경 주장 | 잘못된 수정 안내·띄어쓰기 오류 | 200, 실패 |
| E-02 c1 | 구체적 요일 소실 1/1 | 목요일 유지 안내 | 200, 예비 통과 |
| E-03 c1 | 확인 조건·8→10명·확정 변화 3/3 | 조건·미확정·인원·일정 유지 안내. 두 번째 문장은 다소 추상적 | 200, 읽기·구체성 보완 가능 |
| E-04 p1 | 결재→결제·오탈자 수정 구분. 공백 위치는 ‘참가자 수 사이’로 모호하게 설명 | 단어 뜻 설명은 없음 | 200, 보완 필요 |
| E-04 p2 | 오탈자 수정과 결재 유지를 구분 | 남은 단어의 용례상 문제·선택 기준은 설명하지 않음 | 200, 보완 필요 |
| E-05 c1 | 코드 고정 안내 | 모델 품질 평가 제외 | 200, 고정 처리 확인 |
| E-07 c1 | 응답 없음 | 판정 불가 | 503, 설명 미제공 |
| G-01~03·S-01~03 | 미실행 | 판정 불가 | 서비스 오류 후 중단 |

판정자는 Codex이며 AI 보조 예비 평가다. 사람의 평가·사용자 효과 검증이 아니다. 외부 출처·사용자 의도 발명은 반환된 설명에서 관찰되지 않았으나 사실 오류와 누락은 별도로 남는다. 원문·후보의 품질은 기존 고정 사례의 성격을 그대로 따른다.

- API 성공 5/6 요청. 반환 모델 설명은 5/6 후보, 동일 후보 고정 안내 1/1 별도다.
- 평가 가능한 중요 변화는 E-02·03의 4/4다. E-07의 3개 변화는 응답이 없어 제외한다. 이전 7/7과 분모가 달라 전체 포착률이 유지됐다고 비교하지 않는다.
- E-01은 이전 E에서 맞았지만 F에서 틀렸다. 한 번씩의 관찰이며 성능 악화의 빈도나 입력 구조가 원인이라는 인과관계까지 확정하지 않는다.

## 검증·한계와 남은 작업

- 타입 검사·단위/API 테스트 **47개**, 빌드, 로컬 **Edge 브라우저 테스트 20개 통과**. 신규 테스트는 정확한 문자·공백 구분, 80개 결정적 생성 입력을 포함한 양쪽 문자열 재구성, 후보별 독립성, 32개 경계·전체 비교 전환, 이모지·줄바꿈·길이 제한을 확인한다. 제공자 테스트는 Gemini·엘리스에 전송하는 실제 JSON 구조를 각각 확인한다.
- 외부 호출 없이 기존 세 fixture의 14후보를 변경 구간으로 재구성해 일치함을 확인했다. 저장한 파생 입력과 실제 계산 함수, 기존 E의 원문·후보·모델, 코드 커밋·프롬프트를 대조했다. 변경 문서 8개의 내부 링크·앵커 150개와 `git diff --check`도 통과했다.
- 공유 diff는 기존 알고리즘과 동일하며 UI 경로는 재노출만 한다. 설명 입력을 코드로 만드는 기능이 동작한다는 검사와 실제 모델이 그 정보를 올바르게 활용한다는 평가는 다르다. 엘리스 실제 모델 품질은 이번에 시험하지 않았다.
- 이번 평가는 서비스 오류로 중단했고 재호출하지 않았다. S-03의 기존 인용 오류가 개선됐는지, G-02의 확정 변화 누락이 줄었는지는 미확인이다. 출력 길이·비용·지연의 체계적 비교도 수행하지 않았다.
- 후보가 길거나 구조가 크게 바뀌면 LCS 구간은 언어학적 변경 단위와 다를 수 있다. 문서 전체가 아닌 기존 선택·후보 길이 제한 안에서만 계산한다. 변경 구간과 주변 문맥 추가로 입력량은 증가한다.
- **PR #23의 품질 완료 기준은 여전히 미충족이다.** 재개 시에는 실패한 E-07과 미실행 G·S를 새 실행으로 구분해 기록하고, 틀린 설명을 사용자에게 반환하는 사례에 대한 추가 대책을 검토해야 한다. 구현 완료와 기능 채택·품질 검증 완료를 구분한다.
