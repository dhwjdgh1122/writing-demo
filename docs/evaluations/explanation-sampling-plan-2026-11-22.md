# 엘리스 응답 샘플링 설정의 제한 대조

2026-11-22 / #22·Draft PR #55 / 실행 전 계획. 제품 설정은 바꾸지 않는다.

## 기존 시도와 이번 차이

`6616269`의 동일 지침 비교 문서는 temperature를 보내지 않았다고 기록한다. 당시 `f0cf879`의 어댑터, 현재 어댑터, PR #23·#34 코드·실험 기록 및 현재 추적된 평가 JSON 26개의 정확한 설정 키를 점검했다. temperature·top_p/topP·seed를 바꿔 대조한 기록은 찾지 못했다. **설정 생략을 특정 숫자나 무작위성이 없는 상태라고 해석하지 않는다.**

지침 추가·사전 자료·독립 문장 분석에서도 내용 누락과 잘못된 풀이가 남았다. 이번에는 새 지식을 추가하지 않고 **같은 입력·지침에서 temperature=0을 명시하는 요청 정책이, 설정을 생략하는 정책보다 오류와 출력 변동을 줄이는가**를 확인한다. 낮은 설정이 한국어 지식·의미 판단을 개선한다고 전제하지 않는다.

Gemini는 이 비교에서 제외한다. [Google의 현행 API 안내](https://aistudio.google.com/docs/whats-new-gemini-3.6#api-changes-and-parameter-updates)는 Gemini 3.5 Flash-Lite부터 sampling 설정을 사용하지 않도록 안내한다(2026-11-22 확인). 그 모델에 의미 없는 설정 대조를 실행하거나 모델을 교체하지 않는다.

엘리스 현재 GPT-4o mini 프록시의 해당 설정 지원·기본값을 확정하는 개별 공개 문서는 이번 조회에서 확보하지 못했다. 따라서 **전송값·요청 수락·관찰 결과를 기록하되 HTTP 200만으로 프록시 내부 적용을 입증했다고 하지 않는다.** 400 등 설정 거절은 서비스/호환성 결과로 보존하고 다른 값으로 자동 재시도하지 않는다.

## 고정 입력·실행 경로

- 엘리스 `gpt-4o-mini` 및 기존 endpoint를 유지한다. 제공자 자동 전환·모델 변경은 없다.
- [기존 사전 전달 대조의 6사례](../../tests/fixtures/explanation-lexical-reference-2026-11-22.json)를 그대로 재사용한다: R-03, L-01, E-04(2후보), R-02, R-05, E-03. 원래 gate의 평가 항목과 E-04-p2 잔존 단어 요구를 보존한다.
- 두 조건 모두 기존 `referenceInstruction`과 같은 `lexicalReferences` 2개를 사용한다. **현행 제품의 무참고자료 프롬프트를 비교하는 시험은 아니다.** 사전 자료의 효과를 다시 평가하거나 채택한 것으로 취급하지 않는다.
- `omitted`는 sampling 키를 전송하지 않는다. `zero`는 같은 요청에 `temperature: 0` 하나만 추가한다. 모델·출력 형식·토큰·후보·지침·참고자료·인용 검사는 같다. `top_p`나 `seed`는 추가하지 않는다.
- 원래 로컬 `/api/explanations` → 엘리스 어댑터 → 현재 파서·인용 검사 경로를 사용한다. 주입은 실험 fetch 경계에만 있으며 제품 어댑터·UI를 변경하지 않는다.
- 6사례 × 2조건 × 2반복 = **최대24요청·28후보 결과**. 사례마다 순서를 교대하고 두 번째 반복에서는 같은 사례의 순서를 뒤집는다. 동일 출력이 나와도 결정적 동작을 보장한다고 표현하지 않는다.
- [실행 계획 JSON](../../scripts/evaluations/explanation-sampling-2026-11-22.json), 실제 프롬프트·파일 해시·전송 설정·원응답·API 결과를 보존한다. 반복 번호·판정 기준·정답·이전 출력은 모델에 보내지 않는다.

## 판정·중단 기준

R-03의 실제 오타 수정과 남은 지불 문맥 문제, E-04 두 후보의 수정/잔존 구분, E-03의 승인 조건·수량·미확정성·선택 기준을 필수로 확인한다. L-01·R-02·R-05에서는 정상 표현과 문맥 부족을 오류로 단정하지 않아야 한다. 인용·형식 통과, 내용 정확성, 필수 정보 누락, 선택 기준, 출력 문구의 반복 차이를 분리한다. 원출력 일부를 감추거나 자동 안내로 대체해 품질 성공으로 계산하지 않는다.

단 한 번의 사실 오류·필수 누락도 품질 통과는 아니다. 같은 중요한 누락이 두 반복에서 계속되면 지속 실패 관찰로 기록하고 같은 설정을 더 반복하지 않는다. 새 오판도 채택을 막는다. 같은 오답을 반복할 수 있으므로 문구의 동일성과 내용 정확성을 별도 집계한다. 일부 개선이 있더라도 제품 적용 전 현재 제품 프롬프트와 별도의 대조가 필요하며, #22의 원래 두 모델·14사례·3반복 기준을 통과한 것으로 처리하지 않는다. 소수 반복으로 일반 오류율·통계적 유의성·사용자 효과를 주장하지 않는다.

호출 직전 기존 후속 장부에 예약한다. 서비스/쿼터/설정 오류·시간 초과·원출력 확보 실패가 발생하면 남은 실행은 중단하고 미실행으로 보존한다. 실패 요청도 장부에 남기며 자동 재시도하지 않는다. 이번24회는 실험 크기이며 사용자가 해제한 전체 호출 상한을 재설정하는 것이 아니다.
