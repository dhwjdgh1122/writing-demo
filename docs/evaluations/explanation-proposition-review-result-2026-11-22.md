**결론: 출처 연결과 형식 검사는 작동했지만, 명제를 다시 쓰는 과정에서 가능성·예정 표현의 해석이 남았다. 현재 구성을 제품이나 다음 자동 판단 단계에 연결하지 않는다.** 확보한 4개 출력 중 이번 사례의 정보 보존을 확인한 것은 2개, 판단을 유보한 것은 2개다. 이는 AI 검토의 사례별 결과이며 설명 품질 점수·일반 정확도·실제 사용자 검증이 아니다.

예를 들어 이번 엘리스 E-03의 t2는 다음과 같다.

```text
입력: 화요일까지 10명에게 자료를 발송합니다.
명제: 화요일까지 10명에게 자료를 발송할 예정이다.
```

숫자와 기한은 맞고 형식도 유효하지만, `예정`이라는 해석은 명제 단계에서 추가됐다. 이번 목적은 두 입력이 전달하는 차이를 보존하는 것이므로, 이 해석을 확정된 근거로 삼아 다음 설명을 생성하지 않는다. 반대로 입력을 실제 발송 완료·확정 사실의 증거로 해석해서도 안 된다. CT-03도 단순히 `수 있다`라는 단어가 없다는 이유만으로 명백한 누락이라 판정하지 않고 서술 범위의 불확실성을 남겼다.

## 검토 기록과 묶음의 의미

[별도 구조화 검토 기록](explanation-proposition-review-assessment-2026-11-22.json)에 요청별 결합 키·원자료 파일/원응답 해시·검토 버전·명제 지지·정보별 보존·명제 관계·판단 이유를 남겼다. 루트와 별도 에이전트가 읽고 대조한 AI 검토다. 사람을 대상으로 한 평가나 별도 LLM API 판단 호출은 하지 않았다.

원자료 파일 해시는 실행 때 저장한 LF 형식의 UTF-8 바이트 기준이다. checkout에서 줄 끝이 변환되면 저장소의 해당 git blob으로 확인한다. JSON에 담긴 원응답 문자열 해시와 snapshot 결합 해시는 별도 직렬화 기준이므로 파일 해시와 혼용하지 않는다.

- 엘리스 CT-03의 h1은 회원 필요조건 자체가 지지되지만, 이 판정이 수령 가능성의 완전 보존을 뜻하지는 않는다. h2의 지지와 두 명제 관계는 불확실로 남겼다.
- 엘리스 E-03은 t1의 다섯 정보와 t2의 세 정보를 각각 기록했다. t2의 기한·수량과 발송 서술을 나누고, 뒤 항목은 `needs-review`로 남겼다. 유보된 항목은 통과로 계산하지 않는다.
- 네 검토 기록 모두 기존 오프라인 모듈의 결합 검사를 통과했다. Gemini CT-03만 양 명제의 지지·같은 의미 관계를 AI가 기록한 뒤 진단용 한 묶음을 구성했다. 원래 두 명제·출처는 보존된다. 이것은 **작성한 검토 기록을 코드가 처리한 결과**이며 모델이나 코드가 자동으로 의미 중복을 해결한 결과가 아니다.
- 확보 출력마다 출처당 명제가 하나씩이므로 동일 출처 안의 중복은 관찰되지 않았다. 입력을 거의 복사하거나 여러 정보를 하나의 명제로 담는 것도 이번 계약상 허용된다. 다만 더 작은 의미 단위로 나눠 얻는 실익은 이번 결과로 입증하지 못했다.

## 이전 결과와 다음 판단

직전 [명제 합집합 진단](explanation-propositions-result-2026-11-22.md)의 CT-03 중복·E-03 인용 재작성 실패는 그대로 보존한다. 새 과제는 quote를 생성하지 않고 출처별 중복을 허용하므로, 이번 형식 4개 통과를 이전 3개 통과보다 품질이 높아졌다는 증거로 삼지 않는다. 이전 엘리스 E-03의 주요 정보 보존과 이번 예정 해석을 함께 살펴볼 수는 있지만 생성 과제가 다르고 단회 결과라 인과적 개선·악화율을 계산할 수 없다.

두 제공자 모두 고정한 세 사례의 정보 보존 충족을 확인하지 못했다. 엘리스는 두 사례 유보, Gemini는 서비스 실패·미실행이 남는다. 따라서 **현재 구성을 그대로 확장하거나 같은 배치를 반복하지 않는다.** 후속 판단·최종 설명 생성·전체 반복 평가·제품 연결은 진행하지 않았다. [#22 원래 품질 기준](issue22-original-gate-2026-11-22.md)과 실제 사용자 판단 도움의 미검증 상태를 유지한다.

다음 검토는 **명제를 다시 쓰는 단계가 실제 원문 비교보다 어떤 정보를 더 제공하는지, 그 이익이 새 해석 위험을 감수할 만큼 있는지**다. 불확실한 제안을 자동 판단의 확정 근거로 사용하지 않는 범위와 기존 출처 연결·비교 기능의 재사용 가능성을 먼저 검토한다. 이번 결과만으로 추가 프롬프트 배치나 다단계 모델 호출을 시작하지 않는다.
