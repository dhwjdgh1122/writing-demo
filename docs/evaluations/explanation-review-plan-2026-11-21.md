# #22 설명 재검토 요청의 제한 실험 계획

2026-11-21. 실행 전 고정 계획. 제품 코드 반영 계획과 구분한다.

## 기존 시도와 새 가설

기존 PR #23·#34의 조건별 체크리스트, 근거 ID, 잔존 단어 점검, 숫자 자료 추가는 누락·오판을 충분히 해결하지 못했다. 같은 지침을 재포장하거나 문장 수만 늘리는 시험은 우선하지 않는다.

새 가설: **첫 설명을 생성한 뒤, 같은 모델의 별도 요청에 원문·후보·첫 설명을 함께 주고 재검토하도록 하면 놓친 변화와 잘못된 주장을 보완할 수 있는가?** 동일 요청 안에서 지시를 늘리는 기존 시도와 다르지만, 모델이 자기 오류를 반복할 수 있고 비용·지연이 늘어난다.

## 고정 입력과 요청

- E-03: 기존 조건·8→10·미확정 소실 사례 그대로.
- R-03: 기존 지불 문맥에서 남은 결재/결제 사례 그대로. 기존 `notes` 형식 대신 사용자에게 표시할 설명문으로 동일 의미 기준을 판정한다.
- Gemini `gemini-3.5-flash-lite`, 엘리스 `gpt-4o-mini`. 설정·출력 계약·인용 검사를 유지한다.
- 사례마다 현재 main의 첫 설명 1회 → 재검토 1회. 2사례×2모델×2회 = 최대8회.
- 재검토 입력은 원문·해당 후보·모델이 만든 첫 설명이다. 정답·사례별 required 필드는 보내지 않는다. 일반적인 실제 변화 대조·조건 연결·수치·부정·확정 여부·잔존 오용·조건부 선택 기준을 지시한다.
- 두 번째 요청은 최대4개의 짧은 문장, 총400자 한도를 지킨다. 이번 시험은 **별도 재검토와 재검토 지시의 결합 효과**이며, 호출 분리만의 인과 효과를 분리하지 않는다.
- 첫 응답이 HTTP 실패·출력 중단·읽을 수 없는 형식이면 재검토 입력으로 쓰지 않는다. 인용 검사에 걸렸어도 JSON의 첫 설명이 보존되어 있으면 재검토 대상으로 사용할 수 있으며, 사용자에게 표시된 성공으로 세지 않는다.
- 제공자 장애·쿼터·시간 초과는 해당 제공자의 남은 호출을 중단한다. 다른 제공자는 독립적으로 진행할 수 있다. 자동 재시도·모델 대체 없음.

## 판정과 확대 조건

- E-03: 담당자 확인 조건 삭제,8→10,예정·미확정 소실,원래 정보를 유지해야 할 때의 선택 기준을 모두 전달. 화요일 기한 변경 발명 금지.
- R-03: 오타 수정과 남은 지불 단어 문제를 구분. 이미 결제로 수정했다는 주장·새 의미 변화 발명 금지. 인용이 아닌 수정 제안은 실제 변경으로 표현하지 않는다.
- 두 모델 각각 두 사례에서 필수 정보를 모두 전달하고 사실 오류·인용 차단이 없으며, 첫 설명보다 누락 또는 잘못된 주장이 줄어야 확대 근거가 있다. 개선 없음·새 오류·불완전 대조는 채택 근거 부족으로 중단한다.
- 조건 충족 시에만 정상 결재·모호한 결재·정상 결제·오타 등의 기존 대조 사례에서 개발 잔여 한도 안에 추가 확인한다. 평가 입력/기준은 실행 전에 별도 고정한다.
- 실제 요청은 공통 장부에서 호출 직전 예약하며 기존5회에 더한다. 개발·재현24회,최종84회,총108회 상한을 넘지 않는다.

## 완료와 미완료

이 제한 시험의 완료는 원자료·실패·판정·채택 여부 기록이다. 전체 #22 품질 완료가 아니다. 2단계 생성을 그대로 14사례×2모델×3회 평가하면 최대168회가 필요해 승인된 최종84회 상한을 넘는다. 따라서 작은 시험이 좋아도 현재 예산으로 전체 반복 기준을 충족했다고 할 수 없으며, 제품 채택·90% 달성은 주장하지 않는다. 호출 한도를 임의로 늘리지 않고 #22 미완료를 보존하며 독립 기능 작업을 이어간다.
