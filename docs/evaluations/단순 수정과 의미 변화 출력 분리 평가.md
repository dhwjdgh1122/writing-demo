# 단순 수정과 의미 변화 출력 분리 평가 — M·N

2026-11-17 KST / #22 / Codex AI 보조 예비 평가. 실행 JSON은 UTC 2026-11-16이다. 사람의 독립 평가나 실제 사용자 효과 시험은 아니다.

## 결론

**출력 계약을 분리했지만 설명 품질 기준은 아직 미충족이다.** N에서 Gemini는 6건 모두 설명을 반환했고 엘리스는 4건을 반환했다. 그러나 두 모델 모두 납부 문맥에 남은 `결재` 문제를 설명하지 않았다. 엘리스에는 스키마 거부·의미 변화와 단순 표현 다듬기의 중복도 남았다. API 성공을 내용 합격으로 계산하지 않으며 PR #23 Draft·main 미병합을 유지한다.

## 변경과 평가 조건

- M 코드 `1a0a01e`: 모델 출력의 단순 수정은 `surfaceChanges[{kind,before,after}]`, 의미 변화는 `meaningChanges[{kind,before,after,effect}]`로 분리했다. 단순 수정에는 effect를 요청하지 않고, 임의의 effect가 오면 스키마 오류로 거부한다. 잘못된 설명을 지워 성공 처리하는 방식은 아니다.
- 서버는 의미 변화를 먼저 배치하고 단순 수정에 빈 effect를 붙여 기존 조합·인용 검사로 전달한다. 두 변경 배열의 합 12개·notes 2개·최종 400자 제한을 유지한다. 공개 API와 후보별 순차 호출, 최대 3모델 호출·공통 45초 제한은 바꾸지 않았다.
- M 지침은 후보에 남은 단어 점검을 비교보다 먼저 배치했다. N 코드 `9c668ae`는 M의 실패를 확인한 뒤 지침의 중복을 줄였다. 평가 대상의 정답 단어를 예시로 추가하거나 특정 단어를 서버에서 강제 교체하지 않았다.
- [M·N fixture](../../tests/fixtures/explanation-split-contract-cases.json)는 [L fixture](../../tests/fixtures/explanation-condition-usage-cases.json)의 사례 ID·원문·후보를 그대로 사용한다. 단순 수정 effect 기준만 새 계약에 맞게 바꿨다. 새 독립 표본이 아닌 기존 개발 사례의 재평가다.
- `modelDrafts`는 스키마를 통과한 응답을 서버 내부 형식으로 변환한 기록이다. 의미 변화가 먼저 오고 단순 수정에 빈 effect가 추가된다. 원시 JSON이 아니며 스키마 거부 응답은 저장되지 않는다. 따라서 스키마 오류의 구체적인 필드 원인은 이번 기록으로 특정할 수 없다.

## 검증과 다음 범위

- 타입 검사·단위/API **72개**·빌드 통과. 새 회귀 검사 3개는 의미 영향·notes 전달, 단순 수정의 불필요한 필드와 의미 변화 필수 필드, 두 배열의 합산 상한을 확인한다. 두 제공자와 API의 주입 응답 검사도 새 계약에 맞췄다.
- UI 변경이 없어 로컬 브라우저 검사를 반복하지 않았다. 최신 커밋의 브라우저·빌드 검사는 PR Checks에서 확인한다. 주입 응답의 자동 검사 통과는 실제 모델 정확성 검증이 아니다.
- 스키마 거부 원인을 값 노출 없이 필드·오류 유형으로 관찰할 수 있도록 하는 진단이 다음 우선 과제다. 현재 기록만 보고 effect 필드가 원인이라고 단정하지 않는다.
- 남은 단어 점검은 지침의 위치·길이 변경만으로 해결되지 않았다. 변경 설명과 후보 자체 검토를 분리하는 방식을 검토하되, 추가 호출을 도입한다면 시간·비용·실패 동작을 먼저 정해야 한다. 아직 구현한 기능이 아니다.
- usage/spelling 구분, 잘못된 wording 중복, 충분한 인용 문맥 및 기존 범위 밖 사례 검증도 남아 있다. 사람의 내용 검토·사용자 선택 효과는 미수행이다.
