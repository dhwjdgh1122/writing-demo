**11/21 후속 확인:** FEEDBACK-05 중 영역 밖 드래그는 기존 #4를 재개해 Edge에서 직접 재현하고 종료 이벤트 처리를 수정했다. 출력 중단은 [#44](https://github.com/dhwjdgh1122/writing-demo/issues/44)에서 전용 실패 안내와 제한 비교로 다룬다. 합성 예문 실제5회에서는 중단이 재현되지 않았으므로 제보가 해소됐다고 일반화하지 않는다. [직접 재현·주입 회귀·실제 호출의 구분](검증%20기록.md#correction-recovery-01)을 참고한다. 아래 접수 당시 기록은 보존한다.

- 제보 원문 또는 요약, 제공자·접수일, 근거, 질문·제안·오류 제보의 구분을 남긴다. 접수일과 실제 실행일을 혼동하지 않는다.
- 접수만으로 버그·채택·구현·효과 검증 완료로 표시하지 않는다. 질문의 답은 현재 명세에, 재현 결과는 검증 기록에 연결한다.
- 채택한 작업을 Issue로 옮기면 해당 링크를 남기고 상세 논의는 Issue에서 이어간다. Issue 본문은 [작업 카드 공통 양식](TASKS.md#issue-card-format)을 따르며, 이 문서의 과거 의견·제보 원문은 같은 양식으로 다시 쓰지 않는다. 작업 상태표를 이 문서에 중복 작성하지 않는다.
- 팀원은 이 문서를 읽고 자신의 관찰과 다른 점·추가 질문을 제안할 수 있다. 실행 환경·조작 순서·기대 결과·실제 결과를 함께 남기면 재현에 도움이 된다.

## FEEDBACK-14 — 후보 적용 뒤 원문의 변경 위치를 확인하기 어려움

**접수일:** 2026-11-24. 사용자가 병찬님의 의견과 화면 캡처를 전달했다. 원문 비교·교정 이유가 길어 적용 버튼까지 많이 내려와야 하고, 적용 버튼을 누른 위치에서는 원문 작업 공간의 변경 부분이 보이지 않는다는 제보다. 전달된 의견·화면에 근거한 접수이며 병찬님의 실행 환경에서 직접 재현한 기록은 아니다.

- **채택한 개선 범위:** 사용자의 진행 요청에 따라, ‘이 문장 적용’ 또는 ‘이 후보로 바꾸기’ 성공 직후 원문 입력란에 포커스를 두고 실제로 바뀐 범위를 선택 표시한다. 페이지뿐 아니라 입력란 내부 스크롤도 조정해 변경 위치를 보여준다. 후보·펼친 비교·설명은 유지한다.
- **범위 구분:** 이번에는 적용 버튼을 위에 추가하거나 위치를 옮기지 않는다. 버튼까지 내려가야 하는 거리 자체와 적용 결과를 찾기 어려운 문제를 구분해 후자부터 개선한다. 재교정의 실행 위치 유지·실패 처리도 별도로 유지한다.
- **연결:** [#79](https://github.com/dhwjdgh1122/writing-demo/issues/79)에서 작업·반영 상태를 관리하고 [후보 적용 명세](FEATURE_SPEC.md#applied-source-visibility)와 [화면 설계](DESIGN.md#교정-문장과-후보)에 반영한다. 접수·개선 채택만으로 병찬님의 환경에서 재현·해결 확인이나 사용자 효과 검증이 완료된 것으로 기록하지 않는다.

## FEEDBACK-11 — 적용 후 후보·비교를 유지하고 다른 후보로 바꾸기
