# 웹 데모 사용자 피드백

> 역할: 우리 웹 데모의 사용 의견·개선 제안·질문·미채택 제안과 검토 내용을 관리한다. 실제 입력·출력·재현 결과는 [검증 기록](검증%20기록.md), 담당·우선순위·진행 상태는 [TASKS](TASKS.md)의 관리 기준을 따른다. 기존 센틴스파이 관찰은 [서비스 사용 기록](research/서비스%20사용%20기록.md)으로 구분한다.

## 기록 기준

- 제보 원문 또는 요약, 제공자·접수일, 근거, 질문·제안·오류 제보의 구분을 남긴다. 접수일과 실제 실행일을 혼동하지 않는다.
- 접수만으로 버그·채택·구현·효과 검증 완료로 표시하지 않는다. 질문의 답은 현재 명세에, 재현 결과는 검증 기록에 연결한다.
- 채택한 작업을 Issue로 옮기면 해당 링크를 남기고 상세 논의는 Issue에서 이어간다. 작업 상태표를 이 문서에 중복 작성하지 않는다.
- 팀원은 이 문서를 읽고 자신의 관찰과 다른 점·추가 질문을 제안할 수 있다. 실행 환경·조작 순서·기대 결과·실제 결과를 함께 남기면 재현에 도움이 된다.

## FEEDBACK-01 — 병찬님의 사용 의견과 질문

**접수 기록일:** 2026-11-09. 오정호가 채팅으로 전달한 병찬님의 의견을 정리했다. 실제 실행 날짜·환경은 별도 확인하지 않았다. 이번 정리에서 재현하거나 제품을 수정하지 않았다.

팀원에게 목적·현재 범위의 이해 여부와 UI·불편·개선 의견을 자유롭게 요청한 결과다. 작업표대로 역할을 배정하거나 전체 문서의 동의를 확인한 것은 아니다.

### 실제 출력에서 확인할 문제

여러 문장을 선택한 사례에서 후보 1은 두 번째·세 번째 문장이 빠졌고, 후보 2는 줄바꿈이 공백으로 바뀌었다. 원문·후보·설명과 해석 한계는 [TEAM-01](검증%20기록.md#team-01)에 보존했다. 모델·서버·화면 중 원인 위치는 재현 전 확정하지 않는다.

### 개선 의견·질문·오류 제보

| 분류 | 전달받은 내용 | 현재 판단·추가 확인 |
|---|---|---|
| 사용성 | 원문 비교 하단의 밑줄·취소선·공백·줄바꿈 범례가 보기 어려움 | 가독성 개선 의견. 개선안과 사용자의 이해 여부 확인 필요 |
| 오류 제보 | 적용 후 Ctrl+Z·Ctrl+Y 동작이 꼬임 | 정확한 조작 순서·기대 상태·실제 상태·브라우저 정보가 필요. 재현·수정 완료 아님 |
| 설명 기대 | ‘왜 바뀌었는지’보다 ‘어떻게 바뀌었는지’ 표시함. 별도 요청 때문인지 질문 | 현재 설명은 실제 차이·의미 영향을 안내하려는 기능. 별도 요청이 원인이라는 해석은 확인되지 않음. 명칭과 사용자 기대도 검토 |
| 현재 동작 질문 | 다른 곳을 클릭해 포커스가 바뀌어도 선택한 문장이 유지됨 | 패널 조작 중 선택을 유지하는 것은 현재 명세에 포함됨. 다른 유효 범위 선택·원문 편집과 구분 |
| 동작 확인 | 같은 내용을 다시 붙여넣으면 선택이 유지됨 | 내용 변경 여부와 선택 위치를 포함해 재현한 뒤 의도와 비교. 오류로 확정하지 않음 |
| 화면 역할 질문 | 상단 01·02·03 표시가 순서 안내인지, 기능을 추가할 것인지 질문 | 현재 사용 흐름 안내이며 단계 이동 기능을 채택한 것은 아님 |
| 현재 기능 이해 | 전체 원문을 문맥 이해용으로 넣는다고 이해함. 한국어·일반 문장 옵션은 미지원으로 인식 | 현재 모델에는 선택한 텍스트만 전송함. 한국어·일반 문장은 상태 안내이며 설정 메뉴가 아님 |
| 추후 제안 | 교정 히스토리 필요성, 적용하지 않은 후보도 저장할지 질문 | 필요성과 저장 범위 논의 전. 현재 구현·필수 요구사항으로 확정하지 않음 |

추가 제보의 재현 결과가 나오면 검증 기록을 연결하고, 채택한 개선의 범위·완료 기준은 작업 카드에 정리한다. 기능 동작을 바꾸기로 결정한 경우에만 관련 명세를 갱신한다. 피드백 수령 현황과 작업 후보의 Issue 링크는 [TASKS](TASKS.md#이번-사용-피드백에서-구체화할-작업-후보)에서 확인한다. 후보를 Issue로 등록한 것은 채택·착수 또는 구현 완료를 뜻하지 않는다.

**11/12 후속 확인:** 위 표는 11/9 접수 당시 판단이다. 실행 취소·다시 실행은 이후 #3에서 수정됐으며, 병찬님의 Chrome 수동 확인과 Edge 자동 회귀 검증은 [UNDO-01](검증%20기록.md#undo-01)에 기록했다. 다른 제보까지 수정 완료했다는 의미는 아니다.

## FEEDBACK-02 — 희원님의 현재 방향과 사용 흐름에 대한 의견

**접수 기록일:** 2026-11-09. 오정호가 채팅으로 전달한 희원님의 의견을 정리했다.

- 현재 방향대로 진행해도 좋겠다는 의견이다.
- 원문 작업 공간에 글을 넣고 필요한 문장만 선택해 교정한 뒤, 후보만 보고 선택할 수 있으면 바로 적용하고 헷갈릴 때만 설명을 여는 흐름을 긍정적으로 평가했다.
- 현재 추가로 제안하고 싶은 기능은 없으며, 우선 이대로 진행하면서 더 생각해 보겠다고 했다.

현재 방향과 사용 흐름에 대한 의견으로 기록한다. 이 의견에 따른 코드·기능 범위·기존 작업·역할 배정 변경은 없다. 전체 기능이나 교정 품질의 검증 완료를 뜻하지 않는다.

## FEEDBACK-03 — 병찬님의 엘리스 추가 실행 제보

**접수·기록일:** 2026-11-12. 오정호가 전달한 11/10 발표 준비 중 사용 기록이다. 실행별 정확한 시각은 미확보다. 제보에는 리비전 `f1e588a16eea9d9e20fe494393f768f0c742b219`와 `elice gpt-4o-mini`가 명시돼 있다. 입력·후보·설명과 해석 한계는 [ELICE-02](검증%20기록.md#elice-02)에 기록했다.

| 분류 | 제보 내용 | 확인할 사항 |
|---|---|---|
| 미확인 출력 제보 | 교정 이유에 채팅 고유 번호처럼 보이는 문자가 나타남 | 캡처·문자열이 없어 실제 ID 노출로 단정하지 않는다. 재발 시 요청별 원문·후보·설명을 확보한다. |
| 설명 차단 | 팀빌딩 안내문에서 인용 불일치 안내가 나타남 | 인용 검사 정상 차단과 검사 오류를 구분한다. 차단된 응답과 실제 버튼·요청 순서를 확인한다. |
| 설명 품질 | `이候 보기에 제안된 내용은 원문과 동일합니다.` 출력 | 혼합 문자와, 실제 바뀐 후보를 동일하다고 설명한 문제를 구분한다. 원문·후보·설명 연결과 생성 응답을 확인한다. |
| 교정·설명 대조 | 안내문 후보가 어색해지거나 설명이 실제 변경과 맞지 않는 부분이 있음 | 교정 후보의 품질과 그 후보에 대한 설명의 정확성을 각각 평가한다. |

이번 추가 제보는 앞선 FEEDBACK-01의 기대·사용성 의견과 구분한다. 기존 #5의 설명 평가 기준, #9의 모델 비교 계획과 관련되지만, 이번 출력 사례의 재현·원인 확인을 완료한 것으로 처리하지 않는다. 개발 채택·담당·기한은 별도 협의한다.
