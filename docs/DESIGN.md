# 화면 설계 — 데스크톱앱 화면을 기준으로 한 웹 데모

> 역할: 화면 배치·상태·조작·시각 규칙을 정의한다. 상태: 2026-11-06 기본 화면 구현 및 1440·1280·390px Edge 검증 완료. 교정 이유 열기·접기와 후보별 설명 영역을 구현했다. 기본 교정·적용은 오정호가 제공한 실제 실행 화면으로 확인했다.

## 1. 화면 목표와 참고 기준

사용자가 원문을 선택하고, 교정 후보를 비교한 뒤 선택한 위치에 적용하는 과정을 한 페이지에서 보여준다. 설명은 필요할 때 펼친다.

| 참고 자료 | 반영할 요소 | 이번 화면에 반영하지 않을 요소 |
|---|---|---|
| 오정호가 제공한 센틴스파이 데스크톱 앱 화면 | 흰색 중심 화면, 보라색 강조, 선택·교정 결과의 구분 | 앱 로고·브랜드 그래픽, OS 창 버튼, 구현하지 않은 설정 메뉴 |
| 설명 표시 원칙 | 결과를 먼저 보고 필요한 경우 후보별 설명 열기 | 기본 화면에서 설명을 모두 펼쳐 표시 |

웹 데모에서는 원문 작업 공간과 교정 패널을 한 페이지에 배치한다. 설명은 기본으로 펼치지 않고 사용자가 버튼을 눌렀을 때 표시한다.

상단 브랜드는 ‘문장 교정 DEMO’, 본문 제목은 ‘고치고 싶은 문장부터 선택하세요.’를 사용한다. ‘센틴스파이 데스크톱 사용 흐름을 참고한 독립 웹 데모’라는 보조 문구로 실제 서비스와 구분한다.

## 2. 기본 배치

데스크톱에서는 왼쪽 원문 작업 공간과 오른쪽 교정 결과 패널을 유지한다. 11/18 #4의 후속 변경에서는 하단의 큰 선택 패널을 제거하고, 원문 상단의 작은 선택·실행 영역과 선택 위치 근처 버튼으로 읽기 전용 확인창을 연다. 자동 스크롤·선택 즉시 팝업은 사용하지 않는다. 변경 이력과 병합 근거는 [PR #26](https://github.com/dhwjdgh1122/writing-demo/pull/26)에서 확인한다. 후보 카드·원문 비교·교정 이유·적용 UI는 기존 구성을 유지한다.

```text
문장 교정 DEMO                           AI 연결 상태
고치고 싶은 문장부터 선택하세요.
┌────────────────────────┐  ┌────────────────────────┐
│ 원문 작업 공간          │  │ 교정 문장   [교정 이유] │
│ 선택 글자 수 · 선택 해제 │  │                        │
│ [교정 실행]             │  │                        │
│ 입력·붙여넣기           │  │ 후보 1 · 변경 부분 강조 │
│ 문장을 드래그하여 선택  │  │ [원문 비교] [이 문장 적용]│
│                        │  │ 후보 2 ...              │
│                        │  │ 후보 3 ...              │
└────────────────────────┘  └────────────────────────┘
선택 위치 근처 [교정하기] 또는 상단 [교정 실행]
  → 음영 확인창: 선택 원문(읽기 전용·본문 스크롤)
  → [원문으로 돌아가기] / [교정 시작]
선택한 내용만 교정합니다. 이 페이지의 작업은 자동 저장되지 않습니다.
```

- 최대 콘텐츠 폭 1,440px, 바깥 여백 24px, 두 영역 간격 24px를 기준으로 한다.
- 1,024px 이상에서는 원문 약 55%, 패널 약 45%로 배분한다. 두 열 모두 긴 문장 때문에 화면 밖으로 늘어나지 않게 한다.
- 원문 상단의 선택·실행 영역은 해당 패널 안에서 sticky로 유지한다. 근처 버튼은 선택 끝점(역방향이면 시작점)을 기준으로 본문·화면 경계 안에 배치한다. 스크롤·크기 변경 시 떠 있는 버튼은 숨기며 고정 실행 버튼을 사용할 수 있다.
- 1,024px 미만에서는 원문(선택·실행 포함) → 교정 결과 순서로 쌓는다. 390px에서는 좌우 여백 16px, 버튼 줄바꿈을 허용한다.
- 페이지 전체 스크롤을 기본으로 한다. 확인창이 열리면 배경 조작·페이지 스크롤을 막고 선택 원문 본문에만 세로 스크롤을 둔다. 제목·닫기·실행 버튼은 본문 스크롤과 분리한다. 후보 목록을 고정 높이로 잘라 숨기지 않는다.
- 첫 버전의 원문 입력란은 일반 textarea로 구성한다. 원문 전체 길이는 20,000자 기준으로 안내한다. 초과한 붙여넣기 내용도 버리지 않고 화면에 유지하되, 사용자가 길이를 줄일 때까지 교정 실행을 막는다. 선택 길이 1,000자 제한과 별도로 안내한다.
- 읽기 전용 ‘한국어 · 일반 문장 다듬기’는 현재 동작 안내다. 작동하지 않는 드롭다운으로 보이게 만들지 않는다.
- 상단 `01 문장 선택 → 02 교정 실행 → 03 비교·적용`은 사용 순서 안내이며 단계 이동 버튼이 아니다. 현재 구현은 1100px 이하에서 이 표시를 숨긴다. 선택 대상·전송 범위 안내와 함께 [11/17 점검](검증%20기록.md#selection-scope-01)에서 대조했으며, 사용자 이해도 검증과 구분한다.

## 3. 영역별 조작

### 원문 작업 공간

- 빈 입력란과 ‘원문을 입력하거나 붙여넣고, 고칠 부분을 선택해주세요’ 안내로 시작한다.
- 기본 예문을 자동으로 넣지 않는다. 개발·검증 예문과 사용자가 입력한 문장을 구분한다.
- 드래그 또는 키보드로 연속된 한 구간을 선택하면 글자 수를 표시한다. 선택만으로 확인창을 열지 않으며 복사·범위 조정을 방해하지 않는다. 버튼으로 포커스를 옮겨도 선택 대상은 유지한다.
- 원문에서 커서만 옮기면 선택 대상이 유지된다. 패널의 ‘선택 해제’ 버튼으로 교정 대상을 지울 수 있다.
- 원문 편집 또는 다른 범위 선택 시 이전 결과를 닫고 다시 실행하도록 한다. 세부 무효화 규칙은 기능명세를 따른다.
- 한글 입력 조합 중에는 원문 수정으로 기존 결과를 무효화하되, 새 선택 확정·교정 실행은 조합이 끝난 후 처리한다.

### 선택한 문장

- ‘교정하기’ 또는 ‘교정 실행’을 누르면 배경을 어둡게 하는 확인창을 연다. 전체 선택 텍스트를 공백·줄바꿈 보존 상태로 읽기 전용 표시한다. 길면 본문 영역을 스크롤할 수 있게 하고 말줄임만으로 숨기지 않는다.
- 닫기·Esc·‘원문으로 돌아가기’는 요청을 보내지 않고 선택 범위와 원문 포커스·스크롤을 복원한다. 팝업에서는 Tab이 내부를 순환하며 본문도 키보드로 스크롤할 수 있다.
- 확인창이 열린 동안 배경 원문의 선택 구간을 연한 보라색으로 표시한다. 포커스는 확인창에 유지하고 표시용 레이어는 입력·접근성 읽기 대상에서 제외한다. 닫기·실행·원문/선택 버전 변경 시 표시를 제거한다. 변경 근거는 [#27](https://github.com/dhwjdgh1122/writing-demo/issues/27)을 따른다.
- ‘교정 시작’을 누른 때만 요청을 보내고 확인창을 닫는다. 떨어진 다중 구간 선택·팝업 내 편집은 지원하지 않는다.
- 선택 글자 수는 ‘선택한 글 120자 · 최대 1,000자까지 교정할 수 있어요’로 표시하며 초기·선택 해제 상태에는 0자를 표시한다. 선택 안내는 한 번만 표시한다. 입력란 아래에는 ‘전체 글 350자 · 최대 20,000자 입력 가능’으로 전체 입력 한도와 한 번의 교정 한도를 구분한다. 확인창에도 같은 교정 한도 문구를 사용한다. 선택량 초과 시 ‘선택한 내용이 1,000자를 넘었어요. 범위를 줄여서 나누어 교정해주세요.’라고 안내하고 실행을 비활성화한다.
- 선택 없음·공백 선택·요청 중에는 실행을 비활성화하며 그 이유를 텍스트로 표시한다.
- 상단 ‘교정 실행’을 작은 테두리 보조 버튼으로 표시한다. 선택 근처 ‘교정하기’를 주된 진입 경로로 사용하고, 상단 버튼은 스크롤 후·키보드 조작 시의 고정 경로로 유지한다. 팝업의 실제 요청 버튼 ‘교정 시작’은 보라색 채움 버튼을 유지한다. 버튼 명칭·실행 조건은 동일하다.
- 페이지 내 단축키는 미채택 상태다. 실제 구현·확인 전에는 Ctrl+C+C 안내를 화면에 넣지 않는다.

### 교정 문장과 후보

- 후보는 세로 목록으로 표시한다. ‘후보 1’, ‘후보 2’처럼 중립적인 이름을 사용하며 모델 추천 순위로 안내하지 않는다.
- 후보 문장, ‘원문 비교’ 펼치기, ‘이 문장 적용’ 버튼을 제공한다. 카드나 본문 클릭 자체로 원문을 교체하지 않는다.
- 원문과 동일하면 ‘원문과 동일’ 표시와 함께 적용 버튼을 비활성화한다.
- 적용 성공 시 후보·설명을 닫고 선택 글자 수를 갱신한다. 변경된 선택 문장은 확인창에서 다시 확인할 수 있다. 적용 안내를 읽을 수 있도록 유지하고, 키보드 포커스는 고정 교정 실행 버튼으로 옮긴다.
- 적용 완료 상태에서는 결과 영역을 원문 확인·다른 문장 선택 안내로 바꾸고 선택 영역의 보조 문구도 원문 확인으로 맞춘다. 실행 버튼과 선택 범위는 유지하되, 새 범위 선택·원문 편집·선택 해제·재실행 시 기존 상태 안내로 전환한다.
- 같은 선택에서 ‘교정 실행’ → 확인창의 ‘교정 시작’을 누르면 새 요청을 보낸다. 별도 재실행 버튼은 없으며, 이전 실행과 다른 후보를 보장하지 않는다.

## 4. 변경 표시와 설명

### 변경 부분

- 후보의 추가·교체된 텍스트에는 보라색과 밑줄을 사용한다. 일반 글씨와 충분히 구분되도록 한다.
- ‘원문 비교’를 펼치면 원문과 후보를 위아래로 표시한다. 원문에서 삭제된 내용은 취소선과 ‘삭제’ 범례로 표현한다.
- 비교 영역 상단에 추가(밑줄)·삭제(취소선)의 실제 표시 예시와 공백 `·`·줄바꿈 `↵`·탭 `⇥` 범례를 둔다. 범례는 12px 글자와 항목별 간격을 사용하며 좁은 화면에서 여러 줄로 배치한다. ‘원문 비교’ 조작은 13px로 표시한다.
- 공백·줄바꿈·탭 기호는 변경된 부분뿐 아니라 비교 영역의 해당 문자 위치를 보여준다. 기호 자체가 변경을 뜻하지 않으며 변경 여부는 밑줄·취소선으로 구분하도록 안내한다. 표시용 기호를 실제 후보 문자열에 삽입하지 않으며, 적용에는 원래 후보 텍스트를 사용한다.
- 후보 목록 위에서는 밑줄이 추가된 표현임을 안내하고 삭제·교체 내용은 ‘원문 비교’에서 확인하도록 연결한다. 비교 계산에 실패한 후보에는 범례를 표시하지 않고 기존 직접 비교 안내를 유지한다. 사용자 이해도 개선 효과는 별도 검증 대상이다.
- 원문에서 삭제된 부분이 있는 후보에는 비교 영역을 열 수 있는 ‘삭제된 내용 있음’ 안내를 표시한다. 교체도 삭제와 추가로 계산되므로 이 안내가 함께 나올 수 있다. 색이 없어 변경이 없다고 오해하지 않도록 한다.
- 변경 표시와 문법적 정답·사용자 의도 보존은 다르다. ‘더 좋은 후보’라는 평가 배지를 자동으로 붙이지 않는다.

### 교정 이유

- 결과 제목 바로 아래 오른쪽에 설명 아이콘과 ‘교정 이유’ 이름을 둔다. 아이콘만으로 기능을 전달하지 않는다.
- 버튼은 현재 후보 전체의 설명 표시를 켜고 끈다. 설명은 각 후보 바로 아래에 나타나 해당 후보와 대응된다.
- 기본 상태는 닫힘이다. 처음 열 때 설명을 요청하며, 설명 로딩 중에도 후보 적용은 가능하다.
- 설명 중 원문을 적용하거나 다른 대상을 선택하면 이전 설명을 무효화한다.
- 설명은 후보별 1~2문장을 목표로 한다. 실패하면 후보는 유지하고 설명 영역에 ‘설명을 불러오지 못했습니다’와 재시도 버튼을 표시한다.
- 원문 비교는 실제 문자열 차이 표시이며, 교정 이유는 LLM 설명이다. 두 조작의 이름과 내용을 구분한다.

## 5. 상태별 화면

| 상태 | 표시 | 가능한 조작 |
|---|---|---|
| 초기·선택 없음 | 선택 안내, 비어 있는 교정 영역 | 원문 입력·선택 |
| 선택 완료 | 선택 글자 수·근처 실행 버튼 | 확인창 열기·선택 해제 |
| 선택 확인창 | 읽기 전용 원문·본문 스크롤·배경 음영 | 교정 시작·닫기·원문으로 돌아가기 |
| 길이 초과·공백 | 원인 안내 | 원문 수정·다시 선택 |
| 교정 중 | ‘교정안을 만들고 있습니다’ | 원문 편집·새 선택 가능, 중복 실행 차단 |
| 교정 결과 | 실제 반환한 후보 개수·변경 표시 | 비교·적용·이유 열기 |
| 교정 실패 | 실패 안내, 원문 보존 | 현재 유효 선택으로 재시도 |
| 요청 뒤 선택 변경 | 이전 결과 닫힘·새 선택 표시 | 새 선택으로 실행 |
| 적용 완료 | 적용 안내·교체된 문장 | 계속 편집·새 실행 |
| 설명 중·설명 실패 | 후보는 유지, 설명 영역만 상태 표시 | 설명 닫기·실패 시 재시도·후보 적용 |
| API 미설정 | ‘AI 연결 설정이 필요합니다’ | 원문 입력·선택 가능, 가짜 결과로 대체하지 않음 |

## 7. 화면 검증 계획

- 1440×900, 1280×720, 390×844 화면에서 선택 문장·후보·버튼이 잘리지 않는지 확인한다.
- 키보드로 원문 선택 → 실행 → 후보 비교 → 설명 열기 → 적용할 수 있어야 한다.
- 포커스 테두리를 표시하고, 펼치기 버튼은 현재 열림 상태를 보조기술에 전달한다.
- 로딩·오류·적용 안내는 상태 영역에서 알린다. 결과 갱신 때 원문 입력 포커스를 임의로 빼앗지 않는다.
- 긴 텍스트·삭제만 있는 후보·띄어쓰기 차이·설명 실패 화면을 실제 브라우저에서 확인한다.
