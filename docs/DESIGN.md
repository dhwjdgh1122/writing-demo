# 화면 설계 — 데스크톱앱 화면을 기준으로 한 웹 데모

> 역할: 화면 배치·상태·조작·시각 규칙을 정의한다. 11/18 도입한 선택 확인창·배경 선택 표시의 과거 검증은 보존하며, 11/23 사용자 요청에 따라 두 교정 버튼에서 확인창 없이 바로 실행하도록 변경한다. 최신 변경 근거·검증 범위는 [DIRECT-CORRECTION-ENTRY-01](검증%20기록.md#direct-correction-entry-01)을 따른다. 과거 화면 검증을 현재 모든 환경의 확인으로 확대하지 않는다.

## 1. 화면 목표와 참고 기준

사용자가 원문을 선택하고, 교정 후보를 비교한 뒤 선택한 위치에 적용하는 과정을 한 페이지에서 보여준다. 설명은 필요할 때 펼친다.

| 참고 자료 | 반영할 요소 | 이번 화면에 반영하지 않을 요소 |
|---|---|---|
| 오정호가 제공한 센틴스파이 데스크톱 앱 화면 | 흰색 중심 화면, 보라색 강조, 선택·교정 결과의 구분 | 앱 로고·브랜드 그래픽, OS 창 버튼, 구현하지 않은 설정 메뉴 |
| 설명 표시 원칙 | 결과를 먼저 보고 필요한 경우 후보별 설명 열기 | 기본 화면에서 설명을 모두 펼쳐 표시 |

웹 데모에서는 원문 작업 공간과 교정 패널을 한 페이지에 배치한다. 설명은 기본으로 펼치지 않고 사용자가 버튼을 눌렀을 때 표시한다.

상단 브랜드는 ‘문장 교정 DEMO’, 본문 제목은 ‘고치고 싶은 문장부터 선택하세요.’를 사용한다. ‘센틴스파이 데스크톱 사용 흐름을 참고한 독립 웹 데모’라는 보조 문구로 실제 서비스와 구분한다.

## 2. 기본 배치

데스크톱에서는 왼쪽 원문 작업 공간과 오른쪽 교정 결과 패널을 유지한다. 원문 상단의 작은 선택·실행 영역과 선택 위치 근처 버튼을 유지하되, 두 버튼 모두 확인창 없이 교정을 시작한다. 선택만으로 요청·강제 스크롤은 발생하지 않는다. 확인창을 사용했던 [PR #26](https://github.com/dhwjdgh1122/writing-demo/pull/26)의 후속 변경은 [#64](https://github.com/dhwjdgh1122/writing-demo/issues/64)에서 관리한다. 후보 카드·원문 비교·교정 이유·적용 UI는 기존 구성을 유지한다.

```text
문장 교정 DEMO                           AI 연결 상태
고치고 싶은 문장부터 선택하세요.
┌────────────────────────┐  ┌────────────────────────┐
│ 원문 작업 공간          │  │ 교정 문장   [교정 이력] │
│ 선택 글자 수 · 선택 해제 │  │             [교정 이유] │
│ [교정 실행]             │  │                        │
│ 입력·붙여넣기           │  │ 후보 1 · 완성 문장      │
│ 문장을 드래그하여 선택  │  │ [원문 비교] [이 문장 적용]│
│                        │  │ 후보 2 ...              │
│                        │  │ 후보 3 ...              │
└────────────────────────┘  └────────────────────────┘
선택 위치 근처 [교정하기] 또는 상단 [교정 실행]
  → 확인창 없이 교정 요청 → 교정 결과 표시
선택한 부분의 교정 이력은 브라우저에 보관합니다. 작성 중인 글 전체는 복원하지 않습니다.
[교정 이력] → 같은 오른쪽 패널의 이력 목록 → [뒤로]로 현재 교정 화면 복귀
```

- 최대 콘텐츠 폭 1,440px, 바깥 여백 24px, 두 영역 간격 24px를 기준으로 한다.
- 1,024px 이상에서는 원문 약 55%, 패널 약 45%로 배분한다. 두 열 모두 긴 문장 때문에 화면 밖으로 늘어나지 않게 한다.
- 원문 상단의 선택·실행 영역은 해당 패널 안에서 sticky로 유지한다. 근처 버튼은 선택 끝점(역방향이면 시작점)을 기준으로 본문·화면 경계 안에 배치한다. 스크롤·크기 변경 시 떠 있는 버튼은 숨기며 고정 실행 버튼을 사용할 수 있다.
- 1,024px 미만에서는 원문(선택·실행 포함) → 교정 결과 순서로 쌓는다. 390px에서는 좌우 여백 16px, 버튼 줄바꿈을 허용한다.
- 페이지 전체 스크롤을 기본으로 한다. 교정 시작 시 배경 음영·스크롤 잠금을 사용하지 않는다. 후보 목록을 고정 높이로 잘라 숨기지 않는다.
- 교정 이력은 오른쪽 패널 안에서 현재 교정 화면과 전환한다. 이력 제목·뒤로·내보내기·전체 삭제는 목록 스크롤 바깥에 두고, 긴 이력 내용은 패널 안에서 스크롤한다. 모바일에서도 글자 크기를 축소하지 않고 줄바꿈·여백으로 폭을 맞춘다.
- 첫 버전의 원문 입력란은 일반 textarea로 구성한다. 원문 전체 길이는 20,000자 기준으로 안내한다. 초과한 붙여넣기 내용도 버리지 않고 화면에 유지하되, 사용자가 길이를 줄일 때까지 교정 실행을 막는다. 선택 길이 1,000자 제한과 별도로 안내한다.
- 읽기 전용 ‘한국어 · 일반 문장 다듬기’는 현재 동작 안내다. 작동하지 않는 드롭다운으로 보이게 만들지 않는다.
- 상단 `01 문장 선택 → 02 교정 실행 → 03 비교·적용`은 사용 순서 안내이며 단계 이동 버튼이 아니다. 현재 구현은 1100px 이하에서 이 표시를 숨긴다. 선택 대상·전송 범위 안내와 함께 [11/17 점검](검증%20기록.md#selection-scope-01)에서 대조했으며, 사용자 이해도 검증과 구분한다.

## 3. 영역별 조작

### 원문 작업 공간

- 빈 입력란과 ‘원문을 입력하거나 붙여넣고, 고칠 부분을 선택해주세요’ 안내로 시작한다.
- 기본 예문을 자동으로 넣지 않는다. 개발·검증 예문과 사용자가 입력한 문장을 구분한다.
- 드래그 또는 키보드로 연속된 한 구간을 선택하면 글자 수를 표시한다. 선택만으로 요청하지 않으며 복사·범위 조정을 방해하지 않는다. 버튼으로 포커스를 옮겨도 선택 대상은 유지한다.
- 원문에서 커서만 옮기면 선택 대상이 유지된다. 패널의 ‘선택 해제’ 버튼으로 교정 대상을 지울 수 있다.
- 원문 편집 또는 다른 범위 선택 시 이전 결과를 닫고 다시 실행하도록 한다. 세부 무효화 규칙은 기능명세를 따른다.
- 한글 입력 조합 중에는 원문 수정으로 기존 결과를 무효화하되, 새 선택 확정·교정 실행은 조합이 끝난 후 처리한다.

### 선택한 문장

- ‘교정하기’ 또는 ‘교정 실행’을 누르면 공백·줄바꿈을 포함한 현재 선택 텍스트로 바로 요청한다. 선택 내용을 한 번 더 보여주는 팝업·배경 음영·확인 버튼은 두지 않는다.
- 드래그 후 나타나는 ‘교정하기’는 유지한다. 이 버튼의 포인터 조작으로 선택을 해제하지 않으며, 실행 후 원문에 포커스를 돌려준다. 긴 원문은 기존 입력란에서 확인·스크롤한다.
- 선택 확인창 전용 배경 선택 레이어는 제거한다. 원문 입력란의 실제 선택 상태와 Undo/Redo는 유지하며, 떨어진 다중 구간 선택은 지원하지 않는다.
- 선택 글자 수는 ‘선택한 글 120자 · 최대 1,000자까지 교정할 수 있어요’로 표시하며 초기·선택 해제 상태에는 0자를 표시한다. 선택 안내는 한 번만 표시한다. 입력란 아래에는 ‘전체 글 350자 · 최대 20,000자 입력 가능’으로 전체 입력 한도와 한 번의 교정 한도를 구분한다. 선택량 초과 시 ‘선택한 내용이 1,000자를 넘었어요. 범위를 줄여서 나누어 교정해주세요.’라고 안내하고 실행을 비활성화한다.
- 선택 없음·공백 선택·요청 중에는 실행을 비활성화하며 그 이유를 텍스트로 표시한다.
- 상단 ‘교정 실행’을 작은 테두리 보조 버튼으로 표시한다. 선택 근처 ‘교정하기’를 주된 진입 경로로 사용하고, 상단 버튼은 스크롤 후·키보드 조작 시의 고정 경로로 유지한다. 두 버튼의 실행 조건·요청 경로는 같다.
- 페이지 내 단축키는 미채택 상태다. 실제 구현·확인 전에는 Ctrl+C+C 안내를 화면에 넣지 않는다.

### 교정 문장과 후보

- 결과 제목 오른쪽에는 ‘교정 이력’, ‘교정 이유’ 버튼을 위아래로 배치한다. 제목 옆의 ‘후보 N개’ 배지는 표시하지 않으며, 각 카드의 ‘후보 1’ 이름과 이력 안의 후보 수는 유지한다.
- 두 버튼은 160×40px, 아이콘 18×18px, 글자 14px와 같은 테두리·모서리·간격을 사용한다. 아이콘과 텍스트의 시작 위치를 같게 왼쪽 정렬하고 버튼 사이는 8px로 둔다. 이력은 되돌림 화살표가 있는 시계, 이유는 글줄이 있는 말풍선 아이콘으로 구분하며 같은 선 두께를 사용한다.
- ‘교정 이력’은 최초 진입·교정 요청 중·실패·적용 완료 상태에서도 사용할 수 있다. 설명은 유효한 현재 후보가 있을 때 연다.
- 최초·일반 교정과 적용 후 재교정의 성공 결과는 후보 3개를 세로 목록으로 표시한다. 카드 재교정은 해당 자리의 후보 1개만 교체하며 나머지 카드의 내용·설명·비교를 유지한다. ‘후보 1’, ‘후보 2’, ‘후보 3’처럼 중립적인 이름을 사용하며 모델 추천 순위로 안내하지 않는다. 요청별 개수가 맞지 않거나 출력이 잘리면 기존 실패 안내를 표시하며 후보를 채우거나 복제하지 않는다. 기존 이력은 저장된 1~3개 후보를 그대로 보여준다.
- 후보 문장, ‘원문 비교’ 펼치기, ‘이 문장 적용’ 버튼을 제공한다. 카드나 본문 클릭 자체로 원문을 교체하지 않는다.
- 생성 원문과 동일하면 ‘원문과 동일’을 표시한다. 적용 버튼의 비활성화는 현재 적용 대상 텍스트와의 일치 여부로 결정하므로, 다른 후보를 적용한 뒤 생성 원문과 같았던 후보로 되돌릴 수도 있다.
- 적용 성공 시 후보 3개·펼친 비교·설명과 읽던 변경 표현을 유지하고 선택 글자 수를 갱신한다. 적용한 카드에는 ‘적용됨’ 배지와 비활성 적용 버튼을 표시한다. 다른 카드는 ‘이 후보로 바꾸기’로 현재 적용 범위를 교체하며 현재 문장과 같으면 중복 적용을 막는다. 해당 카드의 ‘다시 교정하기’로 포커스를 연결하고 화면을 맨 위로 이동시키지 않는다.
- 결과 목록을 빈 안내 화면으로 바꾸지 않는다. 적용 완료 안내와 원문 확인 문구를 함께 표시하고, 비교·설명은 후보 생성 당시 원문 기준임을 알린다. 새 범위 선택·원문 편집·선택 해제·Undo/Redo로 문맥이 달라지면 기존 결과를 무효화하고 제거한다.
- 같은 선택에서 ‘교정 실행’을 누르면 일반 새 요청을 바로 보낸다. 결과가 있거나 방금 적용한 상태에서는 ‘다시 교정하기’로 선택 영역을 펼치고 요구를 선택한 뒤 ‘교정 시작’으로 이전 요청에 연결할 수 있다. 요구는 선택 사항이며 추가 확인창을 열지 않는다. 이전 실행과 다른 후보나 요구 충족을 보장하지 않는다. [PR #63의 진입 배치](#rerun-entry-plan)를 따른다.

## 4. 변경 표시와 설명

### 변경 부분

- 카드 상단 후보는 완성된 문장만 표시한다. 밑줄·배경 강조·표시용 공백 기호를 넣지 않으며, 기존 ‘삭제된 내용 있음’ 안내와 후보 목록 위의 밑줄 안내는 표시하지 않는다.
- ‘원문 비교’를 펼치면 전체 원문을 먼저, 전체 교정안을 아래에 표시한다. 문장별로 번갈아 배치하지 않는다. 비교 본문은 15px로 읽을 수 있게 하고 ‘원문 비교’ 조작 영역의 높이는 최소 44px로 둔다.
- 비교 안에서는 실제 문자열 차이를 변경된 표현 단위로 묶어 강조한다. 원문의 삭제·교체 표현은 연한 빨간 배경과 취소선, 교정안의 추가·교체 표현은 연한 보라 배경과 밑줄로 구분한다. 변경과 관계없는 부분은 일반 글씨로 유지한다.
- 띄어쓰기 변경도 공백 하나 대신 주변 표현을 함께 표시한다. 예를 들어 `안녕 하세요 → 안녕하세요`는 양쪽 표현을 각각 강조한다. 강조 범위에는 비교를 돕기 위한 동일한 글자도 포함될 수 있으며, 강조된 글자 모두가 삭제·추가되었거나 틀렸다는 뜻은 아니다.
- 비교 영역 상단에는 원문과 교정안의 변경 표현을 구분하는 짧은 범례를 둔다. 좁은 화면에서는 범례가 여러 줄로 배치될 수 있다.
- 공백·줄바꿈·탭을 점·화살표 등의 작은 기호로 치환하지 않는다. 공백만 달라져도 인접 표현과 함께 강조해 위치를 찾도록 하며, 실제 공백과 줄 구조는 그대로 표시한다. 비교 본문의 복사와 후보 적용에는 원래 텍스트를 사용한다.
- 비교 계산에 실패한 후보도 상단 완성 문장을 유지한다. 비교 안에는 원문·후보와 직접 비교 안내를 표시하며 변경 범례는 표시하지 않는다. 같은 비교 규칙을 읽기 전용 교정 이력에도 적용한다. 사용자 이해도 개선 효과는 별도 검증 대상이다.
- 변경 표시와 문법적 정답·사용자 의도 보존은 다르다. ‘더 좋은 후보’라는 평가 배지를 자동으로 붙이지 않는다.
- 표현별 설명을 받은 경우 색칠된 변경 표현 자체를 클릭 대상으로 사용한다. 번호 배지와 번호 선택줄은 표시하지 않는다. 원문·교정안에서 같은 변경 묶음을 함께 강조하되, 원래 빨간 취소선·보라 밑줄을 유지하고 현재 선택에만 더 진한 배경·윤곽을 추가한다. hover는 선택 강조보다 약하게 표시한다.
- 변경 표현에는 커서·키보드 포커스 표시와 ‘변경 표현을 눌러 이유를 확인’하는 짧은 안내를 제공한다. 추가·삭제로 한쪽에 표현이 없는 경우에는 존재하는 표현에서 선택한다. 원문·교정안의 텍스트 드래그·복사를 방해하지 않는다.
- 위 클릭 동작은 표현별 설명을 받아 이유를 표시하는 동안에만 활성화한다. 이유가 닫혀 있거나 전체 설명만 있는 후보는 기존 변경 색상으로 비교하며, 클릭 가능한 것처럼 표시하지 않는다.

### 교정 이유

- 결과 제목 오른쪽의 ‘교정 이력’ 아래에 말풍선 아이콘과 ‘교정 이유’ 버튼을 둔다. 열고 닫아도 이름은 ‘교정 이유’로 유지하며 ‘보기’·‘접기’를 붙이지 않는다.
- 버튼은 현재 후보 전체의 설명 표시를 켜고 끈다. 설명은 각 후보 바로 아래에 나타나 해당 후보와 대응된다.
- 닫힘은 연한 배경·보라색 글자와 테두리, 열림은 보라색 채움·흰 글자로 표시한다. `aria-expanded`로 현재 열림 상태도 전달한다. 받은 설명의 존재나 과거 클릭 여부가 아닌 현재 표시 상태를 기준으로 하며, hover는 열림보다 약하게 표시한다.
- 기본 상태는 닫힘이다. 처음 열 때 설명을 요청하며, 설명 로딩 중에도 후보 적용은 가능하다.
- 이유를 열어 본 상태에서 재교정이 성공하면 새 후보의 설명 자리에 로딩 안내를 표시하고 새 설명을 자동으로 이어서 생성한다. 적용 전 카드 재교정은 해당 후보만 생성하며 다른 후보 설명은 유지한다. 적용 후 재교정은 새 원문으로 받은 3개 후보의 설명을 새로 생성한다. 이유가 닫혀 있으면 자동 생성하지 않고 다음 열기에서 요청한다. 자동 생성 실패는 같은 설명 상태 영역의 수동 재시도로 연결하며 반복 자동 재시도하지 않는다.
- 같은 유효 묶음에서 후보를 적용하거나 다른 후보로 바꿔도 받은 설명과 진행 중 설명 요청을 유지한다. 직접 원문 편집·다른 대상 선택·선택 해제·Undo/Redo·새 결과 묶음에서는 이전 설명을 무효화한다.
- 표현별 설명은 한 번에 하나의 변경을 보여준다. ‘교정 이유’ 오른쪽에는 `현재 순서 / 전체 개수`를 두고, 본문에는 번호 없는 제목·원문·교정안·이유를 표시한다. 추가 확인이 필요한 내용은 응답에 있는 경우에만 별도로 안내하며 미리 준비한 주의사항을 모든 후보에 붙이지 않는다. 하단은 이전·다음만 두고 ‘번호를 눌러 바로 이동’ 안내를 표시하지 않는다.
- 설명 영역과 본문은 내용에 따라 자연스럽게 늘고 줄어든다. 고정 높이·최소 높이로 짧은 설명 아래에 빈 공간을 만들지 않으며, 좁은 화면에서는 전후 표현과 설명이 패널 안에서 줄바꿈한다.
- 변경 표현 클릭·Enter·Space로 설명을 선택할 때 설명 제목과 선택 내용 시작 부분이 화면 밖이면 해당 설명으로 스크롤하고 제목에 포커스를 옮긴다. 이미 보이면 화면 위치를 유지하며 내용만 바꾼다. 응답 도착이나 이전·다음으로 설명을 바꾸는 동작에는 자동 스크롤을 추가하지 않는다.
- 원문 비교·이유를 접고 다시 펼쳐도 같은 후보의 선택한 변경을 유지한다. 새 후보로 교체되면 변경 선택은 초기화한다. 선택 강조와 키보드 포커스 표시는 구분하며, 스크린리더에는 변경 순서·제목·선택 상태를 전달한다.
- 표현별 자료가 없는 과거 이력·응답은 후보 전체 설명을 그대로 제공한다. 이 경우 변경 표현에 연결된 이유가 있는 것처럼 안내하거나 탐색 버튼을 만들어 표시하지 않는다.
- 후보별 형식·인용 검사 실패는 해당 카드에 안내하고 정상 설명은 유지한다. 설명 상태 영역의 ‘실패한 설명 다시 시도’는 실패한 후보만 요청한다. 전부 실패한 경우도 명시하며 후보 비교·적용은 유지한다. 요청 전체의 통신·ID 오류에는 일반 실패 안내와 ‘설명 다시 시도’를 표시한다. 부분 실패 후 재요청 자체가 실패해도 기존 정상 설명은 보존한다.
- 원문 비교는 실제 문자열 차이 표시이며, 교정 이유는 LLM 설명이다. 두 조작의 이름과 내용을 구분한다.

### 교정 이력 — 11/21 후속

기존 이력 목록과 동작을 오른쪽 패널에 재사용한다. ‘교정 이력’으로 전환하고 ‘뒤로’로 현재 교정 화면에 돌아온다. 화면 전환 자체로 원문·선택·후보·펼친 비교·설명 또는 진행 중 요청을 초기화하지 않는다. 원문 편집·선택 변경으로 인한 결과 무효화는 기존 규칙을 따른다.

이력 제목·뒤로·JSON 내보내기·전체 삭제는 목록 스크롤 바깥에 두며 좁은 화면에서는 버튼 줄바꿈을 허용한다. 목록은 날짜·선택 원문 미리보기·후보 수·당시 적용 기록을 표시하고, 펼치면 선택 원문, 읽기 전용 후보/원문 비교, 저장된 설명과 실패를 볼 수 있다. 본문 글자 크기는 유지하고 긴 문장과 URL은 패널 폭 안에서 줄바꿈한다. 현재 작업의 후보 적용 버튼과 과거 이력은 구분한다. 전체 글을 자동 복원하는 기능은 아니다.

JSON 내보내기에 문장 내용이 포함됨을 안내한다. 개별/전체 삭제 및 손상 저장소 초기화는 확인한 뒤 수행한다. 저장 실패·메모리 전용·손상 상태는 숨기지 않고 내보내기·재시도·초기화 중 가능한 행동을 표시한다. 키보드로 목록을 열고 비교할 수 있으며 삭제 뒤 포커스는 이력 제목으로 돌린다. 설명이 저장되지 않은 후보는 새로 생성하지 않고 해당 상태를 알려준다.

현재 교정 화면에서도 이력 저장 문제가 있으면 짧은 상태 안내와 이력 화면으로 이동할 경로를 표시한다. 정상 저장 안내와 상세 저장 안내는 이력 화면에서 확인한다. 이력으로 이동하면 뒤로가기 버튼에, 뒤로 돌아오면 ‘교정 이력’ 버튼에 포커스를 둔다.

### 11/21 요구 재교정과 행동 기록

11/21 최초 구현은 결과 또는 적용 직후 같은 선택에 ‘다시 다듬기’ 영역과 드롭다운을 표시했다. 11/22 진입 배치와 11/23 후보별 수정·위치 유지 변경은 [아래 설계](#rerun-entry-plan)를 따른다. 카드에서는 해당 후보만 다듬고, 적용 후에는 방금 적용한 문장으로 후보 3개를 다시 만든다는 차이를 안내한다. 요구 목록은 선택 사항이며 별도 재교정 확인 팝업을 더하지 않는다. 최초 교정도 #64부터 확인창 없이 시작하고 근처 드래그 버튼은 유지한다.

작업 공간 아래의 행동 기록 패널에 참여자 코드·기록 범위·요구별 고유 요청 통계·JSON/CSV 내보내기를 둔다. 문장 포함은 기본 해제하며 삭제한 이력의 내용은 내보내지 않는다고 안내한다. 행동 기록 삭제와 교정 이력 삭제를 구분한다. 적용 건수는 만족도가 아니고, 참여자 코드는 로그인 계정이 아님을 명시한다.

### 11/22~23 재교정 진입·요구 선택과 후보별 수정 — 구현

[#62](https://github.com/dhwjdgh1122/writing-demo/issues/62)에서 분리된 동작 시안의 선택 버튼 방식을 채택한 뒤 제품에 옮겼다. 11/23 실제 화면 검토에서는 후보 3에서 실행해도 첫 카드로 이동하고 후보 전체가 바뀌는 문제를 확인해, 실행한 후보만 수정하고 그 위치를 유지하도록 보완했다. 아래는 최종 설계이며 구현·병합 근거는 [PR #63](https://github.com/dhwjdgh1122/writing-demo/pull/63)과 검증 기록을 따른다.

| 상태 | 확정한 배치 |
|---|---|
| 후보 적용 전 | 각 후보 카드의 ‘이 문장 적용’ 아래 같은 폭·높이·모서리의 ‘다시 교정하기’를 세로로 배치 |
| 후보 적용 후 | 적용한 카드의 같은 위치에 같은 폭·높이·모서리의 ‘다시 교정하기’를 유지. 다른 카드의 재교정은 비활성화하고 먼저 해당 후보로 바꾸도록 안내 |
| 선택 영역 닫힘 | 큰 상시 요구 패널 없이 진입 버튼만 표시 |
| 선택 영역 열림 | 누른 버튼 아래 질문·기준 문장 안내·단일 선택 버튼들·‘교정 시작’을 인라인 표시 |

- 질문은 ‘이번에는 어떤 점을 바꾸고 싶나요?’로 하고 선택 사항임을 알린다. 기존 5개 요구와 ‘선택 안 함’을 버튼 모양의 단일 선택지로 제공한다. 선택한 항목은 색뿐 아니라 선택 표시로도 구분하며 키보드 조작을 지원한다.
- 한 번에 하나의 선택 영역만 연다. 적용 전 다른 후보의 버튼을 누르면 이전 영역은 닫고 선택한 요구는 유지한다. 같은 후보 묶음에서 닫았다 다시 열어도 선택은 그대로다. 적용 전에는 ‘이 후보만 다시 다듬으며 다른 후보는 유지’됨을, 적용 후에는 ‘현재 적용 문장으로 후보 3개 생성’임을 안내한다. 해당 묶음의 생성 원문은 비교 기준으로 보존하며 실제 적용 범위는 현재 문서에서 검사한다.
- 펼침과 요구 선택은 실행이 아니다. 별도 ‘교정 시작’에서 요청하고, 재교정 확인 팝업을 추가하지 않는다. 좁은 패널에서는 선택지를 줄바꿈해 문구와 터치 영역을 유지한다.
- 처음의 일반 교정 실행·드래그 버튼은 유지한다. 원문 비교는 해당 묶음의 생성 원문과 현재 후보를 비교하며, 새 후보의 설명·이력·행동은 그 후보를 만든 요청에 연결한다. 적용 전 1개 수정과 적용 후 3개 생성 모두 같은 자리의 비교 열림·닫힘을 유지하고 비교 내용은 새 기준으로 갱신한다. 이유가 열려 있으면 새 후보 설명을 그 자리에서 자동 생성한다. 바뀌지 않은 카드의 기존 설명과 펼친 비교는 유지한다.

**재교정 실패 안내와 재시도 위치:** 재교정을 시작한 선택 영역 안에 오류를 표시하고, 같은 위치의 ‘교정 시작’을 ‘다시 시도’로 바꾼다. 실패 때문에 별도 화면이나 멀리 떨어진 버튼으로 이동하게 하지 않는다.

| 상태 | 화면과 버튼 |
|---|---|
| 요청 중 | 기존 후보·펼친 비교·받은 설명과 선택 영역을 유지하고 ‘교정 시작’을 진행 중 상태로 표시한다. 중복 실행·후보 적용·새 설명 요청은 잠시 비활성화한다. |
| 실패 | 기존 후보와 선택한 요구를 유지한다. 실행 버튼 위에 오류 안내를 표시하고 같은 자리에 ‘다시 시도’를 제공한다. |
| 카드 재교정 성공 | 실행한 자리의 후보 1개만 교체하고 원문 비교 열림·닫힘을 유지한다. 열린 이유는 새 후보 설명 로딩·결과로 이어지며 다른 카드의 문장·설명·비교는 유지한다. 요구 선택 영역만 닫고 다음 요청은 ‘선택 안 함’에서 시작한다. |
| 적용 후 재교정 성공 | 적용한 현재 문장을 새 원문으로 받은 후보 3개를 표시하고 선택 영역을 닫고 초기화한다. 같은 자리의 비교 열림·이유 표시 상태만 유지하고 이전 적용 표시·설명·선택한 변경은 초기화한다. 열린 이유는 새 후보 3개의 설명 로딩·결과로 이어 주며 닫혀 있으면 다음 열기까지 기다린다. 새 후보를 적용하기 전까지 원문 작업 공간의 문장은 바꾸지 않는다. |
| 적용 후 | 적용 카드 안의 선택 영역에서 같은 요청 중·실패·재시도 표시를 사용한다. 기존 후보 3개·적용 표시·비교·설명은 유지하고, 실패해도 이미 적용된 문장을 바꾸지 않는다. |

통신 실패 안내 예시는 ‘새 교정안을 불러오지 못했습니다. 선택한 요구를 유지했습니다.’다. 오류 유형별 기존 원인 안내와 실행 가능 조건은 유지하며 설정·길이 제한 때문에 실행할 수 없는 상태를 단순 재시도로 해결할 수 있다고 안내하지 않는다. 요청 중 후보는 이전 결과임을 구분하고, 문서 편집·선택 변경으로 무효화되면 보존 화면도 해제한다.

**선택 유지와 성공 후 초기화:** 같은 후보 묶음 안의 이동·닫기·다시 열기는 선택값을 유지한다. 새 유효 결과를 표시할 때 선택 영역을 닫고 다음 요청의 선택만 초기화한다. 방금 결과를 만든 요구와 이력·행동 기록·설명 입력은 보존한다. 실패하면 영역과 선택을 유지하며, 적용 후 재교정도 성공 시 같은 규칙을 따른다.

**실행한 위치와 포커스:** 후보 3에서 실행하면 후보 3의 위치를 유지하고 같은 자리의 ‘다시 교정하기’로 포커스를 연결한다. 후보 1로 강제 이동하지 않는다. 실패 뒤에는 같은 영역의 ‘다시 시도’로 연결하며 스크롤을 강제로 이동시키지 않는다. 대기 중 사용자가 스크롤하거나 다른 영역으로 포커스를 옮기면 성공·실패 후 화면과 포커스를 되돌리지 않는다. 키보드 기본 라디오 동작과 320px 화면 줄바꿈을 지원한다. [대상·요청·검증 조건](FEATURE_SPEC.md#rerun-entry-plan)은 기능명세에서 관리한다.
