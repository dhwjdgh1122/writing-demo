# 검증 기록

> 역할: 사용자 공유 결과·실제 API 점검·자동 검증·설치 확인의 근거와 한계를 보존한다. 교정 품질과 설명 정확성, 기능 동작과 사용자 효과를 구분한다. 실행·검증 명령은 [README](../README.md)에서 확인한다. 개선 의견·질문은 [사용자 피드백](사용자%20피드백.md), 협업 현황·작업 상태는 [TASKS](TASKS.md)에서 관리한다.

## 기록 기준

- 초기 기록일: 2026-11-07. 후속 기록일·근거는 각 항목에 표시한다. 사용자 공유 결과의 실행 시각은 별도로 전달받지 않았다. 직접 수행한 점검은 각 항목의 기록을 따른다.
- 같은 문장을 다시 실행해도 별도 기록으로 남긴다. 앞선 실행의 후보나 설명을 다음 실행에 연결하지 않는다.
- 사용자 공유 텍스트·화면에서 확인한 사실과 평가를 구분한다. 화면에 보이지 않는 설명은 미확인으로 기록한다.
- 사용자 공유 결과의 모델·환경은 전달받은 범위만 기록한다. 초기 공유 결과는 Gemini 3.5 Flash-Lite 설정으로 전달받았으며, 실행별 모델명·요청 ID·응답 시간은 별도 로그로 확보하지 않았다. 직접 수행한 API 점검의 모델·시간 등은 해당 항목과 연결된 자료에서 확인한다.
- 일부 예문의 성공·실패를 전체 모델 품질이나 사용자 효과에 대한 결론으로 일반화하지 않는다.

## NUM-01 — 숫자 포함 문장, 첫 공유 실행

**근거:** 사용자가 채팅에 붙여 넣은 후보 3개와 각 교정 이유. 이 기록에서의 ‘첫 실행’은 최초 공유 결과를 뜻하며, 그 이전 실행 횟수는 확인하지 않았다.

**제시했던 테스트 원문:**

> 신청자는 총 15명 이며, 이중 3명은 아직 결재를 하지 않앗습니다.

첫 실행의 입력 화면은 공유되지 않았다. 위 문장은 앞서 제시한 테스트 예문이며, 아래 후보·설명은 오정호가 제공한 실행 결과 그대로 기록한다.

### 후보 1

> 신청자는 총 15명이며, 이중 3명은 아직 결재를 하지 않았습니다.

**출력된 교정 이유:**

> 원문의 맞춤법 오류인 '이 며'와 '않앗습니다'를 각각 '이며', '않았습니다'로 올바르게 수정하였습니다. 의미나 조건의 변화 없이 문법적 정확성만 높아졌습니다.

- 교정 평가: 제시한 테스트 원문과 비교하면 `15명 이며 → 15명이며`, `않앗습니다 → 않았습니다`가 수정됐다. `이중`은 남았고 숫자 15명·3명은 유지됐다.
- 설명 평가: 설명의 인용 `이 며`는 제시했던 원문 `15명 이며`의 실제 오류 위치와 맞지 않는다. 실제 입력 원문을 함께 확보하여 확인할 필요가 있다. ‘문법적 정확성만 높아졌다’는 평가보다 구체적인 변경을 기술하는 편이 명확하다.

### 후보 2

> 신청자는 총 15명 이며, 이 중 3명은 아직 결재를 하지 않았습니다.

**출력된 교정 이유:**

> 원문의 오타인 '않앗습니다'를 '않았습니다'로 고치고, '이중'을 띄어쓰기에 맞는 '이 중'으로 수정하였습니다. 다만 '15명 이며'의 띄어쓰기 오류는 그대로 남아 있습니다.

- 교정 평가: `이중 → 이 중`, `않앗습니다 → 않았습니다`는 수정됐으나 `15명 이며`는 남았다. 숫자 15명·3명은 유지됐다.
- 설명 평가: 수정된 부분과 남은 띄어쓰기 오류를 함께 짚었다. 제공된 결과와 부합하는 설명이다.

### 후보 3

> 신청자는 총 15명이며, 이 중 3명은 아직 결재를 하지 않았습니다.

**출력된 교정 이유:**

> 원문의 '15명 이며', '이중', '않앗습니다'를 각각 '15명이며', '이 중', '않았습니다'로 모두 올바르게 수정하였습니다. 맞춤법과 띄어쓰기가 정확하게 교정되었습니다.

- 교정 평가: 제시했던 띄어쓰기와 오타는 수정됐고 숫자 15명·3명은 유지됐다. `결재`는 그대로다.
- 설명 평가: 나열한 세 가지 수정은 후보에 반영됐다. 다만 ‘맞춤법과 띄어쓰기가 정확하게 교정되었습니다’는 결과 전체의 정확성을 보증하는 표현으로 읽힐 수 있어, 확인 가능한 변경을 중심으로 설명하도록 보완할 필요가 있다.

### 공통 관찰과 해석 한계

- 세 후보 모두 `결재`를 유지했다. 예문을 제시할 때 의도한 의미는 돈을 내는 ‘결제’였지만, 원문에는 참가비 등 금전 정보가 명시되지 않았다. 따라서 이 사례만으로 문맥이 명확한 결제 표현도 교정하지 못한다고 단정하지 않는다.
- 후보별로 일부 오류가 남는 차이가 나타났다. 설명은 후보 2에서 미수정 오류를 짚었으나 후보 1의 인용과 후보 3의 포괄적인 정확성 평가에는 검토할 부분이 있다.
- 숫자 보존은 확인했지만, 숫자가 바뀐 후보를 설명이 발견하는 능력은 이번 실행으로 확인하지 못했다.
- 후보 적용 여부와 실행 시간은 미확인이다.

## NUM-02 — 숫자 포함 문장, 재실행 공유 결과

**근거:** 사용자가 ‘다시 실행’했다고 알리며 첨부한 원문 비교 화면. 화면에서 후보 1을 확인했다. 전체 후보 개수는 단정하지 않는다.

**화면의 원문:**

> 신청자는 총 15명 이며, 이중 3명은 아직 결재를 하지 않앗습니다.

원문 비교 화면의 점(·)은 공백 표시이며 원문에 입력된 문장부호로 옮기지 않았다.

**화면의 후보 1:**

> 신청자는 총 15명이며, 이중 3명은 아직 결재를 하지 않았습니다.

**교정 평가:**

- `15명 이며 → 15명이며`, `않앗습니다 → 않았습니다`로 수정됐다.
- 숫자 15명·3명과 아직 처리하지 않았다는 상태는 유지됐다.
- `이중`의 띄어쓰기와 예문 작성자가 의도한 ‘결제’ 표현은 반영되지 않았다. `결재`에 대한 문맥 부족의 한계는 NUM-01과 같다.
- ‘삭제된 내용 있음’ 안내와 원문 비교 화면이 표시됐다. 이는 문자열 변경 표시이며, 이 안내만으로 중요한 정보가 누락됐다고 판단하지 않는다.

**설명 평가: 미확인.** 첨부 화면에 교정 이유가 보이지 않는다. 설명을 생성하지 않았는지, 접었는지, 화면 밖에 있는지는 확인하지 않았다. NUM-01의 후보 1과 문장이 같더라도 그때의 설명을 이번 실행의 설명으로 옮기지 않는다.

**적용 여부·응답 시간:** 미확인.

## 후속 확인할 항목

- 결제 의미를 명시한 예문: `신청자는 총 15명 이며, 이중 3명은 아직 참가비를 결재하지 않앗습니다.` 이 예문은 제안만 했으며 실행 결과는 아직 전달받지 않았다.
- 재실행에서 설명을 열었다면 그 실행의 원문·후보·설명을 함께 확보하여 별도로 기록한다.
- 교정 후보의 완성도, 설명의 인용 정확성, 과도한 품질 단정을 구분해 점검한다. NUM-01~02 작성 당시에는 코드·프롬프트를 수정하지 않았다. 이후 수정과 비교 결과는 아래에 별도로 기록한다.

### EXP-01 — NUM-01의 원문·후보 고정 비교

NUM-01에 기록한 세 후보와 제시했던 테스트 원문을 사용했다. 당시 사용자 실행의 입력·샘플링을 완전히 재현한 실험은 아니다.

| 항목 | 이전 지침의 이번 출력 | 수정 지침의 이번 출력 | 평가 |
|---|---|---|---|
| 후보 1 | ‘띄어쓰기 오류와 맞춤법 오류’를 고쳐 ‘가독성을 높였다’고 설명 | `15명 이며 → 15명이며`, `않앗습니다 → 않았습니다`를 인용 | 구체적인 수정 위치가 드러남 |
| 후보 2 | 수정된 부분과 `15명 이며`의 미수정을 함께 설명 | `이중 → 이 중`, `않앗습니다 → 않았습니다`를 설명 | 실제 수정은 정확하나 남은 오류 안내는 사라짐. 모든 면에서 좋아졌다고 보지 않음 |
| 후보 3 | ‘원문의 의미를 정확하게 유지하면서 규범에 맞게 다듬었다’고 평가 | 세 가지 변경을 각각 원문·수정 표현으로 인용 | 변화 설명이 구체화됨. ‘맞춤법을 바로잡았다’는 평가 표현은 여전히 있음 |

- 이번 수정 지침의 인용 문자열은 입력 원문·각 후보와 일치했다. `결재`가 `결제`로 바뀌었다는 허위 설명은 없었다.
- NUM-01에서 관찰한 `이 며` 인용 오류는 이번 이전 지침 호출에서도 재현되지 않았다. 따라서 이 오류가 수정 지침 때문에 사라졌다고 단정하지 않는다.
- 호출 소요 시간: 이전 1,881ms, 수정 2,535ms. 단일 측정값이며 속도 우열의 근거로 삼지 않는다.

### EXP-02 — 새 예문, 등록비 결제 표현

**원문:** `참가자 8명중 2명은 등록비를 아직 결재하지 않앗습니다.`

**고정 후보:**

1. `참가자 8명 중 2명은 등록비를 아직 결제하지 않았습니다.`
2. `참가자 8명 중 2명은 등록비를 아직 결재하지 않았습니다.`

두 후보는 개발자가 시험을 위해 작성했으며, Gemini 교정 기능이 생성한 결과가 아니다. 이 원문·후보를 새 지침 안에 예시로 넣지는 않았다.

**이전 지침:** 후보 2에서 ‘맞춤법 오류인 결재와 않앗습니다를 수정하였으나, 여전히 결재를 사용’이라고 설명했다. 바뀌지 않은 `결재`를 수정했다고 말하는 모순이 있다.

**수정 지침:** 후보 1의 `결재하지 → 결제하지`, 두 후보의 띄어쓰기·오타 변경을 정확하게 인용했다. 후보 2의 `결재`가 그대로라는 점도 구분했다. 그러나 아래 문장이 남았다.

> 다만 '결재'라는 표현은 그대로 유지되어 의미 변화에 영향을 줍니다.

**평가: 부분 개선, 문제 잔존.** 그대로인 표현을 수정했다고 말하는 오류는 이번 출력에서 없어졌지만, ‘의미 변화에 영향을 준다’는 설명은 무엇이 달라졌다는 뜻인지 불명확하다. 유지된 단어의 문제와 원문 대비 의미 변화를 혼동할 수 있다. 후보 1의 ‘날짜나 숫자 등 핵심 정보’ 중 날짜는 입력에 없어 불필요한 일반론이다.

호출 소요 시간: 이전 1,328ms, 수정 1,500ms.

### EXP-03 — 새 예문, 기한·조건·숫자·확정 여부

**원문:** `담당자의 확인을 받은 경우에만 화요일까지 8명에게 자료를 보낼 예정이며, 발송은 확정되지 않았습니다.`

개발자가 시험용 후보를 직접 작성했다. 후보 1은 `화요일까지`를 `추후`로 바꾸고, 후보 2는 `화요일까지 10명에게 자료를 발송합니다.`로 바꿨다. 후보 3은 원문과 동일하다.

- 후보 1: 이전 지침은 ‘안내 날짜’, 수정 지침은 ‘자료를 보낼 시점’이 불명확해졌다고 설명했다. 둘 다 구체적 기한의 소실을 짚었으며 수정 지침의 표현이 입력의 발송 상황에 더 맞는다.
- 후보 2: 양쪽 모두 확인 조건과 미확정 상태의 소실을 짚었다. 이전 지침은 인원이 바뀌었다고만 했고, 수정 지침은 10명을 언급했지만 **8명에서 10명으로 바뀐 점을 명시적으로 설명하지 않았다.** 숫자 변화 설명의 구체성은 보완할 여지가 있다.
- 후보 3: 코드가 원문 동일 안내로 처리했다. LLM 성과 판정에서는 제외한다.

호출 소요 시간: 이전 1,345ms, 수정 2,524ms.

### 비교 결론과 남은 확인

- 정확한 인용과 후보별 실제 변경을 중심으로 설명하는 결과가 관찰됐다. 동시에 유지된 표현을 두고 의미 변화를 모호하게 설명하거나 숫자 변화의 전후 값을 생략하는 문제가 남았다.
- 각 조건을 한 번씩만 호출했으므로 모델 출력의 변동성과 지침 효과를 분리할 수 없다. 반복 실험·독립 평가자·사용자 효과 평가는 수행하지 않았다. 전반적인 오류율이 줄었다고 주장하지 않는다.
- 이번 비교 후 추가로 지침을 재수정하지 않았다. 성공한 결과만 고르거나 원본 출력을 다듬어 저장하지 않았다.
- 코드 확인: 타입 검사 통과, 기존 자동 테스트 32개 통과. 지침과 비교 도구만 수정했으므로 브라우저 테스트는 재실행하지 않았다.

## SPACE-01 — 오타 문장의 두 후보와 공백 인용 오류

**기록일:** 2026-11-07. 사용자가 원문과 함께 첨부한 후보 2개·설명 화면을 기록했다. 정확한 실행 시각·요청 ID·실행 당시 서버의 지침 버전은 별도로 확보하지 않았다.

**원문:** `금요일까지 자료를 보내 주세여.`

### 후보 1

> 금요일까지 자료를 보내 주세요.

**화면의 교정 이유:**

> 원문의 오타인 '보내 주세여'를 '보내 주세요.'로 수정하여 맞춤법을 바르게 고쳤습니다.

- `주세여 → 주세요`로 수정했고 `보내` 뒤 공백은 유지됐다. 금요일까지라는 기한도 유지됐다.
- 인용 범위에 마침표 포함 여부의 차이는 있지만, 인용한 두 표현은 각각 실제 원문과 후보에 있다.

### 후보 2

> 금요일까지 자료를 보내주세요.

**화면의 교정 이유:**

> 원문의 오타인 '보내 주세여'를 '보내 주세요.'로 수정하면서 '보내다'와 '주다'를 붙여 썼습니다.

- 오타 수정과 함께 `보내` 뒤 공백이 삭제됐다.
- 설명은 수정 표현을 `보내 주세요.`로 인용했지만 실제 후보는 `보내주세요.`다. 해당 인용은 원문에도 이 후보에도 존재하지 않는다. 다른 후보에 있다고 해서 이 후보의 정확한 인용으로 볼 수 없다.
- ‘붙여 썼다’는 설명은 실제 변경과 맞지만, 인용 표기는 그 설명과 모순된다. 앞선 지침 보완 이후에도 관찰된 인용 오류 사례로 남긴다. 다만 실행 서버의 지침 버전을 로그로 검증한 것은 아니다.
- `보내다`·`주다`는 설명에 사용된 기본형이며 원문·후보의 문자 그대로의 인용은 아니다.

**개수에 관한 사용자 관찰:** 같은 문장에서 어떤 실행은 후보 1개, 이번에는 2개가 나왔다. 현재 최대 3개·최소 1개 설계에서는 개수 변동 자체를 오류로 보지 않는다. 각 실행의 다른 후보·설명을 합치지 않는다.

## GUARD-01 — 인용 불일치 표시 차단 추가

**변경:** 설명 API에서 인용 문자열을 공백까지 대조하는 검사를 추가했다. 형식과 후보 ID가 맞아도, 닫힌 한 줄 인용이 원문과 해당 후보 어느 쪽에도 없으면 설명 묶음을 반환하지 않는다. `EXPLANATION_QUOTE_MISMATCH` 안내와 기존 ‘설명 다시 시도’ 버튼을 사용한다. 후보와 원문은 유지하고 자동으로 다시 호출하지 않는다. 모델·교정 지침·설명 생성 지침은 이번 단계에서 바꾸지 않았다.

**검증 결과:**

- `보내주세요` 후보를 `보내 주세요`라고 인용한 경우 차단됨. 다른 후보에 `보내 주세요`가 있어도 통과하지 않음.
- `이 며`처럼 없는 원문 인용, 잘못된 공백 개수·줄바꿈 인용을 차단하고 올바른 인용·이모지는 허용하는 자동 테스트 통과.
- HTTP API는 인용 불일치 시 502와 오류 코드를 반환하고 설명을 노출하지 않음. 테스트 응답으로 수동 재시도 성공과 후보 유지 확인.
- 타입 검사 및 자동 테스트 **36개 통과**. 설명 관련 Edge 브라우저 테스트 **7개 통과**. 브라우저에서는 오류 응답을 주입하여 설명 미표시·후보 적용 가능·설명만 재요청됨을 확인했다. 실서비스 후보·설명 생성 성공으로 계산하지 않는다.
- EXP-01~03의 저장된 설명 16개에도 새 검사를 적용했으며 모두 통과했다. 그 안에는 앞서 기록한 의미 설명 오류도 포함된다. 인용 검사의 통과를 의미 설명의 정확성으로 해석해서는 안 된다.
- 이 단계에서는 추가 외부 API 호출 없이 저장된 결과와 테스트 응답으로 검증했다.

**한계·추후 확인:**

- 원문·후보에 실제로 존재하는 표현이라도 수정 전후를 반대로 말하는 오류는 잡지 못한다. 따옴표 없는 의미 설명·문법 판단도 검증하지 않는다.
- 검사 대상은 닫힌 한 줄의 작은따옴표·큰따옴표·곡선 따옴표·낫표·겹낫표·백틱 인용이다. 여러 줄·닫히지 않은 인용·중첩 인용은 완전하게 다루지 않는다.
- 기본형·문법 용어 등을 따옴표로 감싼 유용한 설명도 실제 문자열에 없으면 거절될 수 있다. SPACE-01의 `보내다`·`주다`도 이 제한에 해당한다. 한 후보의 오류로 현재 설명 묶음 전체를 숨기는 방식이므로, 향후 거절 빈도와 사용자 부담을 함께 확인해야 한다.
- 이는 잘못된 설명의 노출을 일부 막는 장치이며 모델 학습이나 교정 품질 개선은 아니다. 재시도에서도 같은 문제가 발생할 수 있다.

## HANDOFF-01 — 공유 전 설치·실행 점검

HANDOFF는 팀에 프로젝트를 전달하기 위한 점검 식별자다. 수작업 여부를 뜻하지 않는다.

**기록일:** 2026-11-07. 협업 전달 전 설치·핵심 흐름·공유 대상 파일을 확인했다. 점검 대상은 기존 구현이며 제품 실행 코드·모델 설정·프롬프트를 바꾸지 않고 수행했다.

### 독립 설치·실행 확인

- 기존 프로젝트에서 소스·문서·잠금 파일·설정 예시만 별도 임시 폴더로 복사했다. 기존 node_modules·dist·.env·테스트 생성물·상위 개인 자료는 복사하지 않았다.
- 같은 Windows 컴퓨터의 Node 20.12.2 환경에서 `npm.cmd ci --no-audit --no-fund`로 150개 패키지를 설치했다. 새로운 컴퓨터나 팀원 환경에서 확인한 것은 아니다.
- `npm.cmd test`: **36개 통과**.
- `npm.cmd run build`: TypeScript 검사와 Vite·서버 빌드 **통과**.
- `npm.cmd run test:browser`: Edge 브라우저 **15개 모두 첫 실행 통과**. 실제 외부 모델 응답을 사용하는 테스트가 아니며, 주입한 응답으로 후보·설명·오류 처리를 확인했다.
- 빌드 결과를 `npm.cmd start`로 5182번 포트에 실행했다. health HTTP 200·modelConfigured false와 페이지 표시를 확인했다. 키 없는 상태에서 교정 요청 시 미설정 안내가 나타나고 원문이 유지됨을 브라우저에서 확인했다.
- 설치된 기존 Edge와 npm 캐시를 사용할 수 있는 같은 컴퓨터의 검증이다. 다른 OS·한국어 IME 수동 입력·팀원별 API 접근은 미검증이다.
- 빌드 시 Zod 의존성의 주석 표기 경고가 발생했으나 빌드는 성공했다. 기존 개발 서버와 동시 실행한 브라우저 테스트에는 Vite 자동 새로고침 포트(24678) 충돌 경고가 있었으나 15개 테스트는 통과했다. 개발 서버 종료 후 테스트하도록 실행 안내에 덧붙였다.
- 패키지 보안 감사는 이번 설치 명령에서 수행하지 않았다.

### 실제 모델·시연 화면 확인

기존 개발 서버에서 직접 작성한 예문으로 교정 1회·설명 1회를 호출했다. 둘 다 HTTP 200으로 성공했으며 자동 재시도·모델 변경은 하지 않았다. API 키를 출력하거나 임시 복사본에 복사하지 않았다.

**원문 전체:**

```text
안녕하세요.
금요일까지 자료를 보내 주세여.
감사합니다.
```

가운데 문장만 선택했다.

- **교정 후보 1개:** `금요일까지 자료를 보내 주세요.`
- **교정 이유:** 원문의 오타인 '보내 주세여'를 '보내 주세요'로 수정하여 맞춤법을 바르게 고쳤습니다.
- 오타 변경과 설명의 인용이 실제 원문·후보에 대응함을 확인했다. 기한과 요청 내용은 유지됐다.
- 후보 적용 후 앞뒤 인사·맺음말은 보존되고 이전 후보·설명이 닫혔다.
- 단순 오타 한 건의 성공이다. 후보 간 비교 품질이나 의미 변화 설명 전반·사용자 효과를 입증한 것은 아니다. 기존 설명 오류 사례는 여전히 해결 과제다.

[시연 안내](DEMO_GUIDE.md)에 실제 실행 화면 4개와 별도 키 없는 환경 화면 1개를 연결했다. [요청·응답 기록](demo/2026-11-07/capture-record.json)도 보존했다. 사진 상단의 출처 표시는 촬영 세션에만 추가했으며 제품 화면을 수정하지 않았다. 영상은 촬영하지 않았다.

### 당시 남은 작업

아래는 HANDOFF-01 점검 당시의 기록이다. 이후 상태는 [TASKS](TASKS.md)와 후속 기록에서 확인하며, 과거 점검 결과를 현재 상태로 덮어쓰지 않는다.

- 실제 팀원 환경에서 설치·실행·API 접근 확인.

### 전달 파일 점검

- 저장소 내부 상대 링크 64개를 확인해 누락·저장소 밖 연결이 없었다.

## TEAM-01 — 팀원 실행 보고와 여러 문장 교정 결과

**기록일:** 2026-11-09. 실제 실행 날짜·시각은 전달받지 않았다.

**출처·검증 수준:** 오정호가 채팅으로 전달한 팀원 실행 상황과 병찬님의 피드백이다. 이번 문서 갱신에서 직접 실행하거나 재현한 결과가 아니다. 기존 센틴스파이 서비스 사용 기록과 이번 웹 데모 사용 결과를 구분한다.

### 팀원 실행 보고와 확인 범위

- 두 팀원이 README를 읽고 프로젝트를 실행했다는 오정호의 전달을 받았다.
- 팀원별 OS·브라우저·Node 버전·전체 API 접근 및 자동 테스트 통과 여부는 별도 확인하지 않았다.
- 참여·피드백 수령 현황은 [TASKS](TASKS.md), 사용 의견과 질문은 [사용자 피드백](사용자%20피드백.md#feedback-01)에서 확인한다.

### 여러 문장 교정 결과 — 전달받은 사례

병찬님이 표시한 모델명은 `gemini-3.5-flash-lite`다. 요청 로그로 모델을 별도 확인하지 않았다. 아래 입력은 전달된 표의 줄바꿈 표시를 읽기 쉽게 옮긴 것이며, 마지막 줄바꿈·정확한 선택 범위는 재현 시 확인해야 한다. 표의 `<br>`를 실제 입력 문자로 간주하지 않는다.

```text
이 문장은 테스트 입니다.
이 문장은 테스트 입니다2.
이 문장은 테스트 입니다3.
```

**후보 1**

```text
이 문장은 테스트입니다.
```

전달받은 교정 이유:

> 원문의 두 번째와 세 번째 문장이 삭제되고 첫 번째 문장의 띄어쓰기가 수정되어 '테스트입니다.'로 변경되었습니다.

**후보 2**

```text
이 문장은 테스트입니다. 이 문장은 테스트입니다2. 이 문장은 테스트입니다3.
```

전달받은 교정 이유:

> 각 문장의 띄어쓰기가 수정되어 '테스트입니다.'로 바뀌었으며, 줄바꿈이 공백으로 대체되어 한 줄로 이어졌습니다.

**기록상 관찰과 남은 확인**

- 후보 1은 두 번째·세 번째 문장의 내용이 빠져 있다. 줄바꿈만 바뀐 경우와 별도의 정보 누락 사례로 다룬다.
- 후보 2는 여러 줄이 공백으로 이어져 있다. 줄바꿈 보존 기준과 실제 응답을 함께 확인해야 한다.
- 설명이 삭제나 줄바꿈 변경을 언급한다고 해서 해당 교정이 적절하거나 설명 전체가 정확하다고 판정하지 않는다. 원문·후보·설명 간 대응을 별도로 평가한다.
- 모델 출력·서버 처리·화면 표시 중 원인이 어디에 있는지는 재현 전 확정하지 않는다.

### 실행 취소·다시 실행 오류 제보

병찬님은 후보 적용 후 Ctrl+Z·Ctrl+Y 동작이 꼬인다고 보고했다. 정확한 조작 순서·기대 상태·실제 상태·브라우저 정보가 없어 아직 재현·수정 완료로 판단하지 않는다.

## ELICE-01 — 엘리스 GPT-4o mini 연결 시험 결과

**기록일:** 2026-11-09. 엘리스 Serverless의 `gpt-4o-mini`를 기존 교정·설명 API에 연결해 점검했다.

### 연결 범위

- Gemini 연결을 유지하고 엘리스 어댑터를 추가했다. 서버의 `LLM_PROVIDER` 설정으로 제공자를 선택하며, 기존 프롬프트·후보 형식·설명 ID·인용 검사를 함께 사용한다.
- 설정·전환 방법은 [README](../README.md#엘리스-gpt-4o-mini-연결-시험), 연결 구조와 출력 제한은 [ARCHITECTURE](ARCHITECTURE.md#엘리스-serverless-어댑터)를 따른다.

### 연결 후 실제 테스트 결과

**원문:** `금요일까지 자료를 보내 주세여.`

**교정 API:** HTTP 200, 약 1.58초. 요청 모델 `gpt-4o-mini`.

| 후보 | 실제 반환 텍스트 | 관찰 |
|---|---|---|
| 1 | 금요일까지 자료를 보내주세요. | 요청 문장과 기한이 유지됨 |
| 2 | 금요일까지 자료를 보내 주세요. | 후보 1과 띄어쓰기 차이 |
| 3 | 금요일까지 자료를 보내 주세워. | 잘못된 표현이 반환됨. 형식 검사 통과와 교정 품질은 별개 |

**설명 API:** 약 6.06초 후 `502 / EXPLANATION_QUOTE_MISMATCH`. 형식·후보 ID 검사를 통과했지만 기존 인용 검사에서 차단돼 설명 표시까지 완료하지 못했다. 설명 원문을 보존하지 않아 어느 인용이 원인이었는지는 확인하지 못했다. 검사 자체의 오탐 가능성도 있어 설명 내용이 틀렸다고 단정하지 않는다.

**자동 검증:** 타입 검사·자동 테스트 42개·빌드 통과. 이 결과는 모델 품질이나 브라우저에서의 엘리스 사용 흐름 전체를 검증한 것은 아니다.

### 판단과 남은 확인

- 엘리스 인증·모델 접근·교정 생성 경로는 확인했다. 해당 실행의 설명 표시까지 정상 완료되거나 Gemini보다 품질이 좋다고 결론 내리지는 않는다.
- 기본 제공자는 Gemini로 유지하며 최종 사용 모델은 확정하지 않았다. 중간발표 전에는 기존 기능 점검과 발표 준비를 우선하고, 모델별 품질 비교는 후속 검토로 둔다.
- 실제 브라우저에서 엘리스 후보 적용, 여러 줄·긴 문장·숫자·조건 보존, 설명 차단 빈도, 교육 지원 범위·크레딧 잔액은 후속 확인 대상이다.
