# 기능명세 — 웹 데모

> 역할: 기능별 입력·동작·결과·예외·완료 기준을 정의한다. 기본 교정·비교·적용과 버튼형 설명을 구현했다. 제공자별 실제 호출·동작 확인과 미검증 사항은 [검증 기록](검증%20기록.md), 모델 연결·설정은 [구조 설계](ARCHITECTURE.md)를 따른다. 사용자 도움에 대한 효과 검증은 별도다.

## 1. 기본 흐름과 범위

페이지 내 원문 작성·붙여넣기 → 드래그 선택 → 교정 실행 → 후보 제공·필요할 때 원문 비교 → 후보 선택·원문 선택 범위에 적용.

기본 흐름과 ‘교정 이유’ 버튼의 설명 생성·표시를 구현했다. 설명은 필요할 때 열며, 설명을 열지 않아도 후보를 적용할 수 있다.

| ID | 기능 | 구현 순서 |
|---|---|---|
| F-01 | 원문 입력·선택 및 선택 문장 표시 | 기본 흐름 |
| F-02 | 선택 텍스트 교정 요청·후보 제공 | 기본 흐름 |
| F-03 | 원문 대비 변경 부분 강조 | 기본 흐름 |
| F-04 | 후보 선택·선택 범위 교체 | 기본 흐름 |
| F-05 | 교정 이유 열기·설명 생성·표시 | 구현; 실제 예문 확인, 사용자 효과 검증 전 |
| F-06 | 브라우저 교정 이력 저장·조회·삭제·내보내기 | 11/21 후속 범위; 아래 저장 규칙 적용 |
| F-07 | 요구를 반영한 재교정·선택적 행동 기록 | 재교정 유지; 11/24부터 행동 기록은 기본 비활성화 |

현재는 한국어 일반 문장 다듬기를 기본으로 한다. 첫 구현에서 제외했던 교정 이력은 11/21 F-06, 요구 선택형 재교정은 F-07로 추가했다. 재교정의 더 정중하게/더 담백하게 요구 외에 일반 문체 메뉴·카테고리·프리셋·자유 사용자 프롬프트·전체 문서 저장·단축키는 범위 밖이다. 이전 후보와 완전히 다른 결과의 생성은 보장하지 않는다.

## 2. 모든 기능에 적용할 규칙

### 선택 범위와 요청의 연결

- 선택 텍스트와 그 위치를 함께 보관한다. 문장 내용이 같더라도 문서 내 위치가 다르면 별개의 선택이다.
- 패널이나 버튼으로 포커스를 옮겨 브라우저의 선택 표시가 사라져도 마지막 유효한 선택 범위는 유지한다. 원문에서 다른 범위를 드래그하면 새로운 선택으로 처리한다.
- 원문에서 단순히 커서를 놓는 동작은 기존 선택을 교체하지 않는다. 패널의 ‘선택 해제’ 동작으로 명시적으로 해제할 수 있게 한다.
- 원문을 직접 편집하면 선택·후보·설명을 무효화하고 다시 선택하도록 안내한다. 다른 범위 선택 또는 선택 해제 시에도 기존 후보·설명을 제거한다.
- 요청 시점의 선택 텍스트, 시작·끝 위치, 문서 버전, 선택 버전, 요청 식별자를 묶어 보관한다. 후보별 식별자는 해당 요청에 연결한다. 현재 필드와 타입은 [구조 설계](ARCHITECTURE.md)의 상태·API 정의를 따른다.
- 응답 도착 시 현재 유효한 요청인지 확인한다. 원문·선택이 바뀌거나 더 최신 요청이 있으면 오래된 응답을 화면에 표시하지 않는다. 취소 요청만 믿지 않고 응답 적용 시에도 검사한다.
- 후보 적용 직전에도 같은 문서·선택·요청인지 확인한다. 문자열을 검색해 첫 번째 일치 위치를 대신 수정하지 않는다.

### 데이터 전달과 표시

- 교정 서버에는 선택 텍스트와 채택된 교정 설정만 전달한다. 문서 전체와 선택 위치는 브라우저에서 적용에 사용하며, 주변 문장을 모델 입력에 자동 포함하지 않는다.
- API 키는 서버에서 관리한다. 모델 출력은 일반 텍스트로 표시하고 HTML로 실행하지 않는다.
- 후보와 설명은 ‘데모 생성 결과’이며, 센틴스파이의 실제 모델 출력이나 내부 판단을 확인한 것으로 안내하지 않는다.
- 원문은 사용자가 후보 적용을 누르기 전까지 바꾸지 않는다. 요청 실패·설명 실패가 원문 수정으로 이어져서는 안 된다.
- 전체 원문 작업창은 현재 페이지에서만 관리하며 새로고침 후 복원하지 않는다. 성공한 교정의 선택 원문·후보·실제로 받은 설명은 F-06의 브라우저 저장 범위로 별도 보관한다.

## 3. F-01 원문 입력·선택

**목적:** 사용자가 고칠 범위를 직접 정하고, 교정할 내용이 무엇인지 패널에서 확인한다.

**입력·전제:** 페이지 안의 일반 텍스트 입력 공간. 서식 편집기는 첫 범위에 포함하지 않는다.

**동작·결과**

1. 사용자는 원문을 작성하거나 붙여넣는다.
2. 연속된 한 구간을 드래그하거나 키보드로 선택하면 원문 작업 공간 상단에 글자 수·선택 해제·교정 실행을 표시한다. 선택 위치 근처의 ‘교정하기’와 고정 ‘교정 실행’은 모두 확인창 없이 바로 교정을 요청한다. 선택만으로 요청하거나 화면을 이동하지 않는다. 기존 확인창 제거의 근거·검증은 [DIRECT-CORRECTION-ENTRY-01](검증%20기록.md#direct-correction-entry-01)을 따른다.
3. 패널을 눌러도 교정 대상과 원문 내 위치를 유지한다.
4. 유효한 범위를 다시 선택하면 선택 상태를 갱신하고 이전 요청·결과·설명을 무효화한다. 떨어진 여러 구간을 누적 선택하지 않는다.
5. 선택 원문은 원문 작업 공간에서 확인한다. 실행할 때 공백·줄바꿈과 선택 위치를 그대로 보관하며, 별도 확인창·배경 음영·확인창 전용 선택 표시 레이어를 사용하지 않는다.
6. 선택 없음·공백·길이 초과·한글 조합 중·요청 중에는 실행 진입을 막고 사유를 안내한다. 두 버튼은 같은 실행 경로와 요청 시점의 유효 선택 검사를 사용하며, 연속 클릭으로 같은 요청을 중복 실행하지 않는다.

**제한·예외**

- 선택 없음 또는 공백·줄바꿈만 선택한 경우 실행을 비활성화하고 ‘교정할 문장을 선택해주세요’라고 안내한다.
- 한 번에 교정할 선택 텍스트의 한도는 1,000자다. 드래그 가능한 범위를 1,000자로 제한하는 것은 아니다. 글자 수는 Unicode 코드 포인트 기준으로 세고 공백·줄바꿈도 포함한다. 이 계산과 편집기의 위치 인덱스는 구분한다.
- 1,000자를 넘으면 길이를 안내하고 실행을 막는다. 자동으로 잘라 보내지 않는다. 서버도 동일한 기준으로 검증한다.
- 선택 위치를 기록하기 전에 임의로 trim하지 않는다. 공백 여부 검사용 문자열과 실제 선택 텍스트를 구분한다.
- 입력창에서 시작한 드래그는 포인터를 입력창 밖에서 놓아도 종료를 수집해 선택과 근처 버튼 위치를 갱신한다. 다른 포인터의 종료는 무시하고 포인터 취소·창 포커스 상실 시 추적을 정리한다. 선택 끝이 화면 밖이거나 길이 초과·조합 중일 때의 버튼 숨김 정책은 유지한다.
- 원문 전체 입력은 20,000자까지 허용한다. 초과 입력을 임의로 잘라내지 않고 그대로 표시하되 길이를 줄일 때까지 실행을 막는다. 선택 1,000자 제한과 구분한다.
- 같은 내용을 같은 유효 범위에 붙여넣어 문서 내용이 그대로이면 저장된 교정 범위·후보·설명·유효 요청을 유지한다. 실제 커서가 접혀도 저장 범위를 자동 해제하지 않는다. 내용이 바뀌거나 다른 유효 범위를 선택하면 기존 무효화 규칙을 적용한다. `Ctrl+A`로 전체를 선택했다면 그 전체 범위가 새 기준이다. [#7 실제 클립보드 검증·정책 판단](검증%20기록.md#clipboard-selection-20261124)을 따른다.

**완료 기준**

- 두 군데에 같은 문장이 있어도 사용자가 선택한 위치가 유지된다.
- 패널 클릭 후에도 원문에서 선택한 텍스트로 실행할 수 있다.
- 선택 근처·고정 버튼 모두 확인창 없이 유효한 선택문만 한 번 요청한다. 드래그·복사·범위 조정만으로 요청하지 않는다.
- 선택 없음·공백·1,000자·1,001자 경계를 안내와 함께 처리한다.
- 한글·줄바꿈·이모지가 포함된 선택에서도 표시 텍스트와 적용 위치가 일치한다.

11/17 선택 유지·커서 이동·새 범위 선택·교정/설명 전송 범위의 확인 결과는 [SELECTION-SCOPE-01](검증%20기록.md#selection-scope-01)을 따른다. 당시 검사는 같은 내용 재붙여넣기를 포함하지 않았으며 #7의 Edge·Chrome 실제 클립보드 검사는 [11/24 후속 기록](검증%20기록.md#clipboard-selection-20261124)으로 구분한다. 주변 문맥 활용을 검증한 것은 아니다.

<a id="sticky-source-workspace"></a>

**넓은 화면에서 원문 작업 공간 유지 — 11/24 후속 개선:** 비교·설명을 펼친 오른쪽 후보를 아래로 읽는 동안 왼쪽 원문도 확인할 수 있도록 제목·선택 도구·입력란·하단 안내를 포함한 원문 패널 전체를 유지한다.

- 화면 너비 1,024px 이상이면서 높이 600px 이상일 때 원문 패널은 페이지 스크롤에 따라 화면 위 16px에서 고정된다. 패널 높이는 화면 높이에서 32px를 뺀 값으로 맞추되 최대 900px로 제한한다. 페이지 첫 화면에서 상단 제목 때문에 패널 아래가 화면 밖에 있을 수 있으며, 패널이 고정 위치에 도달한 뒤에는 전체 높이가 화면 안에 들어온다.
- 이 배치에서는 원문 입력란만 내부 스크롤하고 수동 세로 크기 조절은 제공하지 않는다. 제목·선택 도구가 본문을 덮지 않도록 선택 도구의 별도 고정은 해제한다. 오른쪽 후보·비교·이유는 페이지 스크롤로 읽는다.
- 너비 1,024px 미만에서는 원문 다음에 결과를 세로로 배치하고 패널 전체를 고정하지 않는다. 높이 600px 미만이면 넓은 화면도 패널 고정을 해제하되 두 열 배치는 유지한다. 두 경우 원문 입력란의 기존 크기 조절과 선택 도구의 패널 내 고정 규칙을 따른다.
- 창 크기·패널 고정 여부가 바뀌어도 원문·선택·후보·설명 상태를 초기화하지 않는다. 후보 적용 시 [원문 위치 확인](#applied-source-visibility)의 포커스·녹색 강조를 유지하고, 바뀐 범위가 이미 보이면 페이지를 이동하지 않는다. 내부에서 가려진 범위는 입력란 스크롤로 드러낸다.

**인수조건:** 넓은 화면에서 아래쪽 후보의 비교·이유를 펼쳐 읽어도 원문 패널 전체가 보이는지, 긴 원문을 입력란 안에서 읽고 선택·교정·적용할 수 있는지 확인한다. 1,024px·600px 경계와 좁은 화면·낮은 화면에서 겹침이나 가로 넘침이 없는지 확인하고, 적용 후 포커스·정확한 범위 선택·Undo/Redo와 원문 선택 근처 버튼의 기존 동작도 검증한다. 화면 배치 검증을 실제 사용자 편의 개선 수치로 해석하지 않는다.

## 4. F-02 교정 요청·후보 제공

**목적:** 선택한 문장에 대해 실제 모델이 생성한 교정 후보를 받는다.

**입력·전제:** F-01의 유효한 선택과 서버의 모델 연결 설정. 첫 제공자는 Gemini 무료 구간이며, 엘리스 Serverless GPT-4o mini 어댑터를 선택적으로 사용할 수 있다. `LLM_PROVIDER=gemini`이면 `GEMINI_API_KEY`·`GEMINI_MODEL`, `LLM_PROVIDER=elice`이면 `ELICE_API_KEY`·`ELICE_MODEL`·`ELICE_BASE_URL`을 서버에서 읽는다. 변경 후 서버를 재시작하며 사용자용 모델 선택 UI나 자동 대체는 제공하지 않는다. Gemini 무료 등급과 엘리스 교육 지원 한도는 각각 확인해야 한다. 연결 방식과 실제 검증 상태는 구조 설계·README·검증 기록을 따른다.

**동작·결과**

1. 선택 근처 ‘교정하기’ 또는 상단 ‘교정 실행’을 누르면 요청 시점의 원문과 선택 상태를 보관하고, 이전 결과를 비운 뒤 바로 로딩 상태를 표시한다. 중간 확인창은 없다. 후보 카드의 ‘다시 교정하기’는 F-07의 별도 선택 영역·실행 절차를 따른다.
2. 서버가 선택 텍스트를 검증하고 서버 설정으로 선택한 제공자 한 곳에 한 번 요청한다. 최초·일반 교정과 적용 후 재교정은 정확히 3개, 후보 카드에서의 재교정은 그 후보를 다듬은 1개를 요청한다. 의미·날짜·숫자·조건 등 원문 정보를 유지하도록 요청하되 실제 결과의 보존 여부는 별도로 검증한다.
3. 현재 유효한 요청의 응답만 수용하고, 요청한 개수의 비어 있지 않은 후보일 때 성공 결과로 표시한다. 카드 재교정은 해당 자리만 교체하며 다른 후보의 텍스트·ID는 유지한다. 두 모델을 동시에 호출하거나 후보를 추천 순위로 매기지 않는다.
4. 후보마다 현재 요청 안에서 구분 가능한 식별자를 부여한다. 후보 목록과 요청 원문을 함께 유지한다.
5. 처음에는 교정 결과를 완성된 문장으로 표시한다. 변경 강조는 F-03의 ‘원문 비교’를 펼쳐 확인하며 설명은 F-05에서 연다.

**로딩·예외**

- 요청 중 실행을 비활성화한다. 단축키를 나중에 추가하더라도 같은 중복 요청 방지 규칙을 적용한다.
- 요청 중 원문 편집·새 선택은 허용하되 해당 요청을 무효화한다. 이전 응답을 새 선택의 결과로 보여주지 않는다.
- 네트워크 오류·모델 오류·시간 초과·응답 형식 오류는 실패 안내와 재시도 방법을 제공한다. 서버 모델 호출 제한은 45초이며 자동 재시도 없이 사용자가 다시 실행한다.
- 후보가 전부 비어 있거나 응답 형식이 잘못되면 성공 결과로 표시하지 않는다. 원문을 그대로 두고 재시도할 수 있게 한다.
- API 설정 오류, 사용량 제한(429), 제공자의 결과 차단, 출력 중단·형식 오류를 구분해 안내한다. 한도 도달 시 자동 재시도·모델 변경·유료 전환을 하지 않는다. 모든 성공 응답은 후보 수·문자열·길이를 다시 검증한다.
- 제공자의 출력 한도 종료(`length`/`MAX_TOKENS`)는 `MODEL_OUTPUT_TRUNCATED`로 구분한다. 완성처럼 보이는 JSON도 결과로 사용하지 않고 원문·선택을 유지하며 범위를 줄여 나누어 교정하도록 안내한다. 설명 요청의 출력 중단에서는 기존 후보 비교·적용을 유지한다. 중단 자체를 모든 입력에서 예방하는 기능은 아니다.
- 최초·일반 교정과 적용 후 재교정은 정확히 3개, 카드 재교정은 정확히 1개가 아니면 기존 응답 형식 오류(`MODEL_RESPONSE_INVALID`)로 안내한다. 원문·선택과 재교정 전 유효 결과는 유지한다. 자동 재시도하거나 부족한 후보를 채우기·복제하지 않으며 초과 후보를 잘라 성공으로 처리하지 않는다.
- 원문과 동일한 후보에는 ‘원문과 동일’이라고 안내하고, 변경점을 만들어 설명하지 않는다.
- 동일한 후보가 반환될 수 있으며 최초 구현에서 중복 없는 생성을 보장하지 않는다. 중복을 새로운 표현이라고 소개하지 않는다.

**완료 기준**

- 일반 교정은 선택한 내용만 보내고 유효한 후보가 정확히 3개인 응답을 표시한다. 카드 재교정은 최초 선택 원문과 수정할 후보를 구분해 보내고 1개만 받아 교체한다. 요구를 선택한 경우 [F-07](#demand-rerun)의 요구·이전 자료도 전달한다. 선택하지 않은 주변 문장은 보내지 않는다.
- 실패 시 예시 문장으로 몰래 대체하지 않고 원문이 유지된다.
- 원문이나 선택을 변경한 뒤 도착한 이전 응답이 표시·적용되지 않는다.
- 일반 생성 3개와 카드 재교정 1개의 정상 응답·원문 동일·후보 수 불일치·빈 응답·잘못된 응답·출력 중단을 구분한다. 생성 개수 변경은 기존에 저장된 후보 1~3개의 이력이나 설명 요청의 1~3개 후보 지원을 제한하지 않는다.

후보 개수 변경 당시의 구현·검증과 실제 모델 미검증 범위는 [CANDIDATE-COUNT-THREE-01](검증%20기록.md#candidate-count-three-01)에 보존한다. 이후 일반 생성 3개·카드 재교정 1개·적용 후 재교정 3개를 두 제공자의 실제 웹 흐름에서 확인한 범위는 [11/24 제한 비교](검증%20기록.md#provider-workflow-20261124)를 따른다.

### 줄바꿈 보존 기준 — #2, 프롬프트 지침 반영·강제 검사 미구현

**목적:** 표현을 다듬는 과정에서 사용자가 나눈 문장·목록·문단의 구조가 바뀌지 않도록 한다. 2026-11-18에 정한 기본 방향은 **직접 입력한 줄바꿈과 빈 줄을 유지하고, 각 줄 안의 표현만 교정**하는 것이다. [PR #30](https://github.com/dhwjdgh1122/writing-demo/pull/30)의 교정 프롬프트에 이 지침을 반영하고 main에 병합했다(`6dad734`). 모델 출력의 보존을 보장하거나 위반 후보를 자동 차단하는 기능은 아니다.

**보존·변경 허용 범위**

- 선택 텍스트 안의 실제 줄바꿈을 보존한다. 문장·목록 항목의 순서를 유지하고 다른 줄로 내용을 옮기거나 줄을 합치지 않는다. 새 줄이나 빈 줄도 임의로 추가하지 않는다.
- 연속 줄바꿈으로 만든 빈 줄과 선택 범위에 포함된 맨 앞·맨 뒤 줄바꿈도 유지한다. 내용 누락이 없더라도 마지막 줄바꿈 제거는 이 기준에서 위반이다.
- 화면 폭에 따른 자동 줄 접힘은 원문의 줄바꿈이 아니다. 교정 후 글자 수나 화면 크기가 달라져 보이는 줄 수가 바뀌는 것은 허용한다.
- 각 줄 안에서는 의미를 유지하는 맞춤법·띄어쓰기·표현 교정을 허용한다. 줄 수가 같다는 이유만으로 의미·정보 보존까지 통과 처리하지 않는다.
- 줄바꿈을 포함하지 않은 부분 선택은 그 부분만 교정한다. 선택 밖의 줄바꿈·문장은 기존 F-04의 적용 범위 규칙대로 유지한다. 주변 문맥을 추가 요청하지 않는다.
- LF와 CRLF는 같은 논리적 줄바꿈으로 비교할 수 있다. 원문 파일의 바이트 형식 보존을 요구하는 기능은 아니며 브라우저 편집기의 실제 선택 문자열을 기준으로 검증한다. 이 비교 규칙을 후보 전체의 공백을 지우는 `trim` 처리로 확대하지 않는다.
- 문단 재구성·줄 합치기 옵션은 이번 범위에 포함하지 않는다.

**검증 예문과 기대 결과**

아래 `\n`은 실제 줄바꿈, `\n\n`은 빈 줄 한 개를 뜻한다. 아래 결과는 **향후 검증의 기대 예시이며 새 모델의 실제 출력이 아니다.** 원문·후보를 줄 단위로 대조하고 정보 보존도 별도로 판정한다.

| 사례 | 선택 원문 | 허용되는 교정 예시 / 확인 사항 |
|---|---|---|
| LB-01 문장 2줄 | `회의는 목요일 입니다.\n자료는 수요일까지 입니다.` | `회의는 목요일입니다.\n자료는 수요일까지입니다.`. 두 줄을 한 줄로 합치지 않는다. |
| LB-02 빈 줄·목록 | `준비물 입니다.\n\n- 노트북 입니다.\n- 필기구 입니다.` | `준비물입니다.\n\n- 노트북입니다.\n- 필기구입니다.`. 빈 줄과 각 항목을 유지한다. |
| LB-03 앞뒤 줄바꿈 | `\n회의는 목요일 입니다.\n` | `\n회의는 목요일입니다.\n`. 앞뒤 LF가 선택에 포함됐다면 없애지 않는다. |
| LB-04 부분 선택 | 전체 `앞 문장\n회의는 목요일 입니다.\n뒤 문장`에서 가운데 문장만 선택 | 요청은 가운데 문장만 포함한다. 적용 후 `앞 문장\n회의는 목요일입니다.\n뒤 문장`을 유지한다. |

기존 [CORRECTION-COVERAGE-01](검증%20기록.md#correction-coverage-01)의 COV-01/02도 재사용한다. COV-RUN-3의 끝 LF 제거는 LB-03과 같은 판정 대상이다. 내용 누락의 재현 여부(#1)와 이번 구조 보존 판정(#2)을 혼동하지 않는다.

**현재 구현과의 차이·후속 구현 판단**

- `server/llm/prompt.ts`의 교정 지침에 앞뒤 줄바꿈·빈 줄·줄별 내용과 순서 유지, 줄 합치기·나누기·이동 금지를 명시했다. Gemini·엘리스가 공통 지침을 사용하지만 이번 실제 전후 평가는 Gemini만 수행했다. 현재 형식 검사는 문자열·길이·후보 수를 검사하며 줄 경계 보존까지 검사하지 않는다.
- 어댑터→API→후보 표시→선택 범위 적용은 전달받은 문자열을 유지한다. 기존 API·브라우저 재생 검사의 통과는 모델이 올바른 줄 구조를 생성한다는 보장이 아니다. 화면의 `pre-wrap`은 있는 줄바꿈을 표시할 뿐 없어진 줄바꿈을 복원하지 않는다.
- 같은 예문으로 지침 변경 전후를 비교했다. LB-01~05와 기존 COV-02를 재사용한 LB-07의 실제 결과는 [LINEBREAK-PROMPT-01](검증%20기록.md#linebreak-prompt-01)에 남긴다. LB-06은 줄 수만으로 판정하면 놓치는 오류를 설명하는 수동 판정 예시이며 별도 생성 입력이 아니다. 위반 후보의 표시·제외·실패 안내는 미구현이며 추가 재현 근거와 사용자 영향에 따라 같은 #2에서 후속 범위를 정한다.
- 글자 위치·문장 수만 보고 줄바꿈을 자동 복원하지 않는다. 교정으로 문자열 길이가 바뀌면 잘못된 위치에 줄바꿈을 넣을 수 있다. 추가 모델 호출·자동 재시도·줄별 요청 분할도 이번 기준 정리에서 도입하지 않는다.

## 5. F-03 변경 부분 강조

**목적:** 교정 결과를 읽고, 필요할 때 원문 비교에서 실제로 달라진 위치를 확인할 수 있게 한다.

**입력·전제:** 같은 요청의 선택 원문과 후보. 모델이 설명한 변경점을 그대로 색칠하지 않고 실제 두 문자열을 비교한다.

**표시 규칙**

- 카드 상단 후보는 변경 강조나 표시용 공백 기호 없이 실제 후보 문장을 표시한다. 후보 목록 위의 밑줄 안내와 ‘삭제된 내용 있음’ 안내는 표시하지 않는다.
- 후보별 ‘원문 비교’를 펼치면 전체 원문과 전체 교정안을 위아래로 표시한다. 실제 문자열 차이를 변경된 표현 단위로 묶고, 원문의 삭제·교체 표현은 배경색·취소선, 교정안의 추가·교체 표현은 배경색·밑줄로 구분한다. 색만으로 구분하지 않는다.
- 띄어쓰기 변경은 양쪽의 대응 표현을 함께 강조한다. 예를 들어 `안녕 하세요 → 안녕하세요`는 공백 하나가 아니라 두 표현 전체를 표시한다. 공백·줄바꿈·탭만 달라진 경우에도 인접 표현으로 위치를 찾도록 하며, 실제 공백·줄 구조는 그대로 유지한다. 작은 공백 기호를 추가하지 않는다.
- 동일한 후보는 강조하지 않고 ‘변경 없음’이라고 안내한다.
- 비교 영역에는 원문·교정안의 변경 표현을 구분하는 짧은 범례를 제공한다. 강조 범위에는 비교에 필요한 동일한 글자도 포함될 수 있으므로 모든 강조 글자가 실제로 삭제·추가되었거나 잘못되었다고 안내하지 않는다. 강조색이 의미 보존이나 교정 품질을 보증한다고 표현하지 않는다.
- 표현별 설명을 받은 후보에서는 변경 표현 자체로 해당 설명을 선택한다. 원문·교정안의 대응 표현을 함께 강조하고, 본문에 번호 배지나 별도의 번호 선택줄을 넣지 않는다. 클릭 가능한 범위는 실제 비교에서 계산한 변경 묶음과 연결하며, 한쪽에만 있는 추가·삭제도 지원한다. 자세한 선택·이동 기준은 F-05를 따른다.

**예외·완료 기준**

- 날짜 삭제·조사 변경·띄어쓰기 변경·문장 전체 변경·원문 동일 사례에서 실제 차이를 확인할 수 있다.
- 비교 표시를 위해 원문이나 후보의 실제 문자열을 변형하지 않는다. 적용에는 표시용 마크업이 아닌 후보 텍스트를 사용한다.
- 비교 처리 실패 시 상단 후보를 유지하고, 원문 비교 안에 원문·후보와 강조를 제공하지 못했음을 안내한다. 변경 범례는 표시하지 않으며 교정 결과 자체를 지우지 않는다.
- 비교를 열고 닫아도 새 모델 요청을 보내지 않는다. 상단 결과와 비교 표시를 분리해도 후보 적용·설명 상태·이력 왕복 상태는 유지하며, 이력의 읽기 전용 후보에도 같은 표시 규칙을 적용한다.
- 카드 재교정이 성공해 같은 자리의 후보가 바뀌어도 원문 비교의 열림·닫힘을 유지한다. 적용 전 카드 재교정은 최초 선택 원문과 새 후보로, 적용 후 재교정은 현재 적용 문장을 새 원문으로 삼아 새 후보 3개와 비교한다. 적용 후 재교정에서도 같은 자리의 비교 열림만 유지하고 이전 변경 선택은 초기화한다. 닫힌 비교를 자동으로 펼치지 않는다. 다른 원문·선택·일반 교정으로 결과 묶음이 바뀌면 기존 펼침 상태를 넘기지 않는다.
- 공백만 추가·삭제된 경우와 문자 교체에 공백이 섞인 경우 모두 변경된 표현을 볼 수 있어야 한다. 비교 본문 복사와 적용 시 원래 문자열의 공백·줄바꿈·탭을 유지하고, 적용 시 선택 범위 밖 내용도 그대로 보존해야 한다.
- 비교 화면은 공백으로 구분한 어절의 완전 일치를 LCS로 연결하고, 그 사이의 원래 문자열을 비교해 변경 표현을 묶는다. 공백만 달라진 구간은 앞뒤의 일치한 어절도 문맥으로 함께 강조한다. 이는 한국어 문법·의미 분석이 아니다. 기존 문자 단위 비교 함수는 유지하며, 문자열 재구성 등 수행한 검증은 9절에서 구분한다. 입력 크기별 성능과 읽기 편의성 전반은 아직 검증하지 않았다.

## 6. F-04 후보 적용

**목적:** 선택한 후보를 원문의 정확한 위치에 반영한다.

**입력·전제:** 현재 유효한 요청에 연결된 후보 식별자와 텍스트. 결과 표시 자체로 원문을 바꾸지 않는다.

**동작·결과**

1. 후보별 ‘이 문장 적용’ 버튼을 누른다. 설명 열기와 후보 적용은 다른 조작으로 구분한다.
2. 저장된 문서 버전·선택 버전·선택 범위·원문 텍스트가 현재 상태와 일치하는지 검사한다.
3. 해당 범위만 후보 텍스트로 교체하고 앞뒤 문자는 그대로 보존한다. 별도의 trim·공백 자동 삽입은 하지 않는다.
4. 교체된 범위를 새로운 선택으로 표시하고 후보 3개와 펼친 원문 비교·교정 이유를 유지한다. ‘선택한 문장에 적용했습니다’라고 안내하며 적용한 카드에는 ‘적용됨’ 표시와 비활성화된 적용 버튼을 둔다. 적용 성공 후 원문 입력란에 포커스를 두고, 페이지와 입력란 내부 스크롤을 조정해 실제로 바뀐 범위를 보여준다. 해당 범위는 입력란의 선택 표시로 강조한다.
   - 같은 유효 묶음의 다른 후보는 ‘이 후보로 바꾸기’로 현재 적용 범위를 교체할 수 있다. 교체할 때마다 문서·선택 버전, 현재 범위와 텍스트를 다시 검사하고 변경된 길이를 적용 범위에 반영한다. 생성 원문과 같았던 후보도 현재 적용 문장과 다르면 다시 선택할 수 있으며 현재 문장과 같은 후보는 중복 적용하지 않는다.
   - 비교·설명은 후보를 생성한 당시 원문을 기준으로 유지하며, 적용한 문장과의 새 비교인 것처럼 바꾸지 않는다. 후보 적용 자체로 이미 받은 설명·선택한 변경 표현·유효한 진행 중 설명 요청을 지우지 않는다.
   - 적용한 카드의 기존 ‘다시 교정하기’에서 현재 문장으로 새 후보 3개를 요청한다([F-07](#demand-rerun)). 다른 카드의 재교정은 비활성화하고 먼저 해당 후보로 바꾸도록 안내한다. 편집·새 범위 선택·선택 해제·Undo/Redo로 문맥이 달라지면 기존 결과를 무효화하고 제거한다.
5. 사용자는 적용 없이 원문을 유지할 수도 있다. 현재 적용 대상 텍스트와 같은 후보는 중복 적용할 필요가 없음을 표시한다.
6. 적용 후 원문에 포커스를 두고 `Ctrl+Z`를 누르면 적용 전 내용으로, `Ctrl+Y`를 누르면 적용한 내용으로 돌아오는지 확인한다. 선택 범위 밖 내용은 유지하고, 취소·다시 실행으로 내용이 바뀌면 이전 교정 후보·설명은 복원하지 않는다.

**실패·완료 기준**

- 검증 불일치 시 적용하지 않고 다시 선택·실행하도록 안내한다. 적용이 수락되지 않은 경우 원문 확인용 화면 이동·선택 강조도 실행하지 않는다.
- 동일한 문장이 여러 번 나와도 선택한 위치만 바뀐다.
- 후보 길이가 달라져도 범위 밖의 문자·공백·줄바꿈이 유지된다.
- A 문장의 결과를 받은 뒤 B 문장을 선택해도 A 후보가 B에 적용되지 않는다.
- 한 후보 적용 후에도 같은 유효 묶음 안에서는 다른 후보로 바꿀 수 있고 길이가 달라져도 선택 범위 밖 내용은 보존된다. 편집·선택 변경·Undo/Redo 뒤에는 과거 후보로 바꿀 수 없다.
- 후보 적용 후 반복 취소·다시 실행, 두 범위에 순차 적용한 결과의 단계별 취소·다시 실행, 한글·줄바꿈·이모지가 포함된 원문 보존과 적용 후 원문 입력란 포커스를 회귀 테스트로 확인한다. [UNDO-01](검증%20기록.md#undo-01)의 Chrome 수동 보고·Edge 자동 검증은 당시 고정 실행 버튼으로 포커스를 옮기던 구현의 근거로 보존한다. 11/24 실제 클립보드 검사는 F-01의 지정 사례에 한정하며, 브라우저 편집 명령 실패 시의 Undo/Redo와 실제 IME·클립보드의 다양한 조합은 추가 확인 대상이다.

<a id="applied-source-visibility"></a>

**적용한 원문 위치 확인 — 11/24 후속 개선:** 비교·설명이 길어 적용 버튼과 원문의 변경 위치를 한 화면에서 확인하기 어렵다는 [전달 제보](사용자%20피드백.md#feedback-14)에 따라, ‘이 문장 적용’과 ‘이 후보로 바꾸기’의 성공 직후 같은 원문 확인 동작을 사용한다. 원문 입력란 전체를 페이지 상단으로 옮기는 대신 바뀐 선택 범위가 보이도록 필요한 스크롤을 조정한다. 범위가 입력란의 보이는 높이보다 길면 시작 부분을 우선 보여주고 전체 선택 범위는 유지한다. 화면 이동과 선택 표시는 새 교정 요청이나 후보·설명의 무효화를 일으키지 않아야 한다. 적용 버튼의 배치는 유지하며, 재교정의 실행 위치 유지·실패 처리 규칙은 변경하지 않는다.

적용 범위는 약 2.4초 동안 녹색 선택 배경으로 표시한 뒤 일반 선택 표시로 돌아간다. 사용자가 입력란을 클릭하거나 키보드·조합 입력을 시작하면 임시 강조를 바로 해제하며, 기존 범위를 다시 선택하거나 커서를 되돌리지 않는다. 프로그램이 만든 적용 선택만으로 떠 있는 ‘교정하기’ 버튼을 표시하지 않는다. 상단 고정 도구의 실제 높이를 고려해 변경 시작을 가리지 않는다.

**후속 인수조건:** 비교·설명을 펼친 아래쪽 카드에서 적용한 경우, 긴 문서의 입력란 내부 스크롤 아래에 있는 범위를 적용한 경우, 좁은 화면에서 원문 입력란이 화면 밖에 있는 경우에 변경 범위의 시작이 보이고 원문 입력란에 포커스가 있어야 한다. 다른 후보로 바꿀 때도 새 길이의 범위를 정확하게 선택하며, 후보·비교·설명 유지와 선택 범위 밖 내용 보존, Undo/Redo를 함께 확인한다. 전달 제보·자동 검증·실제 사용자 편의 검증은 구분한다. 최신 반영 상태는 [#79](https://github.com/dhwjdgh1122/writing-demo/issues/79)와 연결 PR을 따른다.

## 7. F-05 교정 이유 열기

**목적:** 이유가 궁금한 사용자가 현재 후보의 실제 변화와 의미 영향을 확인한다.

**입력·전제:** 유효한 교정 결과의 선택 원문·후보별 식별자와 텍스트. 선택하지 않은 주변 문맥은 사용하지 않는다.

**구현 동작**

1. 결과 제목 오른쪽의 ‘교정 이력’ 아래에 같은 크기의 ‘교정 이유’ 버튼을 표시한다. 이름은 열고 닫아도 유지하고, 현재 표시 여부를 `aria-expanded`와 열림 색상으로 구분한다. 기본 상태는 닫힘이며, 이미 설명을 받았더라도 닫으면 닫힘 상태로 표시한다.
2. 처음 누를 때 아직 설명이 없는 현재 후보를 실제 생성 요청별로 묶어 서버에 요청하고 로딩 상태를 표시한다. 처음 받은 후보 3개는 같은 묶음이며, 카드 재교정으로 서로 다른 생성 요청의 후보가 섞이면 해당 묶음별로 원문·요구·수정 대상을 연결한다. 교정 생성과 설명 생성은 별도 요청이며 같은 서버 설정 모델을 사용한다.
3. 표현별 설명이 있는 후보는 변경 묶음 중 하나의 제목·변경 전후 표현·이유를 보여준다. 필요한 경우에만 추가 확인 내용을 표시한다. 우측 `현재 순서 / 전체 개수`와 이전·다음으로 순차 탐색하고, 원문 비교의 변경 표현을 눌러 직접 선택할 수 있다. 변경 표현과 설명 제목에 번호를 붙이거나 번호 선택줄을 별도로 표시하지 않는다. 설명 영역 높이는 실제 내용에 맞추며 짧은 설명을 위한 고정 최소 높이를 두지 않는다.
4. 닫았다 다시 열 때는 같은 후보에 한해 이미 받은 설명을 재사용한다. 재교정 중에는 기존 후보·설명을 유지한다. 새 후보가 도착했을 때 교정 이유가 열려 있으면 바뀐 후보의 이전 설명을 해제하고 그 자리에서 로딩 안내와 함께 새 설명을 한 번 자동 요청한다. 적용 전 카드 재교정은 바뀐 1개만 요청하고 다른 후보의 설명을 유지한다. 적용 후 재교정은 현재 적용 문장을 새 원문으로 받은 3개의 설명을 새로 요청한다. 이유가 닫혀 있으면 자동 요청하지 않으며, 다음에 열 때 아직 설명이 없는 현재 후보를 요청한다. 별도 ‘새 후보 설명 보기’를 다시 누르게 하지 않는다. 새 원문·선택·일반 교정은 열림 상태를 초기화하며 이전 설명을 재사용하지 않는다.
5. 교정 이력 화면으로 이동했다가 돌아와도 현재 설명의 열림·로딩·성공·실패 상태를 유지한다. 화면 전환만으로 요청을 취소하거나 다시 보내지 않으며, 숨겨진 동안 도착한 유효한 응답도 수용한다. 같은 묶음의 후보 적용·다른 후보로 바꾸기도 설명을 유지한다. 직접 원문 편집·다른 범위 선택·선택 해제·Undo/Redo와 새 결과 묶음은 이전 설명을 무효화한다.

**표현 선택과 설명 연결**

- 원문과 후보의 실제 문자열에서 공통 비교 코드가 변경 묶음과 식별자를 정한다. 모델은 같은 설명 요청에서 각 묶음에 대한 설명을 반환한다. 긴 설명 문단을 화면에서 임의로 잘라 변화별 이유로 붙이지 않는다.
- 원문·교정안 중 어느 쪽의 변경 표현을 눌러도 동일한 묶음이 선택되고 대응 표현·설명·진행 표시가 함께 갱신된다. 이전·다음이나 표현 선택은 받은 데이터를 전환하며 추가 모델 호출을 하지 않는다.
- 표현 선택은 유효한 표현별 설명을 받아 교정 이유를 표시하는 동안 제공한다. 교정 이유가 닫혀 있거나 표현별 자료가 없을 때는 기존 문자열 차이 표시를 유지하며, 표현 클릭으로 새 설명 요청을 시작하지 않는다.
- 변경 표현에는 클릭 가능성을 알리는 커서·hover·키보드 포커스 표시를 제공한다. Tab으로 접근하고 Enter·Space로 선택할 수 있으며 텍스트를 드래그해 복사하는 동작으로 설명이 전환되지 않도록 한다.
- 사용자가 변경 표현을 직접 선택했는데 교정 이유의 제목과 선택 내용 시작 부분이 화면 밖이면 해당 설명으로 스크롤하고 제목에 포커스를 옮긴다. 해당 영역이 보이면 현재 화면 위치를 유지한다. 설명 응답 도착·이전·다음 조작만으로 자동 스크롤하지 않는다.
- 같은 후보의 원문 비교나 교정 이유를 접었다 다시 열어도 선택한 변경을 유지한다. 재교정으로 후보가 바뀌면 새 후보의 변경 목록으로 초기화하며 이전 식별자를 임의로 이어 붙이지 않는다.
- 표현별 자료가 없는 기존 저장 이력·설명은 후보 전체 설명으로 읽을 수 있게 유지한다. 없는 변경별 이유를 만들어 넣거나 전체 설명을 모든 표현에 반복해서 연결하지 않는다. 과거 이력을 열 때 새 모델 호출을 하지 않는다.

**설명 내용 기준**

- 사용자 기대, 사례별 필수 설명 요소와 수동 판정 절차는 [교정 설명 평가 기준](교정%20설명%20평가%20기준.md)을 따른다. 기준 정의와 실제 모델 출력의 충족 여부는 구분한다.
- 원문의 어떤 표현이 어떻게 달라졌는지, 그 변화가 표현·의미에 미치는 영향을 설명한다.
- 날짜·수치·조건이 없어지거나 확정 여부가 달라졌다면 그 변화를 알려준다. 모든 후보를 ‘더 적절하다’고 정당화하지 않는다.
- #5에서 구체화한 평가 기준: 단순 오탈자는 짧게 설명하고, 부정·주체·대상·행동을 포함한 중요한 의미 변화는 영향과 조건부 선택 기준 또는 추가로 확인할 정보까지 다룬다. 기준 정리 자체는 코드·프롬프트 변경이나 충족 여부의 검증이 아니었다. 이후 11/23 표현별 설명 연결에서는 응답 구조와 지침을 바꿨지만, 연결·표시 확인을 이 내용 기준의 충족으로 보지 않는다. [실제 출력과 한계](검증%20기록.md#expression-linked-reasons-01)를 따른다.
- 수정이 적절한 이유는 실제 변화와 제공된 정보로 뒷받침될 때만 설명한다. 사용자 속마음·기존 모델의 내부 의도·전달되지 않은 글의 상황은 추정해 단정하지 않는다.
- 원문 동일 후보에는 변경이 없음을 알린다. 실제 차이에서 확인할 수 없는 근거·문법 규칙·출처를 만들어 넣지 않는다.
- 2026-11-07 설명 지침 보완: 인용은 해당 원문·후보의 연속 문자열과 공백을 그대로 사용하고, 후보 간 수정 사항을 섞지 않는다. 전체 교정의 정확성을 보증하는 표현 대신 실제 변경을 기술한다. 이는 생성 지침이며 내용의 정확성을 코드로 보장하는 검사는 아니다.

**실패·완료 기준**

- 설명 실패 시 교정 후보와 적용 기능은 유지하고, 설명만 다시 요청할 수 있게 한다.
- 설명 응답의 후보 식별자와 내용 형식을 확인한다. ID 누락·중복·알 수 없는 ID 또는 잘못된 전체 응답은 요청 전체를 실패 처리하며, 연결할 수 없는 설명을 임의 후보에 붙이지 않는다. ID 대응이 확인된 뒤 한 후보의 설명 형식·길이에 문제가 있으면 해당 후보만 `EXPLANATION_INVALID`로 표시한다.
- 표현별 설명은 변경 묶음 식별자가 실제 비교 결과의 전체 집합과 일치하는지 대조한다. 화면의 변경 전후 표현은 모델이 다시 쓴 문구가 아니라 해당 묶음의 실제 문자열을 사용한다. 누락·중복·다른 비교의 식별자를 올바른 설명처럼 연결하지 않으며, 형식 검사를 통과해도 이유의 의미적 타당성까지 입증한 것으로 보지 않는다.
- 서버는 설명의 닫힌 인용(`'…'`, `"…"`, `‘…’`, `“…”`, `「…」`, `『…』`, 백틱)을 공백·줄바꿈까지 원문 또는 해당 후보의 연속 문자열과 대조한다. 여러 줄 인용도 한 구간으로 읽으며 다른 후보에만 있는 표현은 허용하지 않는다. 불일치 후보만 `EXPLANATION_QUOTE_MISMATCH`로 표시하고 정상 설명은 유지한다.
- ‘실패한 설명 다시 시도’는 실패한 후보와 아직 설명을 받지 않은 후보를 생성 요청별로 연결하고 기존 정상 설명은 다시 요청하지 않는다. 설명 요청·응답은 1~3개 후보를 계속 허용하며 생성 요청의 3개/1개 기준을 적용하지 않는다. 재요청 중·재요청 실패 시에도 기존 정상 설명을 유지하며 후보 비교·적용은 계속할 수 있다. 전체 실패는 성공 설명으로 표시하지 않는다. 열린 이유를 이어 보기 위한 새 후보의 최초 자동 요청과 실패 재시도는 구분하며, 실패한 설명을 자동 반복 요청하지 않는다.
- 인용 검사는 부분적인 오류 차단이다. 인용 없이 쓴 주장, 인용 방향 뒤바뀜, 닫히지 않거나 중첩된 인용, 문법 판단·의미 영향의 타당성 전체를 보장하지 않는다. 기본형 풀이 또는 줄바꿈 생략으로 실제 문자열과 다른 인용은 여전히 거절될 수 있다. 통과 여부와 설명 품질 평가를 구분한다. 분리 반영 범위와 회귀 근거는 [EXPLANATION-ISOLATION-01](검증%20기록.md#explanation-isolation-01)을 따른다.
- 설명 요청 중 직접 원문 편집·다른 범위 선택·선택 해제·Undo/Redo 또는 새 결과 묶음이면 이전 설명 응답을 무효화한다. 같은 묶음의 후보 적용·다른 후보로 바꾸기는 설명을 유지한다. 카드 재교정으로 후보 하나만 바뀐 경우 늦은 설명을 그 새 후보에 붙이지 않는다. 응답에 포함된 바뀌지 않은 후보의 설명은 계속 표시할 수 있으며 저장은 해당 설명을 요청한 원래 생성 이력에 연결한다.
- 설명을 열지 않아도 교정 후보를 적용할 수 있다.
- ‘목요일 → 이후’처럼 구체성이 줄어든 사례를 근거 없이 ‘더 명확해졌다’고 설명하면 품질 점검 실패로 기록한다.
- 유효한 설명을 생성했다는 기술적 확인과 사용자의 판단에 도움이 되었다는 효과 검증은 별도로 기록한다.
- 표현 선택·연결 표시는 설명 탐색 방식의 변경이다. #22에서 해결하지 못한 의미 판단·누락 문제를 해결했다거나 기존 품질 목표를 완수한 근거로 사용하지 않는다.

## F-06 브라우저 교정 이력

**목적:** 적용·재실행 후에도 이전 선택 원문과 후보, 이미 생성한 설명을 다시 비교한다. [#8](https://github.com/dhwjdgh1122/writing-demo/issues/8)의 후속 채택 범위다.

- 현재 교정 패널의 ‘교정 이력’으로 같은 오른쪽 패널을 이력 화면으로 전환하고, ‘뒤로’로 현재 교정 화면에 복귀한다. 최초 진입·교정 중·실패·적용 완료 상태에서도 이력을 조회할 수 있다. 별도 팝업이나 작업 공간 아래의 이력 화면을 추가하지 않는다.
- 화면 전환 자체는 원문·선택·현재 후보·펼친 비교·설명·진행 중 요청을 초기화하지 않는다. 이력 조회 중 원문을 편집하거나 다른 범위를 선택하면 기존 결과 무효화 규칙을 적용한다. 이력을 열고 닫는 것만으로 모델을 호출하지 않는다.
- 저장 단위는 현재 유효한 교정 요청의 성공 1회다. 선택 원문·그 요청에서 받은 후보·실제로 받은 설명/후보별 실패·해당 요청에서 마지막으로 적용한 후보와 시각을 저장한다. 같은 묶음에서 다른 후보로 바꾸면 해당 생성 요청의 적용 정보를 갱신한다. 동일한 적용 콜백의 중복이나 더 오래된 시각의 갱신은 무시한다. 카드 재교정의 새 성공 기록에는 새로 받은 후보 1개를 연결하고, 유지한 나머지 후보의 설명·적용은 각 후보의 기존 생성 기록에 연결한다. 기존 버전1에 저장된 후보 1~3개의 이력도 그대로 읽으며 일반 생성의 3개 기준 때문에 손상으로 처리하지 않는다. 원문 전체·계정·모델명 추정값은 저장하지 않는다.
- 편집·선택 변경으로 무효화된 늦은 응답은 저장하지 않는다. 실패 응답만 있는 요청은 성공 이력으로 만들지 않는다. 설명을 열지 않았다면 새 설명을 생성하지 않고 미생성 상태를 표시한다.
- 적용·새 요청·새로고침으로 이력을 지우지 않는다. 이력의 적용 표시는 그 생성 요청에서 마지막으로 수락한 적용이며 전체 교체 순서나 이후 Undo/직접 편집 후의 현재 문서 상태·만족을 뜻하지 않는다. 개별 적용 행동은 F-07의 행동 기록으로 구분한다.
- 목록에서 선택 원문·후보·원문 비교·저장된 설명을 읽기 전용으로 본다. 조회로 모델을 호출하거나 과거 후보를 현재 문서에 적용하지 않는다.
- 개별 삭제·전체 삭제·선택 원문/후보/설명이 포함된 JSON 내보내기를 제공한다. 전체 삭제는 확인하며, 다운로드한 파일까지 삭제하지는 않는다. 삭제한 기록을 늦은 설명 응답이 되살리지 않는다.
- 현재 사이트 주소의 브라우저 저장소만 사용한다. 계정·서버·기기 간 동기화는 없으며, 브라우저 데이터 삭제·시크릿 모드 종료 등으로 이력이 사라질 수 있다. 저장 실패 시 원문 교정은 계속하고 메모리에 남은 내용을 내보낼 수 있도록 안내한다.
- 저장 실패·메모리 전용·손상 상태는 이력 화면을 닫아도 현재 교정 화면에 요약해서 알린다. 이력 화면에서는 기존 상세 안내와 가능한 내보내기·재시도·초기화 조작을 유지한다.
- 용량 부족·저장 차단 시 저장 실패와 재시도 방법을 표시한다. 손상·알 수 없는 버전·읽기 안전 상한 초과 자료는 원래 저장값을 자동 덮어쓰지 않는다. 사용자가 명시적으로 초기화하기 전에는 저장을 중단한다.
- 다른 탭의 저장·삭제는 동일한 잠금 아래 최신 자료에 반영하고 화면도 갱신한다. 해당 저장 기능을 사용할 수 없는 환경에서는 메모리 전용임을 알린다. 오래된 기록을 자동으로 일부 삭제해 공간을 만들지 않는다.

**완료 기준:** 적용·재실행·새로고침 후 보존, 유효한 응답만 저장, 설명 재시도 후 정상 설명 유지, 조회 중 요청 0회, 삭제 후 재생성 방지, 저장 실패·손상 보존·다른 탭 갱신 및 기존 Undo/Redo를 검증한다. 이력 진입·복귀 시 작업 상태와 진행 중 설명 요청 보존, 키보드 포커스 이동, 좁은 패널의 스크롤·줄바꿈, 이력 화면 밖의 저장 문제 안내도 확인한다. 실제 사람의 편의·설명 품질은 별도다.

## F-07. 요구 재교정과 행동 기록

<a id="activity-recording-default-off"></a>

### 11/24 후속 결정 — 행동 기록 기본 비활성화

최종 프로젝트에서 사용하지 않는 행동 기록은 `VITE_ENABLE_ACTIVITY_RECORDING`이 명시적으로 `true`일 때만 켠다. 미설정·`false` 등 그 외 값에서는 행동 기록 패널·참여자 코드·통계·JSON/CSV 내보내기를 표시하지 않고, 새 교정·설명·적용·재교정 사건을 수집하지 않는다. 화면만 숨긴 채 기록을 계속 남기지 않도록 저장 훅도 실행하지 않는다. 기존 행동 기록·참여자 코드 저장소를 읽거나 쓰거나 삭제하지 않으며, 교정 이력 저장과 재교정 요청 연결은 유지한다.

코드를 여러 곳에서 주석 처리하는 대신 단일 기능 설정으로 실행을 차단해 복구 경로를 보존한다. 필요할 때 `.env`에 `VITE_ENABLE_ACTIVITY_RECORDING=true`를 설정하고 개발 서버를 재시작하거나 빌드를 다시 실행한다. 이 설정은 클라이언트 빌드 설정이며 API 키나 인증 설정이 아니다. 아래 행동 기록의 저장·집계 계약은 기능을 켰을 때에만 적용하고, #49의 과거 구현·검증 기록은 유지한다. 비활성화로 KPI나 실제 사용자 효과가 새로 측정되는 것은 아니다.

**인수조건:** 기본 실행에서 행동 기록 영역이 없고 기존 행동·참여자 저장값이 변하지 않으며, 새 행동도 저장되지 않아야 한다. 교정·설명·적용·후보별/적용 후 재교정·교정 이력은 유지한다. 명시적으로 기능을 켠 실행에서는 기존 패널·기록 연결을 사용할 수 있어야 한다. 기존 자료를 삭제하거나 초기화하는 작업은 포함하지 않는다.

### 입력과 실행

- 현재 결과가 있거나 후보를 방금 적용한 유효한 선택에 ‘다시 교정하기’ 진입을 제공한다. 요구는 다른 표현·더 정중하게·더 담백하게·원래 뜻 유지·남은 오류 수정 중 선택 사항이다. 버튼으로 선택 영역을 펼치고 ‘교정 시작’을 눌러야 실행한다. 선택 안 함은 추가 요구 없이 실행한다는 뜻이며 카드 재교정의 대상·개수는 바뀌지 않는다. 카드 재교정은 1개, 적용 후 재교정은 3개를 한 제공자의 한 요청에서 받는다. [진입과 후보별 수정](#rerun-entry-plan)에 배치·대상·상태 보존을 명시한다.
- 적용 전 카드에서는 버튼을 누른 후보를 수정 대상으로 전달하고 최초 선택 원문은 별도로 유지한다. 예를 들어 후보 3에서 ‘더 담백하게’를 실행하면 후보 3만 교체하고 후보 1·2는 유지한다. 적용 후에는 적용한 카드에서 실행하며 현재 선택 문장이 새 원문이고 후보 3개를 만든다. 요구 선택 시 이전 선택 원문·후보를 참고 자료로 연결하며 선택하지 않은 주변 문장은 보내지 않는다.
- 원문 편집·다른 범위 선택·선택 해제는 이전 요청 연결과 선택 요구를 무효화한다. 같은 선택을 유지한 포커스 이동은 연결을 유지한다. 실패 후 다시 시도할 때도 부모 요청을 유지하며, 늦은 응답은 적용·성공 이력·성공 행동으로 기록하지 않는다.
- 현재 선택 1,000자·전체 입력20,000자 제한은 그대로다. 카드에서 수정할 후보는 후보 길이 제한인 2,000자까지 전달하며 원문·적용 기준을 그 후보로 덮어쓰지 않는다. 적용한 문장이1,000자를 넘으면 범위를 줄이기 전 적용 후 재교정할 수 없다. 후보의 완전한 중복 제외나 요구 충족을 보장하지 않는다.
- 설명은 후보 생성과 별개로 요청하며, ‘교정 이유’를 처음 열거나 이유가 열린 상태에서 재교정의 새 후보가 도착할 때 생성한다. 닫혀 있으면 새 후보의 설명도 다음 열기까지 요청하지 않는다. 바뀌지 않은 후보의 이미 받은 설명은 재사용한다. 새 후보는 그 후보의 생성 요청·요구·수정 전 후보를 연결해 따로 설명한다. 비교의 기준은 해당 묶음의 원문과 현재 후보이며 적용 전에는 최초 선택 원문, 적용 후 새 묶음에서는 재교정 요청 당시 적용 문장이다. 수정 전 후보는 요구를 이해하기 위한 자료다. 인용 검사는 현재 요청의 원문·새 후보로 제한한다. 실제 변경이 없는데 요구를 반영했다고 설명하거나 과거 자료를 현재 인용으로 통과시키지 않는다. 이전 후보와 새 후보의 전용 비교 화면은 제공하지 않는다.

|---|---|---|
| 적용 전 | 각 후보의 ‘이 문장 적용’ 바로 아래, 같은 크기의 ‘다시 교정하기’ | 해당 후보를 다듬은 1개만 같은 자리에 교체. 처음 선택 원문은 비교·적용 기준으로 보존 |
| 적용 후 | 적용한 카드의 적용 버튼 바로 아래, 적용 전과 같은 크기·위치의 ‘다시 교정하기’ | 적용된 현재 선택 문장을 새 원문으로 후보 3개 생성. 다른 카드에서는 먼저 해당 후보로 바꾼 뒤 실행 |

- ‘다시 교정하기’는 인라인 선택 영역을 펼치는 버튼으로 바꾼다. 다른 후보에서 열면 이전 영역을 닫아 한 번에 하나만 표시한다. 같은 후보 묶음에서는 요구 선택값을 공유하며, 다른 후보로 이동하거나 닫았다 다시 열어도 선택을 유지한다. 큰 상시 ‘다시 다듬기’ 영역은 이 진입 방식으로 대체한다.
- 요구는 버튼 모양의 단일 선택 UI로 제공한다. ‘선택 안 함’, ‘다른 표현’, ‘더 정중하게’, ‘더 담백하게’, ‘원래 뜻 유지’, ‘남은 오류 수정’의 기존 의미를 유지한다. ‘선택 안 함’은 추가 요구 없이 같은 대상·개수로 실행하며 추가 입력은 이번 범위가 아니다.
- 펼침·닫힘·후보 간 전환·요구 선택만으로 요청하지 않는다. 선택 영역의 별도 ‘교정 시작’을 누를 때만 재교정한다. 추가 확인 팝업을 두지 않는다.
- 적용 전 후보 2 아래에서 실행하면 후보 2만 다듬고 후보 1·3은 그대로 둔다. 그 후보와 최초 선택 원문을 구분해 전달하며 응답에서도 대상 ID·텍스트·요구·원문 대응을 확인한다. 새 후보를 원문 작업창에 자동 적용하지 않는다. 적용 후에는 적용한 카드에서 현재 적용 문장을 기준으로 후보 3개를 만든다고 안내하고, 다른 카드의 재교정은 먼저 그 후보로 바꾼 뒤 사용할 수 있게 한다.
- 기존 길이 제한, 선택·편집 무효화, 부모 요청과 요구 전달, 설명의 별도 요청, 비교·적용·Undo/Redo·이력·행동 기록을 유지한다. 후보 중복 제외나 요구 충족을 보장하는 변경은 아니다.

**요청 중·실패 후 같은 자리 유지:** 재교정은 `startRerun`으로 기존 성공 결과를 보존한다. 기존 일반 ‘교정 실행’의 결과 초기화 동작과 구분하며, 재교정에서는 새 유효 응답을 받을 때까지 후보·펼친 원문 비교·받은 설명·적용 완료 안내를 유지한다.

| 재교정 상태 | 동작 |
|---|---|
| 요청 중 | 기존 후보와 실행한 선택 영역을 유지하고 중복 실행·후보 적용·새 설명 요청을 잠시 비활성화한다. 실행 버튼은 진행 중 상태를 표시한다. |
| 실패 | 기존 후보·선택 요구를 유지한다. 재교정을 시작한 선택 영역 안에서 오류를 알리고, 기존 ‘교정 시작’ 위치의 버튼을 ‘다시 시도’로 바꾼다. |
| 카드 재교정 성공 | 최신 유효 요청에서 받은 1개로 실행한 후보만 교체한다. 실행 카드의 원문 비교 열림·닫힘은 유지하고 내용만 새 후보로 갱신한다. 교정 이유가 열려 있으면 새 후보 설명을 그 자리에서 자동 요청하며, 닫혀 있으면 다음 열기까지 기다린다. 나머지 후보의 텍스트·ID·설명·비교 펼침을 유지한다. 요구 선택 영역만 닫고 다음 요청은 ‘선택 안 함’으로 초기화한다. |
| 적용 후 재교정 성공 | 적용한 현재 문장을 새 원문으로 받은 후보 3개로 묶음을 교체하고 선택 영역을 닫고 초기화한다. 같은 자리의 비교 열림·이유 표시 상태만 유지하며, 이전 적용 표시·설명 내용·선택한 변경은 초기화한다. 이유가 열려 있으면 새 원문·새 후보 3개의 설명을 자동 생성하고 닫혀 있으면 다음 열기까지 기다린다. 원문 작업 공간의 적용 문장은 그대로 두며 새 후보 적용은 별도 사용자 조작이다. |
| 적용 후 재교정 | 기존 후보 3개·적용 표시·비교·설명과 적용한 카드의 선택 영역을 유지한다. 실패 시 같은 영역에서 다시 시도하며, 이미 적용된 문장을 원래 문장으로 되돌리지 않는다. |

화면 보존은 문서·선택이 계속 유효한 경우에만 적용한다. 편집·새 범위 선택·선택 해제 시에는 기존 무효화 규칙을 우선하며 늦은 응답을 반영하지 않는다. 다시 시도는 같은 유효 대상·적용 전/후 구분·부모 요청·선택 요구에 연결한다. 실패한 시도를 새로운 성공 부모로 삼지 않으며, 보존한 후보·설명은 이전 성공 결과다. 실패를 새 성공 이력이나 성공 행동으로 저장하지 않는다.

**같은 후보 묶음에서는 유지, 성공한 새 결과에서는 초기화:** 요청 시작·로딩·실패는 초기화 시점이 아니다. 같은 유효 후보 묶음 안에서 후보 간 이동·닫기·다시 열기는 요구 선택을 유지한다. 새 유효 결과를 표시할 때만 선택 영역을 닫고 다음 요청의 선택값을 ‘선택 안 함’으로 되돌린다. 적용 후 재교정의 성공에도 같은 규칙을 사용한다. 초기화 대상은 다음 요청을 위한 UI 선택값이며, 실행 시 확정한 요구·부모 요청 연결과 그 결과의 설명 입력·이력·행동 기록은 지우거나 ‘선택 안 함’으로 덮어쓰지 않는다. 실패 보존과 문서·선택 무효화는 위 규칙을 따른다. 5176 동작 시안에서 먼저 검토한 결정을 제품에 옮겼으며 자동 재시도는 하지 않는다.

**실행한 위치 유지:** 성공 후 첫 번째 카드로 이동하지 않고 실행한 카드의 화면 위치와 ‘다시 교정하기’ 포커스를 유지한다. 대기 중 사용자가 다른 곳으로 스크롤하거나 포커스를 옮기면 완료 후 강제로 되돌리지 않는다. 적용 후 재교정은 새 후보 묶음에서도 실행한 카드 자리로 연결하되 같은 사용자 이동 보호를 적용한다.

**비교·설명 읽기 유지:** 카드 재교정 전후로 실행 카드의 비교 열림·닫힘을 유지한다. 열린 설명은 새 후보 설명의 로딩·결과로 이어지고 다른 후보 설명은 그대로 남는다. 새 설명 자동 요청 실패 시 오류와 수동 재시도를 제공하며 같은 새 후보를 자동 반복 호출하지 않는다. 이전 후보에 대해 늦게 온 설명을 새 후보에 붙이지 않고, 설명·이력은 실제 생성 요청별로 연결한다. [RERUN-READING-CONTINUITY-01](검증%20기록.md#rerun-reading-continuity-01)에 후속 검증을 기록한다.

기존 설명 요청이 진행 중이면 그 응답의 유지된 후보·이력을 먼저 처리하고 새 후보 설명을 이어서 요청한다. 새 후보 자리에는 먼저 로딩을 표시한다. 전송 대기 중 이유를 닫으면 아직 시작하지 않은 자동 요청은 다음 열기까지 보류한다.

**인수조건:** 선택 영역은 한 번에 하나만 열리고, 키보드로 요구 하나를 고른 뒤 명시적으로 실행할 수 있어야 한다. 후보 1·2·3 각각에서 실행한 후보만 교체하고 다른 후보의 텍스트·ID·설명·비교를 보존하는지 확인한다. 실행한 카드도 비교 열림·닫힘을 유지하고, 이유가 열린 경우 새 후보만 자동 생성·닫힌 경우 다음 열기에 생성·실패 시 수동 재시도를 확인한다. 최초 원문·적용 위치를 유지하고 새 후보 및 유지한 후보의 설명·이력·적용을 각각 실제 생성 요청에 연결한다. 적용 후에는 현재 적용 문장으로 후보 3개를 받는다. 같은 묶음의 선택 유지, 요청 중 결과 보존·중복 실행/적용 차단, 실패 후 같은 대상·요구로 재시도, 성공 후 요구 선택 영역 닫힘·다음 선택 초기화를 확인한다. 실행 위치 유지와 사용자가 이동했을 때 포커스를 빼앗지 않는 동작, 편집·선택 변경·늦은 응답 무효화, 좁은 화면과 기존 F-07 회귀도 확인한다. 실제 사용자 편의와 설명 내용 품질은 별도 검증이다. 화면 배치는 [화면 설계](DESIGN.md#rerun-entry-plan)를 따른다.

**적용 후 후보 유지 후속 인수조건 — [#71](https://github.com/dhwjdgh1122/writing-demo/issues/71):** 적용 뒤 후보 3개·비교·설명·변경 선택을 유지하고, 적용 카드의 표시와 동일한 크기의 재교정 버튼을 확인한다. 다른 후보로 반복 교체하거나 생성 원문과 같았던 후보로 돌아가도 현재 범위만 바뀌어야 한다. 적용 중 설명 응답과 각 후보의 이력·행동은 실제 생성 요청에 연결한다. 적용한 카드만 현재 문장으로 3개를 재교정하며 요청 중·실패에는 기존 결과·문장을 보존한다. 성공 시 새 원문 기준 비교·설명으로 전환하되 열림만 유지하고 과거 내용을 섞지 않는다. 편집·선택 변경·Undo/Redo 후 과거 후보 차단과 새로운 교정 실행도 확인한다. 이전 [#62](https://github.com/dhwjdgh1122/writing-demo/issues/62)·[#66](https://github.com/dhwjdgh1122/writing-demo/issues/66)의 당시 구현·검증 기록은 보존한다.

[후보별 수정·위치 유지 검증 CANDIDATE-REVISION-01](검증%20기록.md#candidate-revision-01)에 현재 계약의 결과와 주입 응답의 한계를 기록한다. 11/22 최초 진입 개선의 [RERUN-ENTRY-01](검증%20기록.md#rerun-entry-01)은 당시 전체 후보 재교정 계약과 검증 기록으로 보존한다.

### 저장과 내보내기

교정 이력은 기본 실행에서도 저장한다. 아래 별도 행동 기록·참여자 코드·내보내기 기능은 [명시적으로 기능을 켠 경우](#activity-recording-default-off)에만 실행한다.

- 교정 이력에 부모 요청 ID·적용 전/후·선택 요구와 카드 재교정의 수정 전 후보 ID·텍스트를 연결한다. 기존 버전1 이력의 새 필드는 선택 사항이므로 기존 자료도 읽는다. 과거 이력 조회는 읽기 전용이다.
- 행동 기록은 참여자 코드·세션/요청/부모/설명 시도/수정 대상 후보 ID·시각·요구·동작·정형 오류 코드만 별도 브라우저 저장소에 보관한다. 원문·후보·설명·자유 입력·원시 오류 메시지는 기본 행동 기록에 넣지 않는다.
- 요청·수신·실패·취소·설명 요청과 결과·후보 적용을 연결한다. 취소한 요청을 성공으로 세지 않으며 이벤트 ID와 요청/동작/시도 키로 중복을 막는다. 참여자 코드는 사용자가 붙이는 구분값으로 로그인·실제 신원 확인이 아니다. 변경 이후 사건에만 새 코드를 사용하며 이전 기록을 소급 수정하지 않는다.
- 후보 적용은 실제로 수락한 조작마다 별도의 시도 식별자를 부여한다. 같은 묶음에서 후보 1 → 후보 2 → 후보 1로 바꾸는 세 행동을 보존하고 동일 콜백의 재실행만 중복 제거한다. 이력의 요청별 마지막 적용 정보와 개별 행동 사건을 구분하며, 적용률 통계는 기존 고유 요청 단위를 유지한다.
- JSON/CSV 기본 내보내기는 문장 미포함이다. ‘문장 내용 포함’을 선택하면 내보내는 시점에 남아 있는 교정 이력만 요청 ID로 연결한다. 삭제한 이력의 문장은 분석 기록에 숨겨 보관하지 않는다. CSV는 수식으로 해석될 수 있는 시작 문자를 처리한다.
- 행동 기록 전체 삭제는 교정 이력·현재 글을 지우지 않는다. 저장 실패는 메모리·내보내기·재시도, 손상은 원본 보존·명시적 초기화를 제공한다. 다른 탭의 기록은 같은 잠금 안에서 병합한다. 30,000사건·10MiB 상한에서 자동 삭제하지 않는다. 외부 자동 전송·계정·서버 DB·분석 파일 가져오기는 없다.

### 수치와 완료 기준

모든 참여자 코드의 고유 요청을 합산해 요구 유형별 요청·수신·실패·취소와 수신한 재교정 중 적용/추가 재요청 건수를 보여준다. 분모가0이면 성공률을 만들어내지 않는다. 적용과 추가 재요청은 동시에 발생할 수 있으며, 적용률은 만족도나 설명 효과가 아니다. 삭제·기록 누락·다른 브라우저의 행동은 추정하지 않는다.

완료 기준은 두 제공자 입력 계약·적용 전/후 기준·문맥 무효화·요구 미선택·실패/취소·설명 분리 호출·저장/내보내기 경계와 기존 비교/적용/Undo 회귀다. 실제 요구 충족 품질과 사람의 판단 도움은 별도 검증이며 #22의 미완료 기준을 낮추지 않는다.

### KPI와 현재 기록 범위 — 2026-11-23 소스 재대조

**11/24 후속 적용 범위:** 아래는 행동 기록을 켰을 때의 계측 경계다. 최종 프로젝트의 기본 실행에서는 행동 기록 수집과 통계 화면을 비활성화하며, 기존 자료를 지우거나 미측정 지표를 측정 완료로 바꾸지 않는다.

KPI의 공식·분모·제외 조건·목표 구분은 [교정 설명 평가 기준의 측정 계약](교정%20설명%20평가%20기준.md#kpi-contract)을 따른다. 11/22 `main 17a2a20`에서 처음 정리한 뒤, 11/23 `main f6f1f85`의 F-02·F-05·F-07 구현에 다시 대조했다. 아래는 후보별 재교정과 표현별 설명을 포함한 현재 수집 경계이며, 새 수집 기능이나 자동 분석을 구현한 기록은 아니다. 교정 완료율 98%·설명 제공률 95%·오류 후 재시도 성공률 90%는 제안 목표이며 현재 실측 성과나 확정된 배포 조건이 아니다.

**요청·후보·설명은 다음처럼 나누어 센다.**

- 최초·일반 교정과 적용 후 재교정의 요청 완료는 유효한 후보 3개, 카드 재교정은 유효한 후보 1개를 받아 해당 자리에 반영한 경우다. 요청 유형별 분모와 생성 후보 수를 구분하며 카드 재교정에서 유지한 나머지 후보를 새로 생성한 결과로 세지 않는다. 개수 불일치를 성공으로 바꾸거나 중복 문장을 채우지 않는다. 과거 1~3개 후보 이력의 조회와 실패한 설명만 1~3개 재요청하는 계약은 그대로 유지한다.
- 후보 3개의 설명을 요청해 2개만 정상 제공하고 1개를 차단했다면, 해당 시도의 후보별 설명 제공은 **2/3**, 요청한 설명 전체 제공은 **0/1**이다. 정상 설명 2개를 유지한 것은 오류 격리 동작의 성공으로 따로 확인한다. 이 결과만으로 두 설명의 의미 정확성이나 사용자 효과가 확인된 것은 아니다.
- 실패한 설명 1개를 다시 요청해 제공했다면 재시도는 **1/1**로 따로 기록하고, 최초 시도의 실패를 지우지 않는다. 최종적으로 설명 3개를 확보한 결과와 최초 요청 성공률을 혼합하지 않는다. 원문 동일 후보의 고정 안내도 모델 생성 설명의 내용 평가와 구분한다.
- 표현별 이유가 여러 개여도 후보 수나 설명 요청 수가 늘어난 것으로 세지 않는다. 표현 클릭·이전·다음은 받은 데이터를 전환하며, 이 탐색이나 선택한 변경 ID는 현재 행동 로그에 남기지 않는다. 전체 설명만 받은 경우와 표현별 설명까지 받은 경우의 제공 형태도 현재 화면 통계에서는 별도로 집계하지 않는다.
- 설명이 실패해도 정상 교정 후보를 비교하고 적용할 수 있다. 이를 ‘유효하지 않은 응답 적용’으로 세지 않는다. 해당 안전 지표는 검증에 실패했거나 현재 선택과 대응하지 않는 **교정 후보를 적용했는지**를 확인한다.
- 오류 때문에 같은 작업을 다시 시도한 경우와, 정상 후보를 받은 뒤 다른 표현·말투 등을 원해 재교정한 경우를 구분한다. 현재 `parentRequestId`는 이전 교정과의 연결이며, 이것만으로 ‘바로 앞 오류 요청의 재시도’나 사용자의 불만을 확정하지 않는다. 요구를 선택하지 않은 재교정도 가능하다.

**현재 로그에서 확인할 수 있는 범위와 추가 확인이 필요한 범위**

| 확인 항목 | 현재 구현·자료로 가능한 범위 | 추가 수집·판정이 필요한 범위 |
|---|---|---|
| 교정 요청과 결과 | 요청 ID로 요청·수신·실패·취소·적용을 연결한다. 현재 화면 통계는 고유 요청 수를 센다. | `correction_requested`는 클라이언트가 요청을 시작한 기록이다. 서버가 유효 요청으로 접수했는지와 실제 화면 표시 완료는 별도 기록이 없어, 그대로 KPI의 서버 접수 분모·화면 표시 분자로 사용하지 않는다. |
| 설명의 부분 실패 | 설명 시도 ID와 후보별 실패 ID·오류 코드가 남는다. 이력에는 실제로 받은 설명과 후보별 실패를 보존한다. | `explanation_received`는 실패 항목을 포함한 응답을 받아도 기록된다. 기본 행동 로그에는 시도별 요청 대상 후보 목록·개수와 후보별 정상 표시 완료가 없어, 이 이벤트 수만으로 제공률을 계산하지 않는다. 최종 이력만으로 과거 각 시도의 성공·실패를 완전히 복원하지 않는다. |
| 오류 후 재시도 | 설명 시도들의 순서와 결과, 재교정 부모 연결을 확인할 수 있다. | 교정 오류의 어느 요청을 다시 시도했는지 명시하는 별도 연결·실행 목적은 없다. 전체 재교정을 오류 후 재시도로 세지 않는다. 오류 후 재시도 성공률 산출에는 정의된 연결과 관찰 기간이 필요하다. |
| 소요 시간 | 같은 요청/시도의 시작·수신·실패 시각이 모두 남았다면 그 차이를 참고용으로 계산할 수 있다. | 화면에 실제 표시된 시각, 사용자가 읽은 시간, 서버 처리 시간은 별도 계측하지 않는다. 현재 화면에 중앙값·P95 자동 집계는 없다. 취소·누락된 기록을 정상 응답 시간으로 처리하지 않는다. |
| 오류 원인·입력별 분석 | 허용된 정형 오류 코드와 요구 유형을 구분할 수 있다. | 제공자·모델·설정·입력 길이·토큰·`finish_reason`은 기본 행동 로그에 없다. 인용 오류 코드만으로 잘못된 차단인지, 줄바꿈이 원인인지 판단할 수 없다. 별도 실행 자료와 판정이 필요하다. |
| 원문 보존·선택 범위 보호 | 구현과 회귀 검증에서 실패 시 원문 유지·선택 범위 적용을 확인한다. | 기본 행동 로그에는 전체 문서 전후값·선택 범위 검증 결과·차단된 적용 시도가 없다. `candidate_applied`만으로 운영 중 원문 보존율·범위 밖 변경률을 실측한 것으로 보고하지 않는다. |
| 사용자 판단·이탈 | 참여자 코드·요구·적용/추가 요청을 연결해 관찰할 수 있다. | 비교 열람·재사용 설명의 열고 닫기·Undo/Redo·명시적 작업 포기·창 종료·판단 이유/의도 충족 응답은 기록하지 않는다. 적용 없음이나 요청 취소를 불만·이탈·설명 효과로 단정하지 않는다. |

참여자 코드는 로그인이나 실제 사람의 신원 확인이 아니다. `sessionId`는 현재 앱 인스턴스의 구분값이며, 한 사람의 전체 방문이나 분석용 세션 종료를 확정하는 값이 아니다. 다시 열기·다른 탭·다른 브라우저·코드 변경·기록 삭제에 따른 경계를 먼저 확인하고, 연결되지 않는 기록은 미확인으로 남긴다. 분모가 없거나 관찰 종료를 확인하지 못한 결과를 0% 또는 100%로 채우지 않는다.

추가 수집은 필요한 지표를 정한 뒤 별도 구현 범위로 검토한다. 이 문서 보강으로 DB·서버 수집·관리자 알림·KPI 대시보드·사용자 설문이 추가되지는 않는다. 현재의 문장 미포함 기본 내보내기, 선택적 이력 연결, 원문 최소 수집 원칙을 유지한다. 사람의 중요한 변화 인지와 의도에 맞는 선택은 별도 평가 자료로 확인하며, 클릭·적용 기록으로 대체하지 않는다.
