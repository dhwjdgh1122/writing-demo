# 기능명세 — 웹 데모 첫 구현

> 역할: 기능별 입력·동작·결과·예외·완료 기준을 정의한다. 기본 교정·비교·적용과 버튼형 설명을 구현했다. 제공자별 실제 호출·동작 확인과 미검증 사항은 [검증 기록](검증%20기록.md), 모델 연결·설정은 [구조 설계](ARCHITECTURE.md)를 따른다. 사용자 도움에 대한 효과 검증은 별도다.

## 1. 기본 흐름과 범위

페이지 내 원문 작성·붙여넣기 → 드래그 선택 → 교정 실행 → 후보 제공·변경 강조 → 후보 선택·원문 선택 범위에 적용.

기본 흐름과 ‘교정 이유’ 버튼의 설명 생성·표시를 구현했다. 설명은 필요할 때 열며, 설명을 열지 않아도 후보를 적용할 수 있다.

| ID | 기능 | 구현 순서 |
|---|---|---|
| F-01 | 원문 입력·선택 및 선택 문장 표시 | 기본 흐름 |
| F-02 | 선택 텍스트 교정 요청·후보 제공 | 기본 흐름 |
| F-03 | 원문 대비 변경 부분 강조 | 기본 흐름 |
| F-04 | 후보 선택·선택 범위 교체 | 기본 흐름 |
| F-05 | 교정 이유 열기·설명 생성·표시 | 구현; 실제 예문 확인, 사용자 효과 검증 전 |

현재는 한국어 일반 문장 다듬기 한 가지 동작이다. 카테고리·문체·프리셋·프롬프트·저장·히스토리는 구현 범위에서 제외했다. 같은 선택에서 ‘교정 실행’을 다시 누를 수 있으며, 별도 재실행 버튼과 페이지 내 단축키는 8절의 검토 항목이다. 재실행 중복 제외 개선은 첫 구현 요구사항으로 확정하지 않는다.

## 2. 모든 기능에 적용할 규칙

### 선택 범위와 요청의 연결

- 선택 텍스트와 그 위치를 함께 보관한다. 문장 내용이 같더라도 문서 내 위치가 다르면 별개의 선택이다.
- 패널이나 버튼으로 포커스를 옮겨 브라우저의 선택 표시가 사라져도 마지막 유효한 선택 범위는 유지한다. 원문에서 다른 범위를 드래그하면 새로운 선택으로 처리한다.
- 원문에서 단순히 커서를 놓는 동작은 기존 선택을 교체하지 않는다. 패널의 ‘선택 해제’ 동작으로 명시적으로 해제할 수 있게 한다.
- 원문을 직접 편집하면 선택·후보·설명을 무효화하고 다시 선택하도록 안내한다. 다른 범위 선택 또는 선택 해제 시에도 기존 후보·설명을 제거한다.
- 요청 시점의 선택 텍스트, 시작·끝 위치, 문서 버전, 선택 버전, 요청 식별자를 묶어 보관한다. 후보별 식별자는 해당 요청에 연결한다. 현재 필드와 타입은 [구조 설계](ARCHITECTURE.md)의 상태·API 정의를 따른다.
- 응답 도착 시 현재 유효한 요청인지 확인한다. 원문·선택이 바뀌거나 더 최신 요청이 있으면 오래된 응답을 화면에 표시하지 않는다. 취소 요청만 믿지 않고 응답 적용 시에도 검사한다.
- 후보 적용 직전에도 같은 문서·선택·요청인지 확인한다. 문자열을 검색해 첫 번째 일치 위치를 대신 수정하지 않는다.

### 데이터 전달과 표시

- 교정 서버에는 선택 텍스트와 채택된 교정 설정만 전달한다. 문서 전체와 선택 위치는 브라우저에서 적용에 사용하며, 주변 문장을 모델 입력에 자동 포함하지 않는다.
- API 키는 서버에서 관리한다. 모델 출력은 일반 텍스트로 표시하고 HTML로 실행하지 않는다.
- 후보와 설명은 ‘데모 생성 결과’이며, 센틴스파이의 실제 모델 출력이나 내부 판단을 확인한 것으로 안내하지 않는다.
- 원문은 사용자가 후보 적용을 누르기 전까지 바꾸지 않는다. 요청 실패·설명 실패가 원문 수정으로 이어져서는 안 된다.
- 앱의 영구 저장 없이 현재 페이지에서 작업한다. 새로고침하면 작업 내용이 사라질 수 있음을 안내한다.

## 3. F-01 원문 입력·선택

**목적:** 사용자가 고칠 범위를 직접 정하고, 교정할 내용이 무엇인지 패널에서 확인한다.

**입력·전제:** 페이지 안의 일반 텍스트 입력 공간. 서식 편집기는 첫 범위에 포함하지 않는다.

**동작·결과**

1. 사용자는 원문을 작성하거나 붙여넣는다.
2. 문장 일부를 드래그하거나 키보드로 범위를 선택하면 패널의 ‘선택한 문장’에 해당 텍스트와 글자 수를 표시한다.
3. 패널을 눌러도 교정 대상과 원문 내 위치를 유지한다.
4. 유효한 범위를 다시 선택하면 패널을 갱신하고 이전 요청·결과·설명을 무효화한다.

**제한·예외**

- 선택 없음 또는 공백·줄바꿈만 선택한 경우 실행을 비활성화하고 ‘교정할 문장을 선택해주세요’라고 안내한다.
- 선택은 최대 1,000자로 시작한다. 글자 수는 Unicode 코드 포인트 기준으로 세고 공백·줄바꿈도 포함한다. 이 계산과 편집기의 위치 인덱스는 구분한다.
- 1,000자를 넘으면 길이를 안내하고 실행을 막는다. 자동으로 잘라 보내지 않는다. 서버도 동일한 기준으로 검증한다.
- 선택 위치를 기록하기 전에 임의로 trim하지 않는다. 공백 여부 검사용 문자열과 실제 선택 텍스트를 구분한다.
- 원문 전체 입력은 20,000자까지 허용한다. 초과 입력을 임의로 잘라내지 않고 그대로 표시하되 길이를 줄일 때까지 실행을 막는다. 선택 1,000자 제한과 구분한다.

**완료 기준**

- 두 군데에 같은 문장이 있어도 사용자가 선택한 위치가 유지된다.
- 패널 클릭 후에도 원문에서 선택한 텍스트로 실행할 수 있다.
- 선택 없음·공백·1,000자·1,001자 경계를 안내와 함께 처리한다.
- 한글·줄바꿈·이모지가 포함된 선택에서도 표시 텍스트와 적용 위치가 일치한다.

## 4. F-02 교정 요청·후보 제공

**목적:** 선택한 문장에 대해 실제 모델이 생성한 교정 후보를 받는다.

**입력·전제:** F-01의 유효한 선택과 서버의 모델 연결 설정. 첫 제공자는 Gemini 무료 구간이며, 엘리스 Serverless GPT-4o mini 어댑터를 선택적으로 사용할 수 있다. `LLM_PROVIDER=gemini`이면 `GEMINI_API_KEY`·`GEMINI_MODEL`, `LLM_PROVIDER=elice`이면 `ELICE_API_KEY`·`ELICE_MODEL`·`ELICE_BASE_URL`을 서버에서 읽는다. 변경 후 서버를 재시작하며 사용자용 모델 선택 UI나 자동 대체는 제공하지 않는다. Gemini 무료 등급과 엘리스 교육 지원 한도는 각각 확인해야 한다. 연결 방식과 실제 검증 상태는 구조 설계·README·검증 기록을 따른다.

**동작·결과**

1. ‘교정 실행’을 누르면 요청 시점의 원문과 선택 상태를 보관하고, 이전 결과를 비운 뒤 로딩 상태를 표시한다.
2. 서버가 선택 텍스트를 검증하고 교정 모델을 호출한다. 의미·날짜·숫자·조건 등 원문 정보를 유지하도록 요청하되 실제 결과의 보존 여부는 별도로 검증한다.
3. 현재 유효한 요청의 응답만 수용하고, 비어 있지 않은 후보를 최대 3개 표시한다.
4. 후보마다 현재 요청 안에서 구분 가능한 식별자를 부여한다. 후보 목록과 요청 원문을 함께 유지한다.
5. 처음에는 교정 결과와 변경 강조만 표시한다. 설명은 F-05에서 연다.

**로딩·예외**

- 요청 중 실행을 비활성화한다. 단축키를 나중에 추가하더라도 같은 중복 요청 방지 규칙을 적용한다.
- 요청 중 원문 편집·새 선택은 허용하되 해당 요청을 무효화한다. 이전 응답을 새 선택의 결과로 보여주지 않는다.
- 네트워크 오류·모델 오류·시간 초과·응답 형식 오류는 실패 안내와 재시도 방법을 제공한다. 서버 모델 호출 제한은 45초이며 자동 재시도 없이 사용자가 다시 실행한다.
- 후보가 전부 비어 있거나 응답 형식이 잘못되면 성공 결과로 표시하지 않는다. 원문을 그대로 두고 재시도할 수 있게 한다.
- API 설정 오류, 사용량 제한(429), 제공자의 결과 차단, 출력 중단·형식 오류를 구분해 안내한다. 한도 도달 시 자동 재시도·모델 변경·유료 전환을 하지 않는다. 모든 성공 응답은 후보 수·문자열·길이를 다시 검증한다.
- 1~2개의 유효한 후보만 반환되면 실제 개수만 표시한다. 억지로 3개를 채우거나 없는 후보를 만든 것처럼 표시하지 않는다.
- 원문과 동일한 후보에는 ‘원문과 동일’이라고 안내하고, 변경점을 만들어 설명하지 않는다.
- 동일한 후보가 반환될 수 있으며 최초 구현에서 중복 없는 생성을 보장하지 않는다. 중복을 새로운 표현이라고 소개하지 않는다.

**완료 기준**

- 실제 모델에 선택한 내용만 보내고 유효한 응답을 후보로 표시한다.
- 실패 시 예시 문장으로 몰래 대체하지 않고 원문이 유지된다.
- 원문이나 선택을 변경한 뒤 도착한 이전 응답이 표시·적용되지 않는다.
- 유효한 소수 후보·원문 동일·빈 응답·잘못된 응답을 각각 구분한다.

## 5. F-03 변경 부분 강조

**목적:** 교정 후보에서 원문과 다른 위치를 확인할 수 있게 한다.

**입력·전제:** 같은 요청의 선택 원문과 후보. 모델이 설명한 변경점을 그대로 색칠하지 않고 실제 두 문자열을 비교한다.

**표시 규칙**

- 후보의 추가·교체된 부분을 색과 밑줄 등으로 강조한다. 색만으로 구분하지 않도록 한다.
- 삭제된 내용은 후보에 남아 있지 않으므로 후보별 원문 비교 영역에 취소선으로 표시한다. 교체는 원문 쪽 삭제와 후보 쪽 추가로 표현할 수 있다.
- 띄어쓰기·줄바꿈 변경이 있으면 비교 영역에서 확인할 수 있게 표시한다. 구체적인 기호와 색은 화면 설계에서 정한다.
- 동일한 후보는 강조하지 않고 ‘변경 없음’이라고 안내한다.
- ‘달라진 부분’이라는 범례를 표시한다. 강조색이 의미 보존이나 교정 품질을 보증한다고 표현하지 않는다.

**예외·완료 기준**

- 날짜 삭제·조사 변경·띄어쓰기 변경·문장 전체 변경·원문 동일 사례에서 실제 차이를 확인할 수 있다.
- 비교 표시를 위해 원문이나 후보의 실제 문자열을 변형하지 않는다. 적용에는 표시용 마크업이 아닌 후보 텍스트를 사용한다.
- 비교 처리 실패 시 원문과 후보를 그대로 표시하고 강조를 제공하지 못했음을 안내한다. 교정 결과 자체를 지우지 않는다.
- 코드 포인트 단위 LCS 비교와 삭제·공백·줄바꿈의 비교 표시를 구현했다. 문자열 재구성 등 수행한 검증은 9절에서 구분한다. 입력 크기별 성능과 읽기 편의성 전반은 아직 검증하지 않았다.

## 6. F-04 후보 적용

**목적:** 선택한 후보를 원문의 정확한 위치에 반영한다.

**입력·전제:** 현재 유효한 요청에 연결된 후보 식별자와 텍스트. 결과 표시 자체로 원문을 바꾸지 않는다.

**동작·결과**

1. 후보별 ‘이 문장 적용’ 버튼을 누른다. 설명 열기와 후보 적용은 다른 조작으로 구분한다.
2. 저장된 문서 버전·선택 버전·선택 범위·원문 텍스트가 현재 상태와 일치하는지 검사한다.
3. 해당 범위만 후보 텍스트로 교체하고 앞뒤 문자는 그대로 보존한다. 별도의 trim·공백 자동 삽입은 하지 않는다.
4. 교체된 범위를 새로운 선택으로 표시하고 기존 후보·설명은 닫는다. ‘선택한 문장에 적용했습니다’라고 안내한다.
5. 사용자는 적용 없이 원문을 유지할 수도 있다. 원문 동일 후보는 적용할 필요가 없음을 표시한다.
6. 적용 후 원문에 포커스를 두고 `Ctrl+Z`를 누르면 적용 전 내용으로, `Ctrl+Y`를 누르면 적용한 내용으로 돌아오는지 확인한다. 선택 범위 밖 내용은 유지하고, 취소·다시 실행으로 내용이 바뀌면 이전 교정 후보·설명은 복원하지 않는다.

**실패·완료 기준**

- 검증 불일치 시 적용하지 않고 다시 선택·실행하도록 안내한다.
- 동일한 문장이 여러 번 나와도 선택한 위치만 바뀐다.
- 후보 길이가 달라져도 범위 밖의 문자·공백·줄바꿈이 유지된다.
- A 문장의 결과를 받은 뒤 B 문장을 선택해도 A 후보가 B에 적용되지 않는다.
- 한 후보를 적용한 뒤 다른 이전 후보를 다시 적용할 수 있는 상태가 남지 않는다.
- 후보 적용 후 반복 취소·다시 실행, 두 범위에 순차 적용한 결과의 단계별 취소·다시 실행, 한글·줄바꿈·이모지가 포함된 원문 보존과 적용 후 교정 실행 버튼 포커스를 회귀 테스트로 확인한다. [UNDO-01](검증%20기록.md#undo-01)의 Chrome 수동 보고·Edge 자동 검증 범위와 한계를 따른다. 브라우저 편집 명령 실패 시의 Undo/Redo와 실제 IME·클립보드 조합은 추가 확인 대상이다.

## 7. F-05 교정 이유 열기

**목적:** 이유가 궁금한 사용자가 현재 후보의 실제 변화와 의미 영향을 확인한다.

**입력·전제:** 유효한 교정 결과의 선택 원문·후보별 식별자와 텍스트. 선택하지 않은 주변 문맥은 사용하지 않는다.

**구현 동작**

1. 결과 제목 아래 오른쪽에 아이콘과 ‘교정 이유 보기’ 버튼을 표시한다. 기본 상태는 닫힘이며, 열면 ‘교정 이유 접기’로 바뀐다.
2. 처음 누를 때 현재 후보들의 설명을 서버에 요청하고 로딩 상태를 표시한다. 교정 생성과 설명 생성은 별도 요청이며 같은 서버 설정 모델을 사용한다.
3. 각 후보와 대응하는 짧은 설명을 보여준다. 후보당 1~2문장을 목표로 하며 최대 400자를 허용한다.
4. 닫았다 다시 열 때는 같은 결과에 한해 이미 받은 설명을 재사용한다. 새 원문·선택·후보로 바뀌면 이전 설명을 재사용하지 않는다.

**설명 내용 기준**

- 원문의 어떤 표현이 어떻게 달라졌는지, 그 변화가 표현·의미에 미치는 영향을 설명한다.
- 날짜·수치·조건이 없어지거나 확정 여부가 달라졌다면 그 변화를 알려준다. 모든 후보를 ‘더 적절하다’고 정당화하지 않는다.
- 수정이 적절한 이유는 실제 변화와 제공된 정보로 뒷받침될 때만 설명한다. 사용자 속마음·기존 모델의 내부 의도·전달되지 않은 글의 상황은 추정해 단정하지 않는다.
- 원문 동일 후보에는 변경이 없음을 알린다. 실제 차이에서 확인할 수 없는 근거·문법 규칙·출처를 만들어 넣지 않는다.
- 2026-11-07 설명 지침 보완: 인용은 해당 원문·후보의 연속 문자열과 공백을 그대로 사용하고, 후보 간 수정 사항을 섞지 않는다. 전체 교정의 정확성을 보증하는 표현 대신 실제 변경을 기술한다. 이는 생성 지침이며 내용의 정확성을 코드로 보장하는 검사는 아니다.

**실패·완료 기준**

- 설명 실패 시 교정 후보와 적용 기능은 유지하고, 설명만 다시 요청할 수 있게 한다.
- 설명 응답의 후보 식별자와 내용 형식을 확인한다. 연결할 수 없는 설명은 임의 후보에 붙이지 않는다.
- 서버는 설명의 닫힌 한 줄 인용(`'…'`, `"…"`, `‘…’`, `“…”`, `「…」`, `『…』`, 백틱)을 공백까지 원문 또는 해당 후보의 연속 문자열과 대조한다. 다른 후보에만 있는 표현은 허용하지 않는다. 불일치 시 설명 묶음을 표시하지 않고 `EXPLANATION_QUOTE_MISMATCH`로 수동 재시도를 안내하며 후보와 적용은 유지한다. 자동 재호출하지 않는다.
- 인용 검사는 부분적인 오류 차단이다. 인용 없이 쓴 주장, 인용 방향 뒤바뀜, 닫히지 않거나 여러 줄·중첩된 인용, 문법 판단·의미 영향의 타당성 전체를 보장하지 않는다. 원문에 없는 문법 용어나 기본형을 따옴표로 감싼 유용한 설명도 거절될 수 있다. 통과 여부와 설명 품질 평가를 구분한다.
- 설명 요청 중 원문·선택·후보 변경 또는 후보 적용 시 이전 설명 응답을 무효화한다.
- 설명을 열지 않아도 교정 후보를 적용할 수 있다.
- ‘목요일 → 이후’처럼 구체성이 줄어든 사례를 근거 없이 ‘더 명확해졌다’고 설명하면 품질 점검 실패로 기록한다.
- 유효한 설명을 생성했다는 기술적 확인과 사용자의 판단에 도움이 되었다는 효과 검증은 별도로 기록한다.

## 8. 핵심 흐름 이후 채택 여부를 정할 기능

| 항목 | 채택할 경우의 기준 | 현재 상태 |
|---|---|---|
| 페이지 내 Ctrl+C+C | 페이지가 활성화된 경우에만 처리, 실행 버튼과 같은 검증·중복 방지, 일반 복사 방해 여부 확인 | 보조 조작으로 검토; OS 전역 호출 아님 |
| 별도 재실행 버튼 | 같은 선택 텍스트로 새 요청, 새 결과와 이전 설명을 섞지 않음 | 전용 버튼은 미구현. 현재 ‘교정 실행’으로 재요청 가능하며 새로운 후보는 보장하지 않음 |
| 중복 후보 개선 | 이전 후보와 비교, 적절한 대안 부족 시 안내 정책 마련 | 별도 개선으로 보류 |
| 설정·카테고리·문체·프리셋·프롬프트 | 실제 요청·결과에 반영되는 범위만 노출 | 첫 구현에서는 보류 제안 |
| 전체·주변 문맥, 직접 참고 문맥 입력 | 사용자 범위 선택, 실제 확보 내용, 기존 기능과 차별점 확인 | 추후 확장 |

## 9. 구현 후 확인 목록

아래는 기존 검증 결과와 남은 확인 항목이다. 자동 검증의 후보·설명은 테스트용 응답이며, 실제 모델 호출 및 사용자가 공유한 실행 결과와 구분한다. 체크는 기재한 범위에서의 확인을 뜻하며 모든 입력·환경의 성공을 보장하지 않는다. 상세 근거는 [검증 기록](검증%20기록.md)에 있다.

### 실제 모델 호출·사용자 실행 확인

- [x] 기본 경로: 입력 → 선택 → 실제 교정 요청 → 후보·강조 → 해당 범위 적용. 오정호가 제공한 실제 실행 화면으로 확인했으며, 모든 문장·환경에서의 성공을 뜻하지 않는다.
- [x] 후보 1개·3개 표시: HANDOFF-01의 실제 실행 화면과 NUM-01의 사용자 공유 결과에서 각각 확인했다. 각 후보의 품질 평가는 별도다.
- [x] 직접 작성한 날짜·숫자·조건·확정 여부·원문 동일 사례를 실제 설명 API로 점검. 후보는 설명 시험을 위해 구성했으며 전체 품질을 보장하는 평가는 아님.

### 자동 검증으로 확인한 동작

- [x] 빈 선택·공백·1,000자 경계·초과 입력에서 요청을 올바르게 허용하거나 차단.
- [x] 버튼 클릭으로 포커스를 옮겨도 선택 유지; 같은 문장이 반복된 원문에서 위치 정확성 확인.
- [x] 요청 중 원문 편집·새 선택 후 이전 응답 도착 시 결과 무효화.
- [x] 결과를 받은 뒤 선택 변경·원문 변경 시 이전 후보 적용 불가.
- [x] 설명 닫힘·열림·실패·재시도, 후보 식별자 불일치, 오래된 설명 응답 처리: 테스트 응답을 주입한 Edge 검증 완료.
- [x] 원문 동일 후보의 설명 표시: 테스트 응답을 주입한 Edge 검증으로 확인.
- [x] 문자열 재구성과 이모지 위치 보존 자동 검증, 날짜 표현 비교·적용 브라우저 확인.

### 남은 확인

- [ ] 서버 오류·시간 초과·빈 후보·형식 오류 시 원문 유지와 재시도 가능. 오류 응답 계약과 API 미설정 원문 유지는 확인했으며, 모든 오류의 브라우저 재시도 조합은 미검증.
- [ ] 동일한 후보가 여러 개 반환될 때의 표시와 원문 동일 후보의 안내·적용 불가 상태를 수동 확인.
