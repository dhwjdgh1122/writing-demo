# 공동 작업과 중간발표 준비

> 역할: 담당·기한·진행 상태·완료 기준을 관리한다. 개인 준비 상태와 실제 팀 합의·배정을 구분한다.

## 현재 확인한 상태

- 오정호가 개인 시제품을 먼저 구현했다. 원문 선택 → 교정 후보 표시·변경 강조 → 선택 범위 적용과 버튼형 설명 기능을 구현·시험했다. 세부 근거는 [README](../README.md)와 [검증 기록](검증%20기록.md)에 있다.
- 희원님은 사용 빈도보다 후보의 차이나 의미 변화를 확인하고 싶은 사용자를 대상으로 잡는 데 동의했다. 필요한 경우 버튼으로 설명을 열고, 적절성을 단정하기보다 실제 변화를 설명하며 설명 기능부터 구현하자는 의견이다.
- 병찬님 의견은 오정호의 방향과 거의 동일하다는 내용으로, 오정호가 전달한 요약이다. 항목별 상세 답변은 제공되지 않았다.
- 설명 품질·사용자 효과는 아직 검증 중이다. 위 의견 수령은 구현 전체에 대한 팀 승인이나 역할 배정 완료를 뜻하지 않는다.
- [GitHub 저장소](https://github.com/dhwjdgh1122/writing-demo)를 생성하고 `main`에 현재 문서·코드·시연 자료를 업로드했다. 팀원 초대와 다른 컴퓨터에서의 클론·실행은 아직 확인하지 않았다.

- 전달 준비 점검: 개인 자료·키를 제외한 임시 복사본에서 새 설치, 타입 검사·빌드, 자동 테스트 36개·Edge 테스트 15개 통과. 기존 개발 서버로 교정·설명 각 1회와 적용을 확인했다. [시연 안내](DEMO_GUIDE.md)·화면 5개를 준비했으며, 상세 근거는 검증 기록의 HANDOFF-01에 있다. 같은 컴퓨터의 점검이며 팀원 환경 검증은 별도다.

- 공유 문서 검토: 오정호 검토 완료. 팀원 전달·회신은 아직 미확인이다.

## 발표 전 일정

오정호가 정리한 중간발표 준비 계획이며, 개별 담당은 팀원들과 협의해 정한다.

|---|---|---|---|
| 11/7 토요일 | 공유 자료·시제품의 실제 실행 화면 준비·전달, 확인 회신 요청 | 문제·기능·현재 구현·한계·후속 작업을 전달하고 실제 회신 여부 기록 | 문서 정리·실제 실행 화면 5개 준비 완료, 전달·회신 미확인 |
| 11/8 일요일 | GitHub 계정 수집·저장소 생성·초대·실행 안내 | 개발 폴더만 공유하고 팀원 환경의 실행 결과·문제 기록 | 저장소 생성·첫 업로드 완료. 데스크톱에서 클론·README대로 실행 확인 후 팀원 초대 예정 |
| 11/9 월요일 | 의견 회의·필요 문서 갱신·공통 규칙·역할 확정·작업 시작 | 담당·수정 범위·완료 기준 결정, 당일 첫 통합 확인, 발표 목차·화면 설명 흐름 초안 | 예정 |
| 11/10 화요일 오후 2~3시 | 새 기능 작업 마감 목표 | 이후 통합 점검·오류 수정에 집중 | 예정 |

| 11/11 수요일 | 최종 확인·중간발표 | PPT/PDF의 화면 표시·발표 순서 최종 확인 후 발표 | 예정 |

기존에 작동하는 데모를 기준으로 추가 작업을 검증한다. 안정화되지 않은 기능은 발표 버전에서 보류한다. 발표자료는 오정호가 최종 정리하고, 작업이 일찍 끝나면 함께 준비한다. 발표는 PPT 또는 PDF 중심으로 실제 실행 화면을 설명하며, 당일 실시간 시연이나 영상 촬영은 필수로 두지 않는다.

## 관리 기준

- 작업 시작 전에 담당·수정 범위·완료 기준을 기록하고, 완료 표시에는 확인 근거를 붙인다.
- PR 절차와 검증 명령은 [협업 안내](../CONTRIBUTING.md), 제품 범위는 [PRD](PRD.md)를 기준으로 한다.
- 담당·일정·진행 상태는 이 문서에서 갱신하고, 기능·설계 변경은 해당 명세에 반영한다.
