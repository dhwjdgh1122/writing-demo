# 기존 센틴스파이 서비스 사용 기록

> 역할: 기존 서비스의 사용 관찰을 작성자·환경별로 보존한다. 관찰·의견·추측·미확인 사항을 구분하며, 이후 상세 관찰은 이 문서에서 관리한다. 우리 웹 데모 사용 결과는 [검증 기록](../검증%20기록.md), 개선 의견은 [사용자 피드백](../사용자%20피드백.md)으로 구분한다.

기존 기록을 이관했으며 새로운 사용 시험을 수행한 것은 아니다. 과거 실패 기록은 이후 정상 작동 보고와 구분해 보존한다.

## 오정호

### 웹 에디터 — 완료

사용한 서비스 종류·사용 상황: 센텐시파이 웹 에디터에서 문체 `표준`을 선택하고 같은 문장을 카테고리 `이메일`과 `보고서`로 교정. 메뉴에는 `없음`과 `이메일`·`논문`·`보고서`·`기사`·`마케팅`·`고객상담`이 보였고, 실제 교정은 이메일과 보고서만 진행했다.

1. **실제로 본 화면과 한 행동:** 처음 사용한 원문은 `다음 주 수요일 오후 2시까지 수정한 기획안 보내 주세요.`이다. 문장을 선택하고 `실행`을 누르면 교정안 3개가 나타났다. 교정안 하나를 누르면 왼쪽 본문 문장이 그 교정안으로 **교체·적용**됐다.

   **이메일 — 1회 실행, 교정안 3개**

   1. 다음 주 수요일 오후 2시까지 수정한 기획안을 보내주세요.
   2. 다음 주 수요일 오후 2시까지 수정된 기획안을 보내 주시기 바랍니다.
   3. 다음 주 수요일 오후 2시까지 수정된 기획안을 보내주세요.

   결과가 마음에 들어 재실행하지 않았다.

   **보고서 — 첫 실행과 재실행, 각 3개**

   | 순서 | 첫 실행 | 재실행 |
   |---|---|---|
   | 1 | 다음 주 수요일 오후 2시까지 수정된 기획안을 보내주세요. | 다음 주 수요일 오후 2시까지 수정한 기획안을 보내주세요. |
   | 2 | 수정된 기획안을 다음 주 수요일 오후 2시까지 보내주시기 바랍니다. | 수정된 기획안을 다음 주 수요일 오후 2시까지 보내 주시기 바랍니다. |
   | 3 | 다음 주 수요일 오후 2시까지 수정한 기획안을 보내 주세요. | 다음 주 수요일 오후 2시까지 수정한 기획안을 보내 주세요. |

   보고서에서는 첫 실행과 재실행의 3번 교정안이 동일했다. **본문 텍스트나 글을 입력하는 영역의 빈 여백**을 단순 클릭하면 오른쪽 교정안이 사라지고 문장 선택 안내가 표시됐다. 그 외의 화면 영역을 클릭할 때는 사라지지 않았다. 본문 텍스트를 드래그할 때도 교정안이 사라지지 않았다. 교정안에는 변경 부분이 강조되지만, 별도의 교정 이유 설명은 보이지 않았다.

   **추가 반복 확인 — 화면상 `이메일` 설정, 첫 실행 1회 + 재실행 4회**

   | 표기 | 실제 교정안 |
   |---|---|
   | A | 다음 주 수요일 오후 2시까지 수정된 기획안을 보내주세요. |
   | B | 다음 주 수요일 오후 2시까지 수정된 기획안을 보내 주시기 바랍니다. |
   | C | 다음 주 수요일 오후 2시까지 수정된 기획안을 보내주시기 바랍니다. |
   | D | 다음 주 수요일 오후 2시까지 수정한 기획안을 보내 주세요. |
   | E | 다음 주 수요일 오후 2시까지 수정된 기획안을 보내 주세요. |

   | 실행 순서 | 표시된 교정안 3개 | 이전 실행에 이미 나온 문장 |
   |---|---|---|
   | 첫 실행 | A · B · C | 비교 대상 없음 |
   | 재실행 1 | A · B · C | 3개 |
   | 재실행 2 | A · B · E | 2개 |
   | 재실행 3 | A · B · D | 2개 |
   | 재실행 4 | A · B · C | 3개 |

   총 15개 표시 중 **고유 문장은 5개**였다. 재실행에서 나온 12개 중 **10개(83.3%)** 가 앞선 어느 실행에 이미 나왔고, A와 B는 5회 모두 반복됐다. 이 수치는 이번 반복 확인의 결과이며, 서비스 전체의 일반적인 중복률은 아니다.

   오른쪽 아래 톱니바퀴 옆 **시계 아이콘**을 누르면 `문장 히스토리`가 열린다. 같은 문장에서 교정안을 여러 번 선택했을 때 히스토리에는 **마지막으로 선택·적용한 문장 한 건만** 남았다. 이번 화면에서는 `수정된 기안안을 다음 주 수요일 오후 2시까지 보내주시기 바랍니다.`가 표시됐다. 그전에 선택한 후보들과 선택하지 않은 후보들은 이 기록에서 보이지 않았다. 히스토리 기록을 눌러도 본문 텍스트가 수정되지는 않았다.

2. **내가 멈추거나 판단해야 했던 지점:** 여러 교정안 중 하나를 골라 본문에 적용하는 단계. 재실행에도 같은 문장이 반복되어 계속 재실행할지 판단해야 했다.
3. **내가 느낀 불편(개인 관찰):** 반복 실행에서 새 표현이 적어 비교 효율이 낮았다. 본문 클릭 시 후보가 사라지고 히스토리 기록을 눌러도 본문에 다시 적용되지 않는 점은 UI·사용 흐름의 불편으로 따로 기록한다.
4. **실제 고객에게도 해당할 것이라는 추측:** 다른 사용자도 반복되는 후보 때문에 선택이 어려울 수 있다. UI에서 느낀 불편도 다른 사용자에게 해당할지는 미확인이다.
5. **더 확인하고 싶은 질문:** 다른 문장·설정에서도 후보가 반복되는가? 중복의 원인은 LLM 생성 결과인가, 후보를 다루는 후처리인가? 기존 교정안에 LLM이 실제 수정 내용과 맞는 짧은 이유를 생성해 붙이면 사용자의 이해와 선택에 도움이 되는가? 히스토리와 후보가 사라지는 동작은 UI 관찰로 구분한다.
6. **수행하지 못한 단계:** 핵심 교정 흐름은 완료했다. 사라진 후보를 다시 불러와 적용하는 방법은 확인하지 못했다.

### 데스크톱 앱 — 사용 기록 완료, 노트북 실행 문제 미해결

**현재 상태(오정호 추가 확인):** 웹 에디터와 데스크톱 앱 사용 기록은 완료했다. 데스크톱 PC에서는 정상 작동하지만, 노트북에서는 데스크톱 앱 실행 문제가 남아 있어 해결이 필요하다. 아래는 기존 단축키 호출 실패 당시의 기록이며 현재 모든 환경의 상태를 뜻하지 않는다. 노트북의 현재 실행 실패 단계와 원인은 추가 확인 대상이다.

#### 기존 단축키 호출 실패 기록

사용한 서비스 종류·사용 상황: Windows 데스크톱 앱 v0.4.10. 메모장에서 문장을 선택해 앱의 교정 기능을 호출하려고 했다.

1. **실제로 본 화면과 한 행동:** 앱에 `선택한 텍스트가 없습니다`와 `Ctrl+C+C` 안내가 표시됐다. 메모장에서 문장을 드래그하고 단축키를 눌렀으나 앱 화면에 반응이 없었다. 창 최소화·창 모드 변경, 앱 완전 종료 후 재실행, `Ctrl`을 누른 채 `C` 두 번 및 두 키를 뗐다가 `Ctrl+C` 반복 입력을 시도해도 같았다. 설정의 `백그라운드에서 계속 실행 (단축키 호출 가능)`을 선택하고 창을 닫은 뒤에도 작동하지 않았다. 설정에는 최신 버전 사용 중으로 표시됐고, 단축키 변경 메뉴는 준비 중이었다.
2. **내가 멈추거나 판단해야 했던 지점:** 선택한 문장을 단축키로 앱에 전달하는 호출 단계에서 멈췄다.
3. **내가 느낀 불편(개인 관찰):** 안내된 단축키와 설정을 따라도 교정 기능을 사용할 수 없었다.
4. **실제 고객에게도 해당할 것이라는 추측:** 같은 현상을 겪는 사용자도 교정을 시작하기 어려울 수 있다. 발생 원인과 다른 환경에서의 재현 여부는 미확인이다.
5. **더 확인하고 싶은 질문:** 이 컴퓨터에서 단축키 호출이 작동하지 않는 원인은 무엇인가? 다른 사용자의 환경과 어떤 차이가 있는가?
6. **수행하지 못한 단계:** 앱으로 문장 전달, 교정 결과 확인, 후보 선택·적용·재실행. 데스크톱 교정 품질은 평가하지 못했다.

## 병찬님

출처: 오정호가 대화에 붙여넣은 병찬님의 초기 의견 원문과 이후 추가 전달 내용. 아래 관찰은 병찬님이 공유한 내용이며, 정리 과정에서 별도로 재현한 결과는 아니다. 제공되지 않은 정보는 미확인으로 남긴다.

### 데스크톱 앱 — 사용 의견 수령, 상세 교정 사례 미확인

사용한 서비스 종류·사용 상황: 프로그램 설치 후 데스크톱 앱 위주로 사용. 웹사이트 에디터보다 다른 프로그램에서 문장을 교정하는 사용 방식에 주목했다.

1. **실제로 본 화면과 한 행동:** 앱을 설치·실행했고, 사용자가 필요한 문장을 드래그해 교정을 요청하는 흐름을 공유했다. 실제 입력 문장, 설정, 출력된 교정안과 후보 수, 선택·적용·재실행의 구체적인 결과는 전달된 기록에 없다.
2. **내가 멈추거나 판단해야 했던 지점:** 구체적인 작업 중 멈춘 지점이나 후보 선택 기준은 미공유. 선택한 문장만으로 전체 글의 흐름을 파악할 수 있는지에 의문을 제기했다.
3. **내가 느낀 불편(개인 관찰):** 직접 겪은 교정 품질·선택 과정의 불편은 미공유. 서비스 조사 방향으로 웹사이트보다 데스크톱 앱과 크롬 확장 프로그램에 집중하자는 의견을 남겼다.
4. **실제 고객에게도 해당할 것이라는 추측:** 병찬님은 설치형 앱에서 다른 프로그램의 문장을 교정하는 것이 주요 콘셉트라고 보았다. 웹 에디터의 편의성이 낮은 것은 개발 우선순위가 뒤로 밀렸기 때문일 수 있다고 추정했다. 또한 사용자가 건넨 문장만 접근한다면 전체 글의 흐름을 보기 어렵고, 사용자가 인지하지 못해 선택하지 않은 문장은 교정하기 어렵다고 보았다. 제품의 실제 문맥 접근 범위와 개발 우선순위는 확인되지 않았다.
5. **더 확인하고 싶은 질문:** 공유 의견에서 도출한 확인 질문은 ‘선택한 문장 외에 주변 문맥도 실제로 전달되는가?’이다. 기록을 보완할 때는 원문·설정·교정안·선택 근거가 포함된 사례를 확인하면 된다. 추가 질문은 정리 과정에서 도출한 것으로, 병찬님이 수행한 작업은 아니다.
6. **수행하지 못한 단계:** 데스크톱에서 특정 단계가 실패했다는 보고는 없다. 다만 선택·적용·재실행 등 핵심 흐름을 모두 완료했는지는 공유 내용만으로 확인할 수 없다.

### 크롬 확장 프로그램 — 작동 문제 및 URL 전송 관찰 공유

사용한 서비스 종류·사용 상황: 크롬 확장 프로그램 사용을 시도했으나 작동하지 않는다고 공유했다. 정확한 버전·대상 사이트·실패 단계는 미공유.

1. **실제로 본 화면과 한 행동:** 확장 프로그램이 작동하지 않는다고 공유했다. 추가로 로그인 상태에서는 서비스를 사용하지 않아도 접속 중인 URL 주소를 `api-js-minxpanel.com`으로 보내는 것을 확인했다고 전달했다. 주소 표기는 전달받은 그대로이며, 요청 내역·전송 내용·재현 자료는 아직 공유받지 않았다.
2. **내가 멈추거나 판단해야 했던 지점:** 확장 프로그램이 정상 작동하지 않아 사용 흐름을 확인하는 데 제약이 생겼다. 구체적으로 어느 동작에서 멈췄는지는 미확인이다.
3. **내가 느낀 불편(개인 관찰):** 병찬님은 확장 프로그램에 문제가 있어 보인다며, 사용하지 않을 때는 비활성화하는 것이 좋겠다는 의견을 남겼다. 실제로 비활성화했는지는 미확인이다.
4. **실제 고객에게도 해당할 것이라는 추측:** 설정이 꼬여 작동하지 않을 수 있다는 추측을 공유했다. 작동 불가 원인, 다른 사용자에게도 동일하게 발생하는지, URL 전송의 조건·범위·목적은 확인되지 않았다. URL 전송을 작동 불가의 원인이나 보안 문제로 확정하지 않는다.
5. **더 확인하고 싶은 질문:** 공유 내용을 바탕으로 정리한 질문은 ‘어느 사이트·설정·동작에서 작동하지 않는가?’, ‘로그인 상태에서 언제 어떤 요청에 URL이 포함되는가?’이다. 현재는 질문만 기록하며 별도 조사를 수행한 상태가 아니다.
6. **수행하지 못한 단계:** 확장에서 정상 교정 결과를 확인했다는 보고는 없다. 후보 확인·선택·적용·재실행의 완료 여부는 미확인이다.

### 웹 에디터 — 관찰 기록 수령·정리 완료

사용한 서비스 종류·사용 상황: 웹 에디터, 문체 `표준`·카테고리 `이메일`. 일정 안내문은 첫 실행을 포함해 총 3회, 추가 예문 3개는 각각 1회 실행했다.

1. **실제로 본 화면과 한 행동:** 일정 안내문의 원문은 다음과 같다.

   > 현재 일정대로 진행된다면 금요일까지 작업을 마칠 수 있을 것 같습니다. 다만 추가 수정 요청이 들어오면 일정이 늦어질 수 있어, 완료 날짜는 목요일에 다시 안내드리겠습니다.

   같은 원문·설정에서 실행당 후보 3개가 나왔다. 재실행하면 이전 후보는 아래에 남고 새 후보가 위에 추가됐다. 총 9개 후보 중 서로 다른 문장은 6개였으며, 원문과 같은 문장이 매번 포함됐다. 이는 희원님의 집계이며 전체 후보 원문은 전달되지 않아 개별 중복 문장을 다시 대조하지는 못했다.

   한 후보에서 `목요일에 다시 안내드리겠습니다`가 `이후에 다시 안내드리겠습니다`로 바뀌어, 재안내 시점의 구체성이 줄었다. `금요일`이라는 작업 완료 예상일이 바뀌었다는 보고는 아니다.

   | 추가 원문 | 각 1회 실행·후보 3개 비교 결과 |
   |---|---|
   | 신청자는 총 15명이며, 이 중 3명은 아직 결제하지 않았습니다. | 숫자 유지. ‘결제하지 않았습니다’ → ‘결제를 완료하지 않았습니다’ 정도의 표현 변화 |
   | 담당자 승인을 받은 경우에만 외부에 자료를 공유할 수 있습니다. | 승인 조건 유지 |
   | 이번 주 배포는 확정되지 않았으며, 테스트 결과에 따라 연기될 수 있습니다. | 배포가 확정되지 않았다는 내용 유지 |

   변경 부분은 보라색으로 표시됐고 별도 교정 이유 설명은 보이지 않았다. 후보를 클릭하면 확인창 없이 본문에 적용됐다. 추가 예문에서 후보를 선택하지 않은 채 본문 아래 빈 여백을 클릭하자 후보 목록이 사라졌다. 같은 원문을 다시 선택해도 이전 후보는 돌아오지 않았다. 히스토리에는 앞서 적용한 문장들이 보였지만 이번에 선택하지 않은 후보는 찾지 못했다. 같은 문장의 마지막 선택만 남는지는 이 기록에서 별도로 확인하지 않았다.

2. **내가 멈추거나 판단해야 했던 지점:** 자연스러운 표현인지뿐 아니라 날짜·숫자·조건·확정 여부가 유지되는지 판단했다. 비슷한 후보 중 자신의 의도에 맞는 문장을 선택해야 했다.
3. **내가 느낀 불편(개인 관찰):** 본문과 후보를 번갈아 보다가 목록이 사라지면 비교가 끊길 수 있다고 보았다. 직전 결과를 다시 열거나 새로 나온 후보를 구분할 수 있으면 좋겠다고 제안했다. 반복 후보 자체는 원문이 이미 자연스러울 수 있으므로 오류로 단정하지 않았다.
4. **실제 고객에게도 해당할 것이라는 추측:** 실제 변경 내용을 짧게 설명하면 사용자가 의도에 맞는 후보인지 판단하는 데 도움이 될 수 있다. 반대로 부정확한 설명은 잘못된 선택을 돕고, 긴 설명은 읽기 부담을 늘릴 수 있다. 날짜 변화 1건만으로 자주 발생한다고 판단하지 않았으며, 실제 고객의 불편이나 재이용 효과도 확인하지 않았다.
5. **더 확인하고 싶은 질문:** 같은 원문·후보에서 설명 유무에 따라 차이·의미 변화를 더 잘 알아차리고 선택에 도움을 받는가? ‘더 자연스럽게 수정했습니다’ 같은 일반적인 평가보다 실제 변화에 근거한 설명이 적절하다는 의견이다. 제안한 설명 예시는 **‘목요일’이 ‘이후’로 바뀌어, 다시 안내할 날짜가 구체적으로 드러나지 않습니다.** 이 문구는 희원님이 제안한 예시이며 서비스 출력이나 구현된 LLM의 결과가 아니다. 실험 방법과 범위는 팀 논의 사항이다.
6. **수행하지 못한 단계:** 데스크톱 앱·확장 프로그램·다른 문체와 카테고리는 미확인. 사라진 미선택 후보를 다른 방법으로 다시 불러올 수 있는지도 미확인. 설명 기능의 효과는 아직 실험하지 않았다.
