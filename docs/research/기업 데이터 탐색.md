# 기업 데이터 탐색 — 채택 속성과 프로젝트 방향의 근거

> 2026-11-20 탐색·멘토링 정리본 대조 기록. [#38](https://github.com/dhwjdgh1122/writing-demo/issues/38)에서 추적한다. 회상 기반으로 집계·문장 대조를 시작했고, 같은 날 오정호가 전달한 4차 멘토링 정리본을 [8절](#mentoring-4-summary)에 반영했다. 전달된 운영 설명과 데이터로 확인한 사실을 구분하며, 제품 방향·팀 합의·사용자 효과를 확정한 결과는 아니다.

## 1. 먼저 확인한 결론

기업 자료에는 **선택된 원문·교정문 쌍과 후보 인덱스·후보 수**가 있다. 기존 분석을 재사용하고 CSV 집계를 다시 계산했지만, 지금 자료만으로 **‘첫 요청에서 대부분 채택했다’거나 ‘설명이 필요하다/불필요하다’는 결론은 낼 수 없다.**

- `selected_index=1`은 전체 CSV 행 중 54.24%다. `total_paraphrasing_sentence_count=3`은 92.94%다. 두 비율은 서로 다른 질문의 답이며 요청 성공률이나 만족도가 아니다.
- 완전히 같은 행이 50,628개 반복된다. 중복 제거 전후 분포와 출처별 차이를 함께 봐야 한다. 중복 제거 후의 행도 실제 독립 사건 수로 확정할 수 없다.
- CSV에는 미채택 요청 전체·미선택 후보 전체·선택 이유·우리 설명 기능을 사용한 결과가 없다. 문장과 재요청을 연결할 수 있는 범위도 제한적이다.

**현재 활용 방향:** 실제 사용 경험에 기업 데이터의 문장·속성 분석을 더해 프로젝트의 필요성과 사용 상황을 구체화한다. 데이터의 정의와 사례 활용 범위를 확인하며, 설명 기능을 무조건 정당화하는 방향으로 해석하지 않는다. 근거가 약하거나 다른 결과가 나오면 프로젝트 가설도 조정한다.

**같은 날 후속 문장 대조:** 메타데이터 집계에 이어 원문·선택문 24쌍을 직접 읽고, 실제 변경 → 사용자가 확인할 질문 → 설명에 필요한 정보의 가설로 정리했다. 기능 상태의 구체성이 달라지는 사례와 표기만 바뀌는 사례가 함께 있었다. 번역·미완결 발췌도 포함돼 있어 모든 쌍을 한국어 교정 평가에 바로 사용할 수는 없다. [10절](#enterprise-pair-review)에 과정과 한계를 남긴다. 실제 사용자의 어려움이나 설명 효과를 확인한 결과는 아니다.

## 2. 분석 질문과 범위

1. 처음에는 회상의 ‘첫 번째 응답’이 첫 후보·첫 요청·최초 묶음 중 무엇인지 확인하려 했다. 정리본에서는 가장 빠르게 도착한 후보로 설명했으며, 이 운영 설명과 CSV 필드의 대응은 계속 확인한다.
2. 선택 인덱스·후보 수의 분포는 무엇이며 중복·출처에 따라 얼마나 달라지는가?
3. 선택 문장을 특정 요청·재요청과 연결할 수 있는가?
4. 확인한 사실이 프로젝트 방향에 어디까지 근거가 될 수 있는가?

첫 탐색은 데이터 구조·채택 특성을 대상으로 했고, 후속으로 실제 문장쌍의 질적 대조를 추가했다. [PRD의 기업 CSV 설명 품질 평가](../PRD.md#기업-csv를-활용한-설명-품질-평가)는 문장 쌍에 대한 AI 설명의 정확성을 시험하는 별도 후속 제안이다. 이번에는 그 설명을 생성·채점하지 않았다. [#22](https://github.com/dhwjdgh1122/writing-demo/issues/22)의 설명 품질 개발, 후보 새 생성, 모델 비교, 사용자 효과 시험도 수행하지 않았다. UI·팝업·히스토리·재교정 요구 기능의 채택을 이 분석으로 확정하지 않는다.

## 3. 재사용 자료와 이번 실행

| 자료 | 기존 기준 | 이번 처리 |
|---|---|---|
| 기업 제공 문장 CSV | 파일명은 `(엔터) 북엔드 제공 데이터.csv`, 출처 열은 2026년 4~6월 자료로 표기. 개별 행의 시각 열은 없음 | 로컬에서 읽기 전용으로 75,881행 재집계. 주요 기존 집계 대조와 교차표·중복 제거 전후·출처별 분포 추가 |
| `data-profile.json` | 2026-10-29 22:11 KST 생성 | CSV 컬럼·건수·중복·고유 입력/문장 쌍·선택 인덱스·후보 수·출처·이벤트·빈 값·원문 동일 건수를 새 계산과 대조해 일치 확인 |
| `data-relations.json` | 2026-10-30 00:15 KST 생성 | 식별자 매핑과 요청 연결 집계를 재사용. 기존 집계 코드를 확인했으며 로그 원본 전체를 다시 분석하지 않음 |
| 기존 CSV 파서·분석 코드 | 따옴표·내부 줄바꿈·이중 따옴표를 읽는 `csvRows` 등 | CSV 파서 재사용. 과거 산출물을 덮어쓰는 기존 실행기는 재실행하지 않고 별도 로컬 점검으로 대조 |

공유 근거는 [집계 JSON](evidence/enterprise-data-2026-11-20.json)이다. 입력 CSV·기존 분석 파일의 SHA-256, 과거 생성 시각, 집계 방법, 분자·분모와 교차표를 담았다. 원문·개인 프롬프트·개별 식별자·원본 로그는 포함하지 않았다. 문서와 집계 결과를 읽기 위해 저장소 밖 개인 자료를 받을 필요는 없다. 재계산하려면 접근이 허용된 동일 원본이 필요하다.

### 집계 방법

- **원본 행:** 헤더를 제외한 파싱된 CSV 레코드 수. 여러 줄 필드가 있으므로 파일의 줄 수와 다르다. 8개 열이 모두 있는지 검사했다.
- **고유 전체행:** 8개 파싱 값 배열을 그대로 `JSON.stringify`한 뒤 SHA-256으로 같은 값을 한 번만 센다. 공백·줄바꿈·문자열을 정규화하지 않는다. 비교용 집계이며 반복 행이 추출 중복인지 정당한 반복 선택인지는 미확인이다.
- **교차표:** `[후보 수, 선택 인덱스]` 문자열 값 조합별 행 수. 조건부 비율은 해당 후보 수의 행만 분모로 쓴다.
- **출처별:** CSV의 `source` 값별로 분리한다. 제품별 모집단·기간·계측이 동등하다고 가정하지 않는다.
- **비율:** 표에 분자/분모를 함께 제시하며 소수 둘째 자리로 반올림한다. 사람·세션·요청·선택 사건 수로 바꾸어 부르지 않는다.

## 4. 필드에서 알 수 있는 것과 미확인 정의

| 필드 | 현재 확인한 내용 | 아직 확인할 정의 |
|---|---|---|
| `source`, `event` | 출처 3종, 모든 CSV 행의 이벤트 값은 `selected_paraphrasing` | 원본 자료의 추출·포함/제외 조건, 선택이 클릭인지 복사·적용 완료인지 |
| `input_sentence`, `selected_sentence` | 원문·선택문으로 제공된 두 문자열 | 입력·출력 길이 최대 255 UTF-16 단위가 실제 제한인지 추출 시 절단인지 |
| `selected_sentence_id` | 문자열 값의 매핑 키로 사용 가능 | 문장·후보·사건 중 무엇의 식별자인지, 재사용·익명화 규칙 |
| `selected_index` | 1 이상의 정수 값 관찰. 정리본에서는 첫 후보를 가장 빠른 응답으로 설명 | 이 필드가 전달된 표시 순서와 대응하는지, 누적 순서인지, 제품·버전별 정의가 같은지 |
| `total_paraphrasing_sentence_count` | 3이 많고 6·9 등도 존재하며 0도 있음 | 한 번의 응답 후보 수인지 누적 수인지, 재실행·추가 생성과의 관계 |
| `user_prompt` | 빈 값이 아닌 요구 문자열이 일부 있음 | 빈 값이 요구 없음인지 미수집인지. 교정 이유 열로 사용하지 않음 |

CSV에 요청 ID·사용자 ID·시각·미선택 후보 전체·교정 이유 열은 없다. 열 이름으로 값의 의미 전체를 확정하지 않는다.

## 5. 이번에 대조한 CSV 결과

총 75,881행 중 고유 전체행은 25,253개, 완전 반복행은 50,628개(66.72%)다. 고유 원문·선택문 쌍은 25,211개다. 아래 두 분모 모두 사용자나 요청 수가 아니다.

| 관찰 | 중복 포함 | 고유 전체행 기준 |
|---|---|---|
| 선택 인덱스가 1 | 41,159 / 75,881 = **54.24%** | 13,878 / 25,253 = **54.96%** |
| 후보 수 값이 3 | 70,526 / 75,881 = **92.94%** | 23,442 / 25,253 = **92.83%** |
| 후보 수가 3인 행 안에서 인덱스가 1 | 39,206 / 70,526 = **55.59%** | 13,178 / 23,442 = **56.22%** |
| 후보 수가 3 초과인 행 안에서 인덱스가 1~3 | 3,941 / 5,327 = **73.98%** | 1,403 / 1,805 = **77.73%** |

마지막 행은 인덱스와 후보 수를 서로 바꿔 읽으면 안 된다는 대조다. 두 값이 누적 후보를 뜻한다는 정의가 확인되지 않았으므로 ‘재요청 후 첫 묶음으로 돌아갔다’는 행동으로 해석하지 않는다.

### 출처에 따른 차이

| 출처 | 인덱스 1 / 전체 행 | 인덱스 1 / 고유 전체행 |
|---|---|---|
| desktop | 4,989 / 10,519 = 47.43% | 1,019 / 2,133 = 47.77% |
| extension | 34,970 / 58,067 = 60.22% | 12,491 / 20,969 = 59.57% |
| homepage | 1,200 / 7,295 = 16.45% | 368 / 2,151 = 17.11% |

전체 분포는 행 수가 많은 extension의 영향을 크게 받는다. **독립 웹 데모가 참고하는 데스크톱 환경을 전체 평균만으로 설명하지 않는다.** 차이가 제품 특성·사용자·표시 순서·추출 방식 중 무엇 때문인지는 확인하지 않았다.

추가 품질 확인 사항:

- 원문과 선택문이 정확히 같은 행은 3,249개, 고유 전체행 기준 663개다. 동일 문장 선택을 만족·불필요한 교정으로 분류하지 않았다.
- `user_prompt`가 빈 행은 72,590개, 원문이 빈 행은 54개다. 빈 원문은 후속 설명 평가 사례를 고를 때 따로 다뤄야 한다.
- 후보 수가 0인 행이 3개 있으며 고유 전체행으로는 1개다. ‘인덱스는 1부터 후보 수까지’라고 가정하면 이 행들이 범위를 벗어난다. 제공 측 정의가 미확인이라 오류로 단정하거나 조용히 제외하지 않았다.
- 입력·출력 최대 길이 255는 기존 집계의 관찰이다. 긴 글 수요나 실제 제품 제한을 설명하는 근거로 쓰지 않는다.

## 6. 기존 로그 연결 분석에서 재사용한 한계

이 절은 10월 분석 결과와 집계 코드의 재검토다. **11/20에 로그 원본을 다시 실행한 결과가 아니다.**

- `source + selected_sentence_id` 24,647개 키 중 577개가 서로 다른 원문·선택문 쌍에 대응했다. 인덱스·후보 수·프롬프트를 추가한 상세 키도 24,651개 중 574개가 복수 쌍에 대응했다. ID 일치만으로 특정 문장을 특정 행동에 1:1로 연결할 수 없다.
- desktop 선택 로그 34,720행 중 CSV 매핑이 있는 행은 10,519개다. 문장 매핑이 유일하고 요청 ID도 있는 범위는 63행, 서로 다른 요청키로 9개다. 9개 모두 실행 로그와 연결되지만 재실행 연결은 0개다. 연결이 없다는 것이 실제 재실행하지 않았다는 뜻은 아니다.
- extension·homepage의 해당 선택 로그에는 요청 ID가 없어 같은 방식으로 문장→실행→재실행을 연결하지 못했다.
- 모든 로그의 시간값이 정시 단위였고 일부에는 `$is_reshuffled=true`가 있었다. 시간의 의미와 재배열 규칙을 확인하기 전에는 초·분 단위 판단 시간이나 같은 시간 안의 행동 순서를 복원하지 않는다.
- desktop 요청키 9,231개 중 9,026개에 실행 행이 여러 개였다. 반복 행을 각각 재요청으로 계산하지 않는다. 식별자 수 역시 검증된 실제 사람 수가 아니다.

따라서 CSV의 채택 비율을 전체 실행 수로 나누거나 재실행과 단순 연결해 만족률·첫 요청 성공률·이탈률로 제시하지 않는다.

## 7. 프로젝트에 연결할 수 있는 점

| 확인 사실 | 활용 가능한 잠정 방향 | 아직 주장할 수 없는 것 |
|---|---|---|
| 원문·선택문 쌍이 있음 | 추출·사용 범위를 확인하고 변화 유형별 사례를 골라 설명 정확성 평가의 입력으로 활용 | 선택문이 정답, 현재 모델이 잘 설명한다는 결론 |
| 인덱스 1 외의 값도 있음 | 후보 비교·선택 상황을 검토할 자료로 활용하고 제품별 정의 확인 | 비교가 어렵다거나 설명이 선택을 개선한다는 결론 |
| 제품별 분포가 다름 | 데스크톱 등 목표 환경을 구분해 질문과 사례 구성 | 제품별 성능·사용자 만족 순위 |
| 문장과 요청·재실행 연결이 제한적임 | 필요한 필드 정의·추출 범위를 좁혀 확인 | 당장 새 행동 수집 시스템이 필수라는 결론 |

현재 서비스에서 우리가 구현한 원문·후보 설명 요청과 응답 검사·후보별 실패 처리의 설계는 별도로 설명할 수 있다. 이 분석은 그 기능의 효과를 입증한 결과가 아니다. 기업 자료를 서비스의 모델 학습·교정·설명 생성에 입력하지 않았으며 서비스 API 호출은 0회다. 후속 문장 대조는 분석 보조 AI가 자료를 읽은 내부 검토이며, AI가 자료를 전혀 열람하지 않았다는 뜻은 아니다.

## 8. 정리본 대조 결과와 남은 확인 사항

**출처:** 2026-11-20 오정호가 전달한 4차 멘토링 정리본. 녹취 원문이나 기업의 데이터 사전·구현 코드를 검증한 자료는 아니다. 첫 탐색의 집계·실패·한계를 덮어쓰지 않고 새 설명과 대조했다.

### 정리본으로 분명해진 취지와 운영 설명

멘토는 처음 제공한 유저 데이터와 채택 문장 셋·속성을 활용해 **현재 프로젝트의 필요성과 목적을 보강**하라고 조언했다. 이를 실제 문장 변화에서 사용자가 확인할 판단 지점을 찾는 작업으로 연결한다. 새로운 행동 수집 시스템을 먼저 만들라는 요구나, 데이터가 설명 효과를 이미 입증한다는 뜻으로 보지 않는다. 기업 문장을 서비스에 넣어 설명을 생성·평가하는 것은 별도 후속 선택이다.

| 후보 | 전달된 운영 설명 |
|---|---|
| 첫 번째 | 서로 다른 모델의 응답 중 가장 빠르게 도착한 후보. 먼저 표시됨 |
| 두 번째 | 내부 규칙에 따른 실시간 평가 점수가 높은 응답 |
| 세 번째 | 무작위 응답. 두 번째와 함께 표시된다는 설명 |

너무 늦는 응답을 계속 기다리지 않도록 일정 시간 안에 도착한 응답을 사용한다고 전달됐다. 정확한 대기 시간·평가식은 미확인이다. **이 설명에서 첫 번째는 첫 요청의 성공을 의미하지 않는다.** 또한 모든 CSV 출처·버전에서 `selected_index`가 이 표시 순서에 대응한다고 확인한 것은 아니다. 우리 데모가 해당 다중 모델 방식을 구현했다는 뜻도 아니다.

### 약 40%와 선택 이유의 해석

정리본에는 첫 번째 후보 채택이 약 40%로 제시됐다. 후보가 비슷해 빠른 것을 골랐을 가능성, 먼저 표시된 후보를 더 깊이 검토했을 가능성, 구별 기준을 몰라 골랐을 가능성이 함께 언급됐다. **이들은 선택 이유에 관한 가설로 기록하며 사용자별 원인으로 확정하지 않는다.** 약 40%는 과반이 아니므로 ‘대부분 첫 번째를 선택한다’고 옮기지 않는다.

이번 CSV 전체행의 인덱스 1 비율 54.24%와 고유 전체행의 54.96%는 [5절](#5-이번에-대조한-csv-결과)의 명시된 분모로 계산한 값이다. 전달 수치 약 40%와 기간·제품·분모·중복 처리·필드 대응이 같다는 확인이 없으므로 서로 대체하거나 오류라고 판단하지 않는다. 과거 3차 요약의 약 43%도 별도 전달 수치로 보존하며 이번 계산값으로 소급 수정하지 않는다.

### 남은 정의 질문과 처리 원칙

1. 전달 수치 약 40%의 기간·대상 제품·분모·중복 처리와 CSV 필드의 대응은 무엇인가?
2. 인덱스·후보 수는 요청 단위인가, 누적 단위인가? 전달된 후보 선정 방식이 출처·버전별로 같았는가?
3. 채택 이벤트의 시점·추출 기준·중복·ID 재사용·시간·재배열·문장 절단의 의미는 무엇인가?
4. 완결된 문장쌍과 요청 범위를 확인할 수 있는가? 그중 어떤 상황을 설명 정확성 또는 판단 도움 평가에 사용할 것인가?

정의가 미확인인 부분은 행동 원인·만족률·첫 요청 성공률로 해석하지 않는다. 현재 24쌍은 판단 질문을 만드는 탐색 자료로 제한하고, 평가용 정답으로 채택하기 전 완결성과 변경 해석을 별도로 확인한다. 새 자료가 기존 해석과 다르면 후속 기록을 추가한다. 문장쌍을 외부 API로 보내는 후속 평가는 사용 범위·개인정보·평가 기준을 확인한 뒤 판단한다.

## 9. 이번 점검의 검증 범위

2026-11-20 첫 집계 단계 작성 시 문서 19개·현재 이슈 21개의 파일/앵커 참조 364건에서 끊어진 연결을 발견하지 않았다. 보존 이슈 본문 20개의 해시도 일치했다. CSV와 기존 분석 JSON 2개의 해시가 실행 후에도 같았고, 공유 집계의 합계·교차표 분모·본문 비율을 대조했다. 공유 집계 JSON의 문자열은 메타데이터·필드명·파일명·방법·주의사항이며 원문·개인 프롬프트·개별 ID 값은 포함하지 않았다.

내부 AI 검토에서 수치·출처·해석 범위·참조를 대조했으며, 사람이 필드 의미나 기업 데이터의 수집 절차를 확인한 것은 아니다. 제품 코드 변경이 없어 로컬 앱 테스트·빌드와 모델 호출은 반복하지 않았다. PR의 자동 검사 결과는 데이터 해석의 타당성이나 사용자 효과 검증과 구분한다.

## 10. 후속: 실제 원문·선택문 24쌍 대조

### 목적과 방법

집계만으로는 어떤 글에서 무엇을 선택하는지 알기 어렵다. 실제 쌍을 읽고 **관찰한 변경 → 선택할 때 확인할 질문 → 설명이 제공할 정보 가설**로 연결했다. 문장을 선택한 사람의 어려움·선택 이유를 복원하거나, 설명 기능의 필요성을 증명하려는 작업은 아니다.

- 같은 `(출처, 원문, 선택문)`을 한 번씩 센 25,211쌍에서 빈 입력/출력 18쌍, 길이 255 이상 241쌍, 연락처 형태 등 5쌍을 순서대로 제외했다. 남은 24,947쌍이 선정 대상이다. 이는 8개 열 전체가 같은 행을 제거한 25,253개 집계와 단위가 다르다.
- 출처별로 **동일 1·공백/기호 중심 1·숫자 문자열 차이 2·조건 등 단서 차이 2·기타 2**를 골라 총 24쌍을 검토했다. 각 그룹 안에서는 고정된 해시 정렬 순서로 뽑았다. 정확한 규칙·선정 풀·할당량은 [문장 대조 근거 JSON](evidence/enterprise-pair-review-2026-11-20.json)의 `method`에 있다.
- 그룹 이름은 표본을 다양하게 구성하기 위한 문자열 필터다. 숫자 차이가 수량 변화를 뜻하거나, 조건 단서 차이가 조건 삭제를 뜻하지 않는다. 비율·발생 빈도를 추정하기 위한 대표 표본도 아니다.
- 24쌍 모두 `user_prompt`가 비어 있었다. 요청이 없었는지 미수집인지 알 수 없다. 선정 후 무변경·맥락 부족 사례도 그대로 유지했으며 유리한 사례로 교체하지 않았다.
- 원문은 로컬 분석 자료로 유지하고, 공동 저장소에는 원문·고유명·구체 수치·개별 식별자 없는 추상 요약만 남겼다. P01~P24는 이번 검토용 번호이며 사용자 ID가 아니다. 문장 대조는 **AI 내부 검토**로, 사람이 만든 평가 정답이 아니다.

### 실제로 확인한 차이와 프로젝트에 연결할 질문

| 사례 | 관찰한 차이 | 선택할 때 확인할 질문 | 설명에 필요한 정보 가설 |
|---|---|---|---|
| P01·P09·P17 | 원문과 선택문이 동일 | 수정 없이 유지하려는 것인지는 기록만으로 알 수 없음 | 변경이 없다는 짧은 안내. 개선 이유를 만들어 설명하지 않음 |
| P02·P10·P18 | 문장 부호·띄어쓰기·기호 정리 | 문서 표기 방식에 맞는가? | 실제 표기 차이를 짧게 설명. 의미·정중함 향상을 단정하지 않음 |
| P04·P20의 앞부분 | 날짜·금액의 **값은 같고 표기만 다름** | 일정·금액 자체가 바뀐 것인가, 표시 방식만 바뀐 것인가? | 숫자 문자열 차이와 값의 변화를 구분. P20 후반은 미완결이라 판정 유보 |
| P12 | 제목·본문의 반복 제거와 표현 통합. 반복된 명칭의 숫자도 줄어듦 | 반복 제거와 추가된 강조가 글의 목적에 맞는가? | 숫자 출현 감소를 수량 감소로 설명하지 않음 |
| P22 | 기능 이용 불가가 덜 구체적인 상태 진술로 바뀌고, 사용자 불편을 가능성으로 덧붙임 | 실제 상태를 정확히 알리는 것이 중요한가, 완곡한 안내가 적절한가? | 격식뿐 아니라 상태 정보가 달라진 점을 설명. 실제 일부 사용 가능·선택문 오류는 단정하지 않음 |
| P15·P23 | 개별 제시 강조 또는 메모를 독자 대상 행동 안내로 전환 | 개별 항목을 원하는가? 내부 메모인가, 실제 안내문인가? | 같은 내용이라도 사용 목적·독자에 따라 적합성이 달라질 수 있음을 설명 |
| P05·P06·P07·P08·P21·P24 | 개념·수식 관계·연결·지시 표현·강조·시제 등의 차이 | 앞뒤 문맥과 작성 의도를 유지하는가? | 관찰한 차이만 제시하고 문맥 부족 때문에 확정할 수 없는 부분 구분 |
| P11·P13·P14·P16·P19 | 번역·기술 명칭·문서 형식 전환 포함 | 번역이 요청된 것인가? 현재 한국어 교정 범위에 해당하는가? | 번역과 교정 구분. 단서가 달라져도 조건이 유지된 사례를 조건 삭제로 설명하지 않음 |
| P03 | 두 미완결 발췌의 내용 차이가 큼 | 같은 입력 범위에 대응하는 완전한 결과인가? | 먼저 대응 범위 확인. 보이지 않는 정보를 삭제됐다고 판정하지 않음 |

P20은 앞부분 금액 표기와 별개로 결과를 더 구체적으로 서술하는 차이도 있었다. 실제 사실·전체 맥락은 확인하지 않았으며, 금액이 같다는 관찰을 문장 전체의 의미 보존 판정으로 확대하지 않는다. 24쌍 각각의 변경·선택 질문·설명 정보·한계는 위 JSON의 `cases`에 보존했다. P20·P22는 별도 내부 AI 대조 후 표현을 보완했다.

### 가장 구체적으로 연결할 수 있는 가설

P22에서는 단순히 ‘더 자연스럽고 정중한 문장’이라고 설명하면 **기능 상태를 알리는 내용의 차이**를 놓칠 수 있다. 이를 바탕으로 다음 질문을 세울 수 있다.

> 상태를 정확히 알려야 하는 안내문에서, 변경된 상태 표현과 선택 기준을 설명해 주면 원문 비교만 볼 때보다 의도에 맞는 문장을 고르는 데 도움이 되는가?

이것은 **기업 문장쌍을 보고 만든 검증 질문**이다. 사용자가 실제로 어려워했다는 관찰이나 설명 효과의 결과는 아니다. 반대로 P02·P04처럼 단순한 표기 차이는 짧은 안내나 원문 비교만으로 충분할 가능성도 함께 검토해야 한다.

### 이번에 더 분명해진 한계와 다음 범위

1. **255 미만인 문장도 중간에 끊겨 있었다.** 길이만으로 완결된 사례를 고를 수 없다. 뒤쪽에 없다는 이유만으로 정보 삭제·환각을 판정하지 않는다.
2. **번역이 섞여 있었다.** 서비스의 한국어 교정 범위와 구분해야 하며, 이번 표본으로 전체 기업 데이터의 번역 비중을 추정하지 않는다.
3. **설명을 만들거나 채점하지 않았다.** 현재 모델이 위 정보를 정확하게 설명하는지는 #5·#20의 기준과 별도 평가가 필요하다. #22의 설명 내용 품질은 여전히 별도 미완료 범위다.
4. **새 행동 수집 기능이 바로 필요한 것으로 결론 내리지 않았다.** 먼저 완결된 문장쌍과 요청 범위를 확인하고, 표기 수정·상태 정보 변화처럼 비교할 질문을 좁힐 수 있다.

정리본과 해석을 대조했으며, 기존 데이터로 프로젝트의 필요성·사용 상황을 구체화하자는 취지로 연결했다. 실제로 평가할 사례·목적의 확정은 남아 있다. 필요하면 공개 가능한 새 예문과 사람이 확인한 변경 기준을 마련해 현재 설명의 정확성 또는 사람의 판단 도움을 **서로 다른 평가**로 진행한다. 기업 원문을 외부 서비스 API에 보내는 시험은 이번 범위에 포함하지 않는다.

**추가 기록 점검:** 24개 사례의 ID·출처별 할당량·누락/중복과 선정 풀 합계를 검사했다. CSV·기존 분석 파일 2개의 해시도 유지됐다. 공유 JSON의 필드를 제한하고 원문·선택문 전체 및 개별 선정 해시가 없는지 자동 검사한 뒤, 추상 요약의 고유명·수치 노출과 해석 범위를 내부 검토했다. 연결된 문서·이슈의 파일/앵커 점검에서 끊어진 참조는 없었다. 자동 검사가 완전한 비식별화나 의미 판단의 정답을 보장하는 것은 아니다.
