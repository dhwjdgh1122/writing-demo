# 프로젝트 선정 근거

> 역할: 서비스 관찰·멘토링·팀 의견·데이터 탐색이 프로젝트 방향에 어떻게 기여했는지 설명한다. 현재 목적·범위는 [PRD](../PRD.md), 작업 상태는 [TASKS](../TASKS.md)가 기준이다.

## 해결하려는 문제를 좁힌 과정

기존 서비스에서 사용자는 교정 후보를 비교하며 원래 의도와 날짜·조건 등이 유지됐는지 판단한다. 변경 강조만으로 표현 변화의 의미를 충분히 이해할 수 있는지는 별도 확인이 필요하다는 가설에서 출발했다.

| 근거 | 방향에 기여한 내용 | 해석 한계 |
|---|---|---|
| 오정호의 웹 에디터 관찰 | 비슷한 후보가 반복되고 본문 클릭 시 후보가 사라지는 사례 확인 | 단일 예문·환경의 관찰이며 일반적 중복률이나 고객 불만을 입증하지 않음 |
| 희원님의 웹 에디터 관찰 | ‘목요일’이 ‘이후’로 바뀌어 재안내 시점의 구체성이 줄어든 사례 | 작업 완료 예상일이 바뀐 사례와 구분. 전체 후보 원문은 확보되지 않음 |
| 병찬님의 기존 서비스 의견 | 외부 프로그램에서 선택 문장을 다듬는 데스크톱 사용 흐름에 주목 | 주변 문맥 접근이나 교정 품질을 직접 검증한 결과는 아님 |
| 초기 멘토링·강사 조언 전달 | 제공 데이터 분석만으로 문제를 정하기보다 사용자 가치와 기능 개선을 탐색 | 과거 프로젝트 사례·조언을 공식 평가 기준이나 필수 요구사항으로 간주하지 않음 |
| 2차 멘토링 전달 | 데스크톱 중심 흐름과 선택 문장 단위 교정이라는 배경 확인 | 기업 API·앱 확장 환경을 제공받은 것은 아님 |

세부 관찰과 출처는 [서비스 사용 기록](서비스%20사용%20기록.md)과 [서비스 분석](서비스%20분석.md)에 있다. 위 자료는 문제 탐색의 근거이며 설명 기능의 필요성·효과가 입증됐다는 뜻은 아니다.

## 대상 사용자와 설명 방향에 관한 의견

오정호가 전달한 병찬님의 초기 방향성 의견은 제안한 방향과 거의 동일하다는 요약이다. 희원님은 처음에는 헤비 사용자를 생각했지만, 재확인 답변에서 사용 빈도보다 **후보의 차이나 의미 변화를 확인하려는 사용자**를 대상으로 잡는 방향에 동의했다.

희원님은 필요한 경우 버튼으로 설명을 열고 설명 기능부터 구현하자는 의견을 주었다. 수정이 무조건 적절하다고 평가하기보다 원문과 무엇이 달라졌는지 안내하는 방향이다. 이는 대상·설명 방향에 대한 의견이며 구현 전체 승인이나 사용자 효과 검증과 구분한다. 이후 웹 데모 사용 의견은 [사용자 피드백](../사용자%20피드백.md)에서 다룬다.

## 먼저 웹 시제품을 만든 이유

오정호는 논의한 기능을 실제 화면으로 확인하고 전체 구조·구현 가능성·어려운 부분을 파악하기 위해 먼저 개인 시제품을 만들었다. 중간발표에서 사용 흐름을 보여주고, 팀이 개선 범위와 작업을 구체적으로 논의할 수 있게 하려는 목적이었다.

실제 센틴스파이 데스크톱 앱을 수정해 시험할 환경은 기업에 문의하지 않은 상태였으므로, 웹 에디터와 데스크톱 앱 중 어떤 흐름을 참고할지 검토했다. 주력 환경에서 설명 기능이 들어갈 위치를 보여주기 위해 데스크톱 앱의 화면·흐름을 참고한 독립 웹 데모를 선택했다. 원문 입력·선택 공간을 웹페이지에 마련하고 교정 패널에 연결했다. 데스크톱 앱 확장 여부와 구체적 방식은 [PRD](../PRD.md)의 후속 검토 범위를 따른다.

## 기업 제공 데이터의 기여와 한계

기존 문장 CSV·행동 로그 탐색에서 구조·중복·연결 가능성을 살펴봤다. 아래는 기존 분석의 핵심 해석을 정리한 것으로, 이번 문서 이관에서 원본 데이터를 다시 분석하지 않았다. 기업 원본 데이터는 이 문서에 포함하지 않는다.

| 확인한 데이터 특성 | 알 수 있는 것과 없는 것 |
|---|---|
| 원문·선택된 교정문·선택 순서·사용자 프롬프트 등이 있음 | 문장 쌍의 실제 변화는 검토 가능. 선택된 결과가 정답이라는 뜻은 아님 |
| 선택되지 않은 후보 전체·교정 이유 전용 열이 없음 | 과거 후보별 설명 품질이나 사용자의 선택 이유를 직접 평가할 수 없음. 사용자 프롬프트는 교정 이유가 아님 |
| 실행·선택·재실행 행동 로그가 있음 | 행동 발생과 그 이유를 구분해야 함. 재실행만으로 불만·설명 필요성을 확정할 수 없음 |
| 새 설명 기능을 사용한 결과가 없음 | 설명의 정확성과 사용자 비교·선택에 주는 도움은 별도 시험 필요 |

`run_paraphrasing`, `selected_paraphrasing`, `rerun_paraphrasing`의 이름만으로 요청·표시·적용 완료 시점을 확정하지 않는다. 제품·버전·모드·작업 단위와 계측 정의를 확인해야 한다.

현재 웹 데모의 직접적인 기반은 서비스 관찰, 멘토링·팀 의견, 기획과 직접 수행한 테스트다. 기업 데이터를 모델 학습이나 교정·설명 생성에 직접 사용하지 않았다. 데이터가 설명 기능의 필요성을 입증했다고 발표하지 않는다.

## 후속 평가 아이디어

CSV의 원문·선택 교정문 일부를 고정된 문장 쌍으로 삼아 사람이 정리한 변화·의미 영향과 AI 설명을 비교하는 방법을 검토할 수 있다. 아직 수행하지 않은 아이디어다. 데이터 사용·외부 API 전송 가능 범위와 개인정보를 확인한 뒤 사례·평가 기준을 정해야 한다. 자세한 제안은 [PRD의 기업 CSV 평가](../PRD.md#기업-csv를-활용한-설명-품질-평가)를 따른다.

후보 중복 개선·주변 문맥 활용 또한 현재 필수 기능으로 채택한 것은 아니다. 조사 자료의 아이디어를 구현 완료나 팀 합의로 해석하지 않는다.
